## Resolution

root_cause: Four compounding bugs — (1) spec geoToStageXY ignores stage pan/zoom so drag anchors missed the shape; (2) PenShapeManipulateLayer used manual Layer onMouseMove/Up which only fires from child events — once cursor left the shape the Stage swallowed events and drag became a no-op; (3) Vertex Circle has React-controlled x/y props that fight Konva drag so e.target.x() at dragEnd returns start position (same class as BezierEditLayer UAT-fix#1); (4) LayerTogglePanel (always-visible, top-left) covered the vertex handles after a north body drag; (5) BezierApplyControls only renders when activeTerritoryId!=null — hidden before a barony is selected.

fix: |
  TEST-HARNESS:
  - Add __forgePendingRingScreen() hatch to CanvasViewer (canvas-container-relative px) and __forgePendingRing() stays in PenShapeManipulateLayer.
  - Spec re-reads hatch before every gesture so anchors always hit the live rendered shape.
  - Draw coords kept with geoToStageXY (coarse but works for initial click placement).
  - Body drag direction changed to SOUTH so vertices stay below the LayerTogglePanel.
  - Apply activation: call __forgeSelectBarony() before clicking Apply (same pattern as 08.3-carve-roundtrip.spec.ts).
  - test.setTimeout increased to 1200s; waitForShaChange stays at 300s.

  COMPONENT (PenShapeManipulateLayer):
  - Switch from manual mousedown/move/up on Layer to Konva `draggable` + onDragStart/Move/End on Line and Circle nodes. Konva's drag captures stage-wide pointer events so move/up fire even off-shape.
  - Body drag: track last-move offset in bodyLastCanvasPosRef; use it at dragEnd instead of e.target.x/y (avoids stale React prop value).
  - Vertex drag: use stage.getRelativePointerPosition() (pointerCanvasPos helper) instead of e.target.x/y — pointer is immune to React-controlled x/y prop reset. Track last pointer pos in vertexLastCanvasPosRef for dragEnd.
  - jsdom fallbacks added to all position extractors for unit test compatibility.
