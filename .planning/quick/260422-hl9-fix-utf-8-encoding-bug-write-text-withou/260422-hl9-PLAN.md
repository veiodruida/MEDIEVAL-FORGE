<objective>
Fix Windows UTF-8 encoding bug: `Path.write_text()` without explicit `encoding="utf-8"`
falls back to the platform default (cp1252 on Windows), corrupting non-ASCII characters
in emitted GeoJSON and color sidecars (e.g. "Córdoba" → "C□rdoba").

Purpose: Non-ASCII condado/barony names (Spanish/Portuguese diacritics) must round-trip
cleanly through the generator → canvas → export pipeline. Current code already reads
with `encoding="utf-8"` but writes bare, which silently re-encodes the data on Windows.

Output: All `write_text()` / `read_text()` calls in `backend/medieval_forge/services/`
(recursively) use explicit `encoding="utf-8"`. GeoJSON writes also use
`ensure_ascii=False` so the file on disk contains real UTF-8 bytes (not `\uXXXX`
escapes), matching the style already used by `render_modern.py`.
</objective>
