<objective>
Fix orphan bug #4 from `.planning/phases/04-canvas-editing-basic/04-HUMAN-UAT.md` (line 178): the "Gerar mapa" pipeline currently uses a stale 4-condado `territory_iberia.json` template (or `DEFAULT_TERRITORY`) sent from the frontend instead of the rich research stored in the `research_cache` table (91 condados for Q29,Q45 via the manual provider).

Root cause located:
- `frontend/src/pages/ProjectDetail.tsx:359` calls `generate.mutate(territory)` where `territory` originates from either `DEFAULT_TERRITORY` (4 condados, lines 31-44) or `useTerritoryTemplate('iberia')` which `GET /api/projects/territory-template/iberia` reads from `backend/medieval_forge/services/territory_iberia.json` — neither has any knowledge of the per-project `research_cache` rows that `POST /projects/{id}/research/manual` writes.
- `backend/medieval_forge/api/generate.py:82` requires `territory_data` to be present in the merged dict and accepts whatever the body sends, so it never consults `ResearchCache`.

Purpose: Make the DB cache the canonical source of truth for generation input. The frontend body becomes an optional override (e.g., explicit "regenerate with template" power-user flow), and is no longer the default.

Output:
- New service `services/territory_builder.py` that assembles `territory_data` from `ResearchCache` (latest row for the project tuple) + centroids from `generated/territories.geojson` (via the existing `research_runner.load_condados`).
- `api/generate.py` updated to prefer cached research; 422 with a clear message if no cache and no body override.
- Regression test that fails without the fix and passes with it.
</objective>

| ResearchCache.payload (JSON column) | Originates from LLM output via `parse_research_json` (extra='forbid') OR pasted by user via manual endpoint — already validated against `ResearchResult` schema before write; safe to consume |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-q3v-01 | Tampering | `force_body_territory_data` flag | accept | Local-only tool, no auth model. Flag is documented; misuse only affects the caller's own project. |
| T-q3v-02 | Information Disclosure | INFO log line containing condado count + provider | accept | provider/model strings are non-secret; counts are aggregate. No PII, no credentials. |
| T-q3v-03 | DoS | Cache lookup adds one indexed SELECT per generate call | accept | Single-row indexed query on PK-or-tuple; negligible cost vs. the pipeline (~seconds). |
| T-q3v-04 | Spoofing | A cache row from a previous (country, period, provider) tuple bleeds into the wrong project | mitigate | Cache lookup keyed on `(country_qid, period_start, period_end)` from the project row, never from the request body. Even if attacker controls body, they cannot redirect the cache key. |
</threat_model>
