# Quick Task 260422-h24: Add Manual Paste Provider (Copy-Generated) Summary

**One-liner:** Manual (copy/paste) LLM provider with NoAuth registration, prompt-generation + JSON-submission REST endpoints, fence-stripping parser, and a two-step ResearchDialog panel that lands results in the same store/cache path as SSE providers.

## What Was Built

A complete "Manual (Copiar/Colar)" provider flow that lets users with no API keys or local Ollama copy a generated research prompt, paste it into any external chat (ChatGPT, Claude.ai, Gemini web), paste the JSON response back, and have it validated and cached identically to SSE-based providers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Deviation] Used existing parse_research_json instead of creating a parallel parser**
- **Found during:** Task 2 planning (advisor review)
- **Issue:** Plan proposed creating a new `parse_research_json` in `parse.py` that re-implemented lenient JSON parsing without the fallback that strips extra top-level keys — this would cause qwen2.5/llama3.2 models to fail on manual submissions they'd succeed with via SSE
- **Fix:** Created `parse.py` as a thin fence-stripping wrapper that delegates to the existing `schemas.parse_research_json`, preserving the lenient fallback
- **Files modified:** `backend/medieval_forge/services/llm/parse.py`

**2. [Rule 2 - Architectural simplification] Used `manualResult` store field instead of lifting SSE stream state**
- **Found during:** Task 5 planning (advisor review)
- **Issue:** Plan said "add `setResult`/`setStatus` to store if missing" — but SSE result/status live in `useResearchStream` local `useState`, and lifting them would touch the SSE verification path mid-plan
- **Fix:** Added `manualResult: ResearchResult | null` + `setManualResult` to `useResearchStore`; ResearchDialog stores the result there + refetches `cachedQuery` so the "Resultado em cache" display path triggers on next dialog open
- **Files modified:** `frontend/src/stores/useResearchStore.ts`, `frontend/src/components/research/ResearchDialog.tsx`

**3. [Rule 3 - Test fixture path] Used `generated/` for territories.geojson in new tests**
- **Found during:** Task 2 test writing (advisor flag)
- **Issue:** Existing SSE test fixture writes to `out/` directory but `load_condados` reads from `generated/` — new tests must use the correct production path
- **Fix:** New test fixture writes to `fake_root / pid / "generated" / "territories.geojson"`
