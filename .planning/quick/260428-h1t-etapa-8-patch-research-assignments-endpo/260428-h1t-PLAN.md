<objective>
Add a backend-only PATCH endpoint that lets the frontend edit barony→condado assignments AND condado metadata (name / duchy_id) after research has been generated, persisting changes back to the research cache so subsequent /generate calls use the edited data.

Endpoint: `PATCH /api/projects/{project_id}/research/assignments`

Body (Pydantic, both fields optional, at least one required):
```json
{
  "barony_assignments": {"B_123": "C_TOLEDO", "B_456": "C_NEW"},
  "condado_renames": {
    "C_OLD": {"name": "New Name", "duchy_id": "D_X"},
    "C_NEW": {"name": "Brand-new Condado", "duchy_id": "D_X"}
  }
}
```

Behavior:
1. Validate `project_id` UUID → 400 otherwise; load Project → 404 otherwise.
2. Locate the most recent MapResearchResult cache row for the project's (country_qid, period_start, period_end) tuple via `territory_builder.select_latest_cache_row`. Reject with 409 if no row exists, or if the row predates Etapa 3 (no `barony_assignments` key in payload).
3. Load `raw/baronies.geojson` for the project to know which barony ids are valid → 409 if missing.
4. Apply `condado_renames` first (so brand-new condado_ids referenced by the assignment delta become valid):
   - For each entry, if condado_id exists in payload → patch `name` / `duchy_id` in place.
   - If condado_id is new → append a new `MapCondado` dict (kingdom_id inherited from the rename target's duchy → kingdoms via existing duchies map; reject with 400 if duchy_id is unknown).
5. Apply `barony_assignments` delta (overwrite per-key on top of existing `barony_assignments`).
6. Validate every barony_id in the FINAL `barony_assignments` exists in `baronies.geojson` → 400 with sorted unknown list, no cache mutation.
7. Re-parse the edited payload through `MapResearchResult.model_validate(...)` to enforce the cross-ref invariant (every assignment value points to an existing condado). On failure → 400.
8. Persist via `set_cached(...)` using the SAME cache_key_hash as the loaded row (overwrite-in-place) and bump `project.updated_at` via `touch_project`.
9. Return the updated `MapResearchResult` JSON (`{"result": payload}` mirroring `/research/manual`).

Scope: backend + tests only. Frontend `AssignmentEditor.tsx` is **out of scope** (Etapa 8b).

Purpose: closes the editing half of Etapa 8 from `hazy-hatching-abelson.md` H.8 / G.2 — without it, users cannot correct the LLM's barony grouping before generating the map.

Output: PATCH route + 6 passing integration tests; no breaking changes to existing 234 tests.
</objective>
