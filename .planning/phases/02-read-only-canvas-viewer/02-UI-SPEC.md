## Typography

All text rendered inside React (sidebar, overlay panel, inspector). Canvas territory labels are Konva `Text` nodes — see Canvas Typography section below.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 | 1.5 | Inspector property values, layer toggle labels, neighbor chips |
| Label | 12px | 400 | 1.4 | Section headings within inspector groups, stat units (km², lat/lng) |
| Heading | 16px | 600 | 1.3 | Inspector territory name, sidebar header (project name in summary state) |
| Display | 20px | 600 | 1.2 | Not used in Phase 2 canvas view |

Label is differentiated from Body by size (12px vs 14px), not by weight. Both use weight 400. Two weights total: 400 (Body, Label) and 600 (Heading, Display).

Source: Radix Themes `size` scale (size="2" = 14px, size="1" = 12px, size="3" = 16px). Matches existing ProjectDetail usage pattern.

### Canvas Typography (Konva Text nodes — territory labels)

These are rendered by Konva, not React, and must be set explicitly on the `Text` shape.

| Property | Value | Rationale |
|----------|-------|-----------|
| fontFamily | `"system-ui, sans-serif"` | Matches Radix default; no font loading delay |
| fontSize | 12px (Konva `fontSize: 12`) | Readable at zoom ≥ 1.5×; does not overflow small condados |
| fontStyle | `"normal"` | No italic — italic in Konva requires font variant load |
| fill | `"#1a1a1a"` | Near-black; sufficient contrast on colored fills |
| stroke | `"rgba(255,255,255,0.7)"` | White halo, 1px wide — separates text from polygon edge |
| strokeWidth | 1 | Thin enough not to make text bold-looking |
| listening | false | Labels are display-only; must not intercept pointer events |

## Color

### Application Shell (Radix Tokens)

Radix Themes `accentColor="iris"` provides the `--iris-*` scale. Semantic tokens used:

| Role | Radix Token | Approx Hex | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--gray-1` | #fcfcfd | Page background, canvas backdrop outside map bounds |
| Secondary (30%) | `--gray-3` / `--panel-background` | #f5f5f6 | Right sidebar background, floating layer panel card background |
| Accent (10%) | `--iris-9` | #5b5bd6 | Fit-to-view button (primary), active layer toggle indicator |
| Destructive | `--red-9` | #e5484d | Not used in Phase 2 (read-only phase, no destructive actions) |

Accent reserved for: Fit-to-view button fill, active checkbox indicator (handled by Radix Checkbox with `accentColor` inherited). No other elements use accent color.

### Canvas Color System (Konva polygon fills)

Territory fill colors come exclusively from `lookup_condado_colors.json` and `lookup_barony_colors.json` (D-01). The canvas NEVER generates its own palette.

| Canvas Element | Color Rule |
|----------------|------------|
| Condado fill | Value from `lookup_condado_colors.json` keyed by territory ID |
| Barony fill | Value from `lookup_barony_colors.json` keyed by territory ID, rendered at 85% opacity above condados |
| Territory border (default) | `rgba(0, 0, 0, 0.35)`, strokeWidth 1px |
| Territory border (selected) | `#f0c040` (gold-yellow), strokeWidth 3px, drawn on interaction layer — fill color unchanged (D-03) |
| Capital dot fill | Owning condado color from lookup (D-04) |
| Capital dot ring | `#ffffff` outer ring 1.5px, `rgba(0,0,0,0.6)` inner ring 0.5px |
| Capital dot radius | 5px (visible at all zoom levels within min–max range) |
| Canvas background | `#1a1f2e` (dark navy) — outside map bounds; contrasts with terrain PNG |

Note: The selected territory border is drawn as a separate `Line` on the interaction Konva layer, not by modifying the base polygon's stroke. This ensures geometry is not mutated during selection (read-only contract).

## Layout Architecture

This section supplements the template because Phase 2 introduces a two-region layout that the executor must implement precisely.

Primary visual anchor: the canvas area — it occupies the dominant viewport width and is the first element the eye resolves.

### `/projects/:id` Route Layout

```
┌──────────────────────────────────────────────────────────────────┐
│ App Shell: project header bar (Radix Box, p="4", gray-2 bg)      │
│  ← Back to projects   [Project Name]   [status badge]            │
├─────────────────────────────────────────────┬────────────────────┤
│                                             │                    │
│  CANVAS AREA                                │  RIGHT SIDEBAR     │
│  flex: 1; overflow: hidden                  │  width: 340px      │
│  background: #1a1f2e                        │  min-width: 340px  │
│                                             │  flex-shrink: 0    │
│  Konva Stage fills 100% of this region      │  overflow-y: auto  │
│                                             │                    │
│  ┌─────────────────────────────────────────┐│  [Inspector panel] │
│  │ LAYER TOGGLE CARD                       ││  or               │
│  │ Radix Card, position: absolute          ││  [Project summary] │
│  │ top: 12px; left: 12px                   ││                    │
│  │ z-index: 10                             ││                    │
│  │ shadow: var(--shadow-3)                 ││                    │
│  └─────────────────────────────────────────┘│                    │
│                                             │                    │
│  [Fit to view btn: bottom-left, 12px margin]│                    │
├─────────────────────────────────────────────┴────────────────────┤
│ (no footer in Phase 2)                                           │
└──────────────────────────────────────────────────────────────────┘
```

- Outer container: `display: flex; flex-direction: row; height: calc(100vh - [header height])` — fills remaining viewport
- Canvas area: `flex: 1; position: relative; overflow: hidden` — Konva Stage is `position: absolute; top: 0; left: 0`
- Right sidebar: fixed 340px, `background: var(--gray-2)`, `border-left: 1px solid var(--gray-4)`, `padding: 16px`
- Narrow viewport behavior: sidebar stays fixed width (desktop-only tool; no responsive breakpoint in Phase 2)

## Konva Stage Architecture

| Layer (z-order bottom→top) | `listening` | Content | React component |
|----------------------------|-------------|---------|-----------------|
| 0 — Background | `false` | Terrain PNG as `KonvaImage` | `<BackgroundLayer>` |
| 1 — Territories | `true` | Condado `Line` polygons + optional Barony overlay | `<TerritoryLayer>` |
| 2 — Decorations | `false` | Capital `Circle` nodes, territory label `Text` nodes | `<DecorationsLayer>` |
| 3 — Interaction | `true` | Selected territory highlight `Line` only | `<InteractionLayer>` |

- All `Line` polygons use `closed={true}`, `points={flattenedCoords}`
- `listening=false` on Background and Decorations layers prevents hit-test cost on non-interactive nodes
- Territory polygons on layer 1 get `onClick` handlers; Decorations layer does not
- Stage `draggable={true}` implements pan; wheel event is handled via `onWheel` on the Stage component

## Interaction Contracts

### Pan

- Stage `draggable={true}` — Konva default drag behavior
- Pan is clamped: after each `dragend` event, clamp `stage.position()` so the map cannot translate fully out of viewport
- Clamp formula: `clampedX = clamp(pos.x, viewport.width - scaledMapWidth, 0)` (and symmetrically for Y)
- Cursor: `grab` at rest, `grabbing` while dragging — set via CSS on the Konva container `canvas` element

### Zoom

- `onWheel` on Stage; `e.evt.preventDefault()` to block page scroll
- Anchor on cursor position: `newPos = cursorPos - (cursorPos - oldPos) * (newScale / oldScale)` (D-15, CONTEXT.md Specifics)
- Scale limits: `minScale = fitToViewScale`, `maxScale = fitToViewScale * 4` (D-13)
- After scale change, apply same pan clamp as drag

### Selection (click-to-inspect)

- `onClick` on each territory `Line` shape in TerritoryLayer
- Writes `selectedTerritoryId` to Zustand `useUIStore`
- `Esc` key clears selection (sets `selectedTerritoryId = null`) — D-14
- Interaction layer re-renders the selected polygon outline as a gold `Line` above all other layers
- No dimming of non-selected territories (D-03)

### Fit to View

- Button in bottom-left of canvas area (absolute positioned)
- `Ctrl+0` keyboard shortcut also triggers (D-14)
- Computes: bounding box of all territory centroids → scale = min(viewportW / mapW, viewportH / mapH) × 0.95 (5% padding) → centers map
- Sets Stage `scaleX`, `scaleY`, `x`, `y` to computed values
- `minScale` is set to this computed fit-to-view scale

### Layer Toggles

- Zustand `useUIStore` holds `layerVisibility: { terrain: boolean; territories: boolean; borders: boolean; capitals: boolean; labels: boolean }`
- Default on project open: `{ terrain: true, territories: true, borders: true, capitals: true, labels: false }` (D-09)
- Each Radix `Checkbox` binds to its layer boolean; no animation on toggle
- Labels only render when `layerVisibility.labels === true && scale >= LABEL_ZOOM_THRESHOLD`
- `LABEL_ZOOM_THRESHOLD = 1.5` (relative to fit-to-view scale) — D-10, planner may tune against Iberia dataset

### Neighbor Navigation

- Clicking a neighbor chip fires `setSelectedTerritoryId(neighborId)` — same selection path as canvas click
- Canvas pans to center the newly selected territory (pan only; no zoom change)
- Inspector updates immediately via Zustand subscription

## States and Transitions

Each component must handle all of these:

| State | Trigger | Visual |
|-------|---------|--------|
| Loading | GeoJSON fetch in-flight | "Loading map…" centered in canvas area, gray-1 background |
| Error | fetch fails or GeoJSON missing | Callout in canvas area with error copy; no Stage rendered |
| Empty | Project status is not `generated` or `exported` | "No map generated yet." copy in canvas area |
| Ready (nothing selected) | GeoJSON loaded, no selection | Stage rendered, inspector shows project summary |
| Territory selected | User clicks polygon or neighbor chip | Interaction layer shows gold outline; inspector fills 4 groups |
| Territory deselected | Esc key or click on empty Stage area | Interaction layer clears; inspector returns to project summary |
