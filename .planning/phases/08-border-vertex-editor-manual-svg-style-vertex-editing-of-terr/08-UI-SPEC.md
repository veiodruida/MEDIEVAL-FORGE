## Interaction Contract

### Vertex Edit Mode (VertexEditLayer)

**Entry:** Clicking on a territory polygon in canvas while any edit tool (V/A/D/S/M) is active switches that territory to vertex-edit mode. The polygon's vertex handles appear.

**Handle states:**
- Unselected: `#4a9eff` circle radius 5px
- Hover: `#ffffff` circle radius 5px
- Selected: `#f0c040` circle radius 5px
- Snap target (within 5px): `#eab308` circle radius 8px stroke (D-28)

**Drag behavior:**
1. `mousedown` on handle: begin drag; show coord tooltip following cursor (lat, lon, 6 decimals, monospace size="1")
2. During drag: if polygon becomes self-intersecting (Shapely `is_valid` check), polygon interior turns `#ef4444` fill opacity 0.25 and border `#ef4444` stroke 2px
3. `mouseup` with invalid result: handle snaps back to pre-drag position; Callout error shown 3s (D-26)
4. `mouseup` with valid result: position committed; shared-vertex neighbours updated simultaneously (D-30)
5. Hold `Alt` during drag: snap disabled for this drag session; no yellow indicator shown (D-28)

**Edge hover (Add-Vertex tool):**
- Cursor near an edge: ghost handle preview at cursor position (`#4a9eff`, opacity 0.6)
- Click on edge: inserts vertex; undoable op

**Shared edge hover (D-31):**
- `mouseover` shared edge: edge stroke becomes `#a855f7` 2px; both endpoint handles enlarge to radius 7px stroke `#a855f7`
- Tooltip (Radix, 300ms delay): "Aresta compartilhada — N vizinhos afetados"
- `mouseleave` edge: reverts immediately

**Marquee select (D-29):**
- Drag on canvas background (not on handle): rubber-band rectangle
- On release: all handles within rectangle become selected (gold)
- `Shift+click` handle: toggle add/remove from selection
- `Delete` key: removes all selected vertices in one undoable op

### Split Tool (S)

1. Press S or click Split button — cursor changes to crosshair
2. User draws a line across the target polygon: click to start, click to end (two-point cut)
3. On second click: preview of split shown (two polygons, each highlighted `#f0c040` outline)
4. Confirm: line becomes cut, two territories created per D-07 semantics
5. Esc during draw: cancel without committing

### Merge Tool (M)

1. Press M or click Merge button — cursor shows link icon
2. Click first territory: highlighted `#f0c040`
3. Click second adjacent territory: highlighted `#f0c040`; merge preview shows union outline
4. Auto-confirmed on second click (no separate confirm button) — D-08 winner rule applied
5. If clicked territory is not adjacent: brief `Callout color="red"` "Territórios não são adjacentes" (2s auto-dismiss)
6. Esc: cancel

### Translate (whole-territory drag)

1. In Select tool (V), click polygon interior (not a handle): drag moves entire territory
2. During drag: coord tooltip shows centroid position; neighbours not moved (only shared vertices follow — D-30)
3. Drop: one undoable translate op

## Notes for Executor

1. **No v1 code resurrection (CLAUDE.md D-V3-04).** `VertexEditLayer`, `useEditorStore`, `useEditKeyboardMap`, `useUndoShortcut` are all NEW files written from scratch. Do not restore the deleted v1 equivalents.

2. **zundo scope is editor ops only (D-25).** `useEditorStore` wraps with `temporal({ partialize: (s) => ({ vertices: s.vertices, editLog: s.editLog }) })`. Branch switch, snapshot create, Phase 04 sliders are excluded from undo history. History cap ~100 ops; oldest evicted on push.

3. **Topology validation must run on the backend (D-26).** The drag rejection is frontend-visible (red handles + snap-back), but the `is_valid` + `touches` Shapely check runs via a lightweight `/api/v3/projects/{id}/editor/validate` endpoint or inline via Python WASM — planner confirms approach. Invalid drags must never persist to the edit log.

4. **Shared vertex coupling (D-30) is the only move behaviour.** There is no "Alt to move only active territory" escape hatch. Snap (D-28) guarantees shared vertices are identified by proximity ≤ 5px.

5. **Coord tooltip is a DOM div, not Radix Tooltip (inherited from Phase 03 constraint).** Radix Tooltip requires a DOM anchor; Konva Stage is canvas-only. Use `position: fixed; pointer-events: none; z-index: 60`.

6. **`original_idx` for new baronies = `max(existing original_idx in branch) + 1` (D-22, CLAUDE.md Rule #4).** The branch metadata stores the high-water-mark counter. Never reuse a freed `original_idx` from a merged territory.

7. **Export manifest (D-16) must include `branch_name`, `snapshot_id`, `snapshot_timestamp`.** This extends the Phase 06 MANIFEST v2 schema — do not break existing parity tests (Phase 06 validator must still pass on non-branch exports).

8. **"Desktop required" banner (D-36) is non-dismissible.** It uses `Callout color="amber"` above the toolbar. UA detection pattern: `navigator.maxTouchPoints > 0 && !window.matchMedia('(pointer: fine)').matches`.

9. **Simplify tolerance slider (D-01).** The toolbar "Simplificar" button opens a small popover (not a modal) with a single `Slider` component (Radix) for the Douglas-Peucker tolerance.
