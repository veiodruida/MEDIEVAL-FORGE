<objective>
Close GAP-A (Selection→editor bridge). Today clicking a barony only sets
`useUIStore.selectedBaronyId`; `useEditorStore.setActiveTerritoryId` has ZERO
callers and `useEditorStore.vertices` is never populated, so VertexEditLayer
(which gates handle rendering on `activeTerritoryId !== null` and maps over
`vertices`) can never render a handle at runtime.

This plan wires the bridge: on barony selection, set `activeTerritoryId` and
load that barony's polygon ring into `vertices`; on condado-select or deselect,
clear both. All work is FRONTEND-ONLY wiring + one additive type field.

Purpose: make editable vertex handles reachable at runtime (the root of
EDIT-VERTEX-01/02/03/05 and PERF-01 failures).
Output: BaronyRender.geoRing field, SelectionBridge component, CanvasViewer mount.
</objective>

         const n = closed ? ring.length - 1 : ring.length
         const vertices: Record<string, { lat: number; lon: number }> = {}
         for (let i = 0; i < n; i++) {

           vertices[`${selectedBaronyId}#${i}`] = { lat, lon }
         }
         useEditorStore.getState().setActiveTerritoryId(selectedBaronyId)
         useEditorStore.setState({ vertices })
