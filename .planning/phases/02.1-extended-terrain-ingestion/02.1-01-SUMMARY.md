## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Re-export OVERPASS_ENDPOINTS from ingest_osm for backward compat**
- **Found during:** Task 1 regression check
- **Issue:** Pre-existing test `test_ingest_osm.py::test_overpass_endpoints_are_three_live_mirrors` imports `OVERPASS_ENDPOINTS` directly from `ingest_osm`. After moving the list to `overpass_client.py`, this import failed.
- **Fix:** Added `OVERPASS_ENDPOINTS = overpass_client.OVERPASS_ENDPOINTS` re-export to `ingest_osm.py`. No duplication — it's a reference, not a copy.
- **Files modified:** `backend/medieval_forge/services/ingest_osm.py`
- **Commit:** f0e7a09

**2. [Rule 2 - Security] T-01-05: Sanitize bbox backfill error in SSE**
- **Found during:** Task 2 (threat_model review before writing _backfill_bbox)
- **Issue:** Plan's action snippet emitted `f"data: AVISO: bbox backfill falhou: {exc}\n\n"` which leaks full Shapely exception repr to SSE stream.
- **Fix:** Changed to emit only `exc.__class__.__name__` in SSE; full repr goes to `logger.warning` only.
- **Files modified:** `backend/medieval_forge/services/ingest_runner.py`
- **Commit:** 4211ff5

**3. [Rule 3 - Convention] Router prefix matches existing main.py pattern**
- **Found during:** Task 2 (advisor review)
- **Issue:** Plan's `api/terrain.py` snippet used `prefix="/api/projects/{project_id}/terrain"` which would double the `/api` prefix when registered with `prefix="/api"` in main.py.
- **Fix:** Used `prefix="/projects/{project_id}/terrain"` in router, registered with `prefix="/api"` in main.py — consistent with all other routers.
- **Files modified:** `backend/medieval_forge/api/terrain.py`
- **Commit:** 4211ff5
