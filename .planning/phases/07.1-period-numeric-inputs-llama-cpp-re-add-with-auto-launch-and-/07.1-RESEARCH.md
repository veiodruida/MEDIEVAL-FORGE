### Pattern 1: Subprocess lifecycle module (NEW pattern for Medieval Forge)

**What:** Encapsulate the entire `llama-server` lifetime in `llamacpp_launcher.py`. Surface is tiny: `launch(model_filename) -> LaunchResult`, `shutdown() -> None`, `shutdown_sync() -> None` (for atexit), `status() -> dict | None`.

**When to use:** Any external long-running subprocess managed by the FastAPI process.

**Why this pattern:** Centralizes idempotency, port-pick, error mapping, and lifecycle. Tests reset module-level state via an explicit `_reset_state_for_tests()` helper rather than `importlib.reload` (which CLAUDE.md forbids).

**Skeleton:**
```python
# Source: synthesized from D-08 + D-08b; no v1 equivalent (new pattern).
from __future__ import annotations
import atexit, os, shutil, socket, subprocess, threading, time
from dataclasses import dataclass
from datetime import datetime, timezone
from pathlib import Path

import httpx

DEFAULT_MODELS_DIR = Path.home() / ".medieval-forge" / "models"
SHUTDOWN_TIMEOUT_S = 5.0

@dataclass
class LaunchResult:
    ok: bool
    base_url: str
    pid: int
    model: str           # filename (relative to models dir)
    started_at: str      # ISO8601 UTC

# Module-level state — single-process invariant per D-08
_STATE_LOCK = threading.Lock()
_PROCESS: subprocess.Popen | None = None
_ACTIVE_MODEL_PATH: Path | None = None
_ACTIVE_PORT: int | None = None
_STARTED_AT: str | None = None


def models_dir() -> Path:
    """D-07a: env override + fallback."""
    env = os.environ.get("MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR")
    return Path(env) if env else DEFAULT_MODELS_DIR


def list_models() -> list[str]:
    """D-07a: top-level only, .gguf (case-insensitive), alpha sort."""
    d = models_dir()
    if not d.exists():
        return []
    return sorted(
        p.name for p in d.iterdir()
        if p.is_file() and p.suffix.lower() == ".gguf"
    )


def _resolve_binary() -> str | None:
    """D-07b: env override + shutil.which."""
    return os.environ.get("LLAMA_SERVER_BIN") or shutil.which("llama-server")


def _pick_port() -> int:
    """D-08: ephemeral port via SO_REUSEADDR."""
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.bind(("", 0))
        return s.getsockname()[1]


def launch(model_filename: str) -> LaunchResult:
    """D-08: idempotent by model_path. HTTP 409 surfaced via raised
    LlamacppLaunchConflict for the api/v3 layer."""
    binary = _resolve_binary()
    if binary is None:
        raise LlamacppBinaryMissing("llama-server not on PATH")

    target_path = (models_dir() / model_filename).resolve()
    if not target_path.exists():
        raise FileNotFoundError(f"model not found: {target_path}")

    with _STATE_LOCK:
        global _PROCESS, _ACTIVE_MODEL_PATH, _ACTIVE_PORT, _STARTED_AT
        if _PROCESS is not None and _PROCESS.poll() is None:
            # already alive
            if _ACTIVE_MODEL_PATH == target_path:
                return LaunchResult(
                    ok=True,
                    base_url=f"http://127.0.0.1:{_ACTIVE_PORT}",
                    pid=_PROCESS.pid,
                    model=model_filename,
                    started_at=_STARTED_AT,
                )
            raise LlamacppLaunchConflict(
                f"modelo `{_ACTIVE_MODEL_PATH.name}` ativo — pare-o antes via DELETE"
            )

        port = _pick_port()
        proc = subprocess.Popen(
            [binary, "-m", str(target_path), "--ctx-size", "8192", "--port", str(port)],
            stdout=subprocess.DEVNULL,  # avoid blocking on stdout buffer
            stderr=subprocess.DEVNULL,
        )
        _PROCESS = proc
        _ACTIVE_MODEL_PATH = target_path
        _ACTIVE_PORT = port
        _STARTED_AT = datetime.now(timezone.utc).isoformat()

    # Optional: poll /health for 2-3s before returning ok=True so the UI
    # doesn't have to do a separate probe. Planner: decide TTL.
    return LaunchResult(
        ok=True,
        base_url=f"http://127.0.0.1:{port}",
        pid=proc.pid,
        model=model_filename,
        started_at=_STARTED_AT,
    )


def status() -> dict | None:
    with _STATE_LOCK:
        if _PROCESS is None or _PROCESS.poll() is not None:
            return None
        return {
            "pid": _PROCESS.pid,
            "model": _ACTIVE_MODEL_PATH.name if _ACTIVE_MODEL_PATH else None,
            "base_url": f"http://127.0.0.1:{_ACTIVE_PORT}",
            "started_at": _STARTED_AT,
        }


def shutdown_sync() -> bool:
    """Used by atexit — synchronous. Returns True if a process was alive."""
    global _PROCESS, _ACTIVE_MODEL_PATH, _ACTIVE_PORT, _STARTED_AT
    with _STATE_LOCK:
        if _PROCESS is None or _PROCESS.poll() is not None:
            _PROCESS = _ACTIVE_MODEL_PATH = _ACTIVE_PORT = _STARTED_AT = None
            return False
        proc = _PROCESS
    proc.terminate()
    try:
        proc.wait(timeout=SHUTDOWN_TIMEOUT_S)
    except subprocess.TimeoutExpired:
        proc.kill()
        proc.wait(timeout=1.0)
    with _STATE_LOCK:
        _PROCESS = _ACTIVE_MODEL_PATH = _ACTIVE_PORT = _STARTED_AT = None
    return True


async def shutdown() -> None:
    """Used by FastAPI lifespan — async wrapper around shutdown_sync."""
    import asyncio
    await asyncio.to_thread(shutdown_sync)


atexit.register(shutdown_sync)


def _reset_state_for_tests() -> None:
    """Test isolation helper — NEVER call from production code."""
    global _PROCESS, _ACTIVE_MODEL_PATH, _ACTIVE_PORT, _STARTED_AT
    with _STATE_LOCK:
        if _PROCESS is not None and _PROCESS.poll() is None:
            _PROCESS.kill()
            _PROCESS.wait(timeout=1.0)
        _PROCESS = _ACTIVE_MODEL_PATH = _ACTIVE_PORT = _STARTED_AT = None


class LlamacppBinaryMissing(RuntimeError): pass
class LlamacppLaunchConflict(RuntimeError): pass
```

### Pattern 2: Provider port (literal-port template, v3 adjustments only)

**What:** `LlamaCppProvider` mirrors `OllamaProvider` shape: both `health()` (Ollama-style `dict` return for `/providers` endpoint) and `health_check()` (Protocol-conforming `HealthStatus`).

**When to use:** Any v3 provider that needs to surface `available_models` in the `/providers` builder.

**Example (skeleton — full body ports from `87f8aab~1:services/llm/llamacpp.py`):**
```python

# v3 deviations:
#   1. base_url comes from llamacpp_launcher.status() — fallback DEFAULT_BASE_URL only if launcher idle
#   2. health() returns Ollama-shape dict (D-09) with available_models from launcher.list_models()
#   3. Drop `model == "(server-default)"` sentinel logic — D-08 always passes explicit model
class LlamaCppProvider:
    provider_id = "llamacpp"
    display_name = "Llama.cpp (local)"
    auth_methods = [NoAuth()]

    async def health(self) -> dict:
        """REVIEWS-shape return: {ok, message, available_models}."""
        from .llamacpp_launcher import list_models, status, _resolve_binary
        available = list_models()
        binary = _resolve_binary()
        if binary is None:
            return {
                "ok": False,
                "message": "llama-server não encontrado no PATH (defina LLAMA_SERVER_BIN)",
                "available_models": available,  # still listed if dir exists
            }
        running = status()
        if running is None:
            return {
                "ok": False,
                "message": "Servidor llama-server não está ativo. Use 'Levantar servidor'.",
                "available_models": available,
            }
        # Probe /v1/models on the live server
        try:
            async with httpx.AsyncClient(timeout=3.0) as client:
                r = await client.get(f"{running['base_url']}/v1/models")
                ok = r.status_code == 200
                return {
                    "ok": ok,
                    "message": f"Reachable at {running['base_url']}" if ok else f"HTTP {r.status_code}",
                    "available_models": available,
                }
        except Exception as exc:
            return {
                "ok": False,
                "message": f"Unreachable: {exc}",
                "available_models": available,
            }
```

### Pattern 3: Nested Radix Dialog (AuthSetupSheet inside ResearchDialog)

**What:** AuthSetupSheet is its own `<Dialog.Root>` rendered as a sibling of ResearchDialog inside the parent component tree. State is lifted: ResearchDialog owns an `authSheetOpen` boolean, which it passes to AuthSetupSheet as `open`/`onOpenChange`. Radix Themes handles portal stacking and focus return automatically [CITED: radix-ui.com/themes/docs/components/dialog].

**Why this works:** Radix Dialog uses portals + focus traps that compose. A child Dialog opens on top, closing returns focus to the parent's trigger. No bespoke focus-restoration code needed.

**Example:**
```tsx
// In ResearchDialog.tsx (rodapé Flex):

    Configurar provedores
  </Button>

</Flex>
{/* Sibling, NOT nested inside Dialog.Content of parent */}
<AuthSetupSheet open={authSheetOpen} onOpenChange={setAuthSheetOpen} />
```

### Anti-Patterns to Avoid
- **Spawning llama-server inside the request handler** — must go through the launcher module so module-level idempotency + atexit fire.
- **`subprocess.run` instead of `Popen`** — `.run()` blocks until exit; we need a daemon-style spawn that returns immediately.
- **Reading `Popen.stdout`/`stderr` without piping them out** — fills the OS pipe buffer and deadlocks; default `stdout=DEVNULL, stderr=DEVNULL`. If logs become important, use a dedicated reader thread.
- **`time.sleep` inside FastAPI request handler waiting for server readiness** — blocks the event loop. Use `httpx.AsyncClient` with retry+backoff via `asyncio.sleep`.
- **`importlib.reload(llamacpp_launcher)` for test isolation** — CLAUDE.md forbids. Use `_reset_state_for_tests()` helper instead.
- **PT-BR error messages bubbling up via uncaught `Exception`** — wrap in a typed exception (`LlamacppLaunchConflict`, etc.) and map at the api/v3 boundary.
- **Trusting the user-supplied `model` filename without basename-check** — `os.path.basename` + reject if `Path(filename).parent != Path('.')` to block path traversal.

## Common Pitfalls

### Pitfall 1: Browser `<input type="number">` quirks
**What goes wrong:** `e.target.value` is a *string*. `e.target.valueAsNumber` is `NaN` for empty input. `step="any"` allows floats — we want integer years only.
**Why it happens:** HTML number input contract; React doesn't coerce.
**How to avoid:**
```tsx
<TextField.Root
  type="number"
  min={1}
  max={2100}
  step={1}
  inputMode="numeric"
  value={periodStart ?? ''}
  onChange={(e) => {
    const v = e.target.value
    if (v === '') { setPeriodStart(null); return }
    const n = Number(v)
    setPeriodStart(Number.isFinite(n) && Number.isInteger(n) ? n : periodStart)
  }}
/>
```
**Warning signs:** Submit payload contains `"period_start": NaN` (invalid JSON — `JSON.stringify` converts to `null`). Backend rejects with 422.

### Pitfall 2: Windows `Popen.terminate()` is `TerminateProcess` — no graceful shutdown signal
**What goes wrong:** On POSIX, `terminate()` sends SIGTERM and llama-server can flush its model cache. On Windows, `terminate()` is equivalent to `TerminateProcess` — abrupt kill, like SIGKILL [CITED: docs.python.org/3/library/subprocess.html#subprocess.Popen.terminate]. The 5-second grace period in D-08b's `shutdown_sync` is therefore effectively a no-op on Windows.
**Why it happens:** Windows lacks a native cooperative-termination primitive for arbitrary child processes.
**How to avoid:** Accept the asymmetry. Document in the launcher docstring. Add `creationflags=subprocess.CREATE_NEW_PROCESS_GROUP` on Windows IF a future need to send `signal.CTRL_BREAK_EVENT` arises — but Phase 07.1 doesn't need this since llama-server is stateless across restarts.
**Warning signs:** Truncated log lines on app exit are normal on Windows; on POSIX, llama-server prints a clean "shutdown complete".

### Pitfall 3: D-12 parity invariant — zero-LLM byte identity
**What goes wrong:** Phase 07.1's runner.py and cache.py edits touch files referenced by the Iberia 868 parity test. If `cache_key` derivation changes for the existing `period_label` callers (e.g., a forgotten dead-code branch), the parity test stays green BUT we silently broke cache hits for any existing project.
**Why it happens:** Cache truncate masks the bug — fresh runs always re-populate.
**How to avoid:** D-04c locks the API body to an atomic swap. No transitional dual-acceptance. The legacy `period_label` parameter is **removed everywhere in one commit**; grep gate runs in CI:
```bash
grep -rn "period_label" backend/medieval_forge/ frontend/src/ && echo "FAIL: period_label still referenced" && exit 1
```
**Warning signs:** Any file still mentioning `period_label` after Phase 07.1 is a residual that needs cleanup.

### Pitfall 4: Race between `socket.bind(('', 0))` and llama-server spawn
**What goes wrong:** Pick port 38291 → `socket` closes → 5ms later `llama-server` spawns → in the 5ms window another process binds 38291 → llama-server fails with "address in use".
**Why it happens:** OS may or may not honor TIME_WAIT for very-recent ephemeral allocations.
**How to avoid:** D-08 explicitly accepts this race ("Race window is acceptable for single-user local app"). If it becomes painful, add retry-with-new-port: try up to 3 times before erroring.
**Warning signs:** Intermittent test failures of `test_llamacpp_launch_picks_free_port` on a busy CI runner.

### Pitfall 5: `subprocess.Popen` zombie process on parent crash
**What goes wrong:** If Python crashes hard (segfault, KILL signal), the FastAPI lifespan handler doesn't run, `atexit` doesn't fire — llama-server is orphaned, holds memory + ports.
**Why it happens:** Atexit only runs on clean interpreter exit.
**How to avoid:** D-08b accepts this — "If a llama-server is still running from a previous crashed app instance, the user has to kill it manually; the next launch attempt detects the port collision". Document in user-facing copy: "Servidor pode estar órfão de uma sessão anterior. Use `taskkill /F /IM llama-server.exe` (Windows) ou `pkill llama-server` (macOS/Linux)."
**Warning signs:** Second `POST /launch` after a crash returns 409 with no llama-server registered in the launcher's memory — surface a clear error message: "Porta `<X>` ocupada. Mate o processo manualmente e tente novamente."

### Pitfall 6: Pydantic `model_validator(mode='after')` re-runs on each `.model_copy()`
**What goes wrong:** If a test does `body = StartResearchBody(...).model_copy(update={"period_end": 0})` to test invalid states, the validator may or may not run depending on Pydantic version semantics.
**Why it happens:** Pydantic v2 only revalidates on `model_copy(deep=True, ...)` if `model_config["revalidate_instances"] = "always"`.
**How to avoid:** Tests instantiate the model directly with invalid values and assert `ValidationError` — don't use `.model_copy` for testing validation.
**Warning signs:** A test passes locally but the same input rejected by the live endpoint, or vice versa.

### Pitfall 7: `Path.home()` resolution on Windows surprise
**What goes wrong:** `Path.home()` returns `C:\Users\veio_` (uses backslashes); when joined with `".medieval-forge" / "models"` the result is a `WindowsPath` that compares unequal to a `PosixPath` literal in cross-platform tests.
**Why it happens:** Cross-platform tests sometimes hardcode forward-slash paths.
**How to avoid:** Tests use `monkeypatch.setenv("MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR", str(tmp_path))` rather than asserting against `Path.home()`. Production code is fine — `Path` operations are platform-correct.
**Warning signs:** Test asserts a literal string path and fails on the other platform.

### Pitfall 8: `Popen` stdout/stderr deadlock if not piped to DEVNULL
**What goes wrong:** llama-server writes ~30 lines on startup. If `stdout=subprocess.PIPE` without a reader, the OS pipe buffer (~64KB) fills and llama-server blocks on `write()`, never responding to `/v1/models`.
**Why it happens:** Pipe is bidirectional but synchronous; nobody is reading.
**How to avoid:** `stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL` (already in skeleton above). If logs become needed: dedicated reader thread or capture to log file via `stdout=open("/tmp/llama.log", "w")`.
**Warning signs:** `httpx.get("/v1/models")` hangs forever after spawn.

### Pitfall 9: Frontend dropdown stays stale after launch succeeds
**What goes wrong:** User clicks "Levantar servidor" → backend launches → user clicks "Iniciar pesquisa" → request still uses the previous (stale) health status because `useLlamacppHealth` didn't refetch.
**Why it happens:** TanStack Query doesn't auto-invalidate sibling queries on mutation success.
**How to avoid:** In `useLlamacppLaunch`, the mutation's `onSuccess` callback calls `queryClient.invalidateQueries({ queryKey: ['llamacpp-health'] })`. Also invalidate `['providers']` so ResearchDialog sees the fresh healthy state.
**Warning signs:** UAT test "launch then immediately submit research" fails with `provider=llamacpp` reported unhealthy.

### Pitfall 10: ResearchDialog seed effect overwrites user edits on cache invalidation
**What goes wrong:** D-03 seeds `periodStart/End` from `Project.period_start/end` via `useEffect`. If `useProject` refetches (e.g., after window focus), the effect overwrites the user's typed value.
**Why it happens:** Naive `useEffect` deps including `project.period_start`.
**How to avoid:** Guard with `prevOpenRef.current === false && open === true` — seed ONLY on open transition, not on every project refetch. Pattern already established in Phase 07 ResearchDialog (line 89-92 — period re-seed gated on `open`).
**Warning signs:** User reports "minha entrada foi apagada".

```typescript
// Source: pattern from useResearchOverlay + useProviders
import { useMutation, useQueryClient } from '@tanstack/react-query'

interface LaunchResult {
  ok: boolean
  base_url: string
  pid: number
  model: string
  started_at: string
}

export function useLlamacppLaunch() {
  const qc = useQueryClient()
  return useMutation<LaunchResult, Error, { model: string }>({
    mutationFn: async ({ model }) => {
      const res = await fetch('/api/v3/llm/llamacpp/launch', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ model }),
      })
      if (!res.ok) {
        const txt = await res.text()
        throw new Error(txt || `launch failed: ${res.status}`)
      }
      return res.json()
    },
    onSuccess: () => {
      // Pitfall 9 — refresh providers + health so ResearchDialog sees healthy state.
      qc.invalidateQueries({ queryKey: ['providers'] })
      qc.invalidateQueries({ queryKey: ['llamacpp-health'] })
    },
  })
}
```

## Security Domain

Security enforcement is on by default in this project's config.

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | No auth introduced; existing local-only app posture. |
| V3 Session Management | no | Stateless API; no sessions. |
| V4 Access Control | yes | The launch endpoint can spawn an arbitrary executable. Restrict the model parameter to a basename inside the configured models dir; reject `..` and absolute paths. |
| V5 Input Validation | yes | Pydantic `conint` + `model_validator` + Path basename check. The model filename string MUST be validated server-side: `Path(filename).name == filename` AND `Path(filename).suffix.lower() == '.gguf'`. |
| V6 Cryptography | no | No new crypto. |
| V12 Files and Resources | yes | Path traversal must be blocked on the model filename. `(models_dir() / filename).resolve()` MUST start with `models_dir().resolve()` — otherwise reject 400. |
| V14 Configuration | yes | Env vars (`MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR`, `LLAMA_SERVER_BIN`) — document; no secrets. |

### Known Threat Patterns for {FastAPI + subprocess + httpx}

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Path traversal in model filename (`../../../etc/passwd.gguf` symlink → arbitrary file read by llama-server) | Tampering / Info Disclosure | Reject filename if `Path(filename).name != filename` (rejects any directory component) AND `.suffix.lower() == '.gguf'`; resolve and verify it starts with `models_dir().resolve()`. |
| Command injection via model filename (filename contains `; rm -rf /`) | Tampering | `subprocess.Popen` is invoked with `[binary, "-m", str(path), …]` (list form, not shell=True). The filename never reaches a shell — Popen passes args directly to CreateProcess/execve. |
| Arbitrary binary execution via `LLAMA_SERVER_BIN` env override | Elevation of privilege | Env vars are local-machine trust boundary; the user controls their own env. Document the override; do not validate (consistent with PATH semantics). |
| DoS by spawning multiple llama-server processes | DoS | D-08 idempotency: only one process at a time; second different-model launch returns 409. |
| Resource exhaustion via huge `period_end - period_start` range | DoS | `conint(le=2100)` bounds the range; the prompt builder doesn't iterate the range. |
| SSRF via crafted `base_url` in credentials dict | Tampering | LlamaCppProvider's `base_url` is sourced from launcher, not user input. (Old v1 code accepted `credentials["base_url"]` — drop this on port; rely on launcher state only.) |
| Provider returns malformed JSON that crashes the parser | DoS | Existing `parse_research_json` lenient parser handles this (Phase 07). |

## Open Questions

1. **Should the launch endpoint block waiting for llama-server readiness, or return immediately?**
   - What we know: D-08 response shape includes `ok: bool` but doesn't specify whether `ok=True` means "spawned" or "spawned AND /health responding".
   - What's unclear: User experience tradeoff — block for ~3s with a clear progress message, OR return immediately and let the UI poll `useLlamacppHealth`?
   - Recommendation: Block for ≤3s via httpx readiness probe; if not ready in 3s, return `ok=True, ready=false` with a hint, UI continues polling.

2. **Test isolation for `atexit.register` — how do we test the registration without polluting subsequent tests?**
   - What we know: `atexit._run_exitfuncs()` runs registered functions; pytest doesn't normally fire them.
   - What's unclear: Repeated import of `llamacpp_launcher` in tests registers the atexit handler multiple times.
   - Recommendation: Move `atexit.register(...)` call into a top-level `_register_atexit()` function called once at import via a module-level flag; expose `_atexit_registered_count` for assertion in tests.

3. **Should `useLlamacppLaunch` mutation invalidate `['providers']` too, or only `['llamacpp-health']`?**
   - What we know: `useProviders` is read by ResearchDialog's provider dropdown.
   - What's unclear: If we invalidate `['providers']`, the dropdown rebuilds; if not, the stale "unhealthy" badge stays.
   - Recommendation: Invalidate BOTH. Cost is one extra GET; clarity worth it.

4. **Real or mocked subprocess for `test_llamacpp_launch_lifecycle` (SC-4e)?**
   - What we know: Real llama-server is on the dev machine but startup is slow (5-30s with a real model) and requires a gguf file.
   - What's unclear: CI doesn't have llama-server; we want the test to be portable.
   - Recommendation: Use `subprocess.Popen([sys.executable, "-c", "import time; time.sleep(120)"], ...)` as a stand-in via dependency injection — the launcher takes `binary_resolver` as a kwarg so tests can swap in `sys.executable` with a script arg. Document this seam.
