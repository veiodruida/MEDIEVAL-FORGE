**Why human:** Dialog sibling mounting, tab visual state, and conditional hint rendering require a live browser.

### 3. Levantar/Parar servidor lifecycle

**Test:** With a valid `llama-server` binary in PATH and a `.gguf` model in `~/.medieval-forge/models/`: open AuthSetupSheet, select a model, click "Levantar servidor".
**Expected:** Button changes to "Parar servidor" (red solid). A model info row appears showing the model name and port. After ~5s polling, `GET /api/v3/llm/llamacpp/launch` confirms `running: true`. Clicking "Parar servidor" stops the server and returns to "Levantar servidor". Closing the sheet and reopening starts with a clean state (no stale "running" shown from previous mutation cache).
**Why human:** Requires a real llama.cpp binary and .gguf model; subprocess lifecycle, real HTTP polling, and mutation reset behavior cannot be verified without a live environment.
