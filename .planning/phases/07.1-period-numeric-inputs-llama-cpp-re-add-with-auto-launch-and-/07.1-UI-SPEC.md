# Phase 07.1 — UI Design Contract

> Visual and interaction contract for two additive frontend surfaces:
> (1) numeric period inputs in `ResearchDialog`, and
> (2) the new `AuthSetupSheet` with a Llama.cpp local-server panel.
> Generated by gsd-ui-researcher.

**Inheritance:** This contract extends Phase 07 (`07-UI-SPEC.md`, status: approved).
All design-system tokens, spacing scale, typography, color split, and registry safety
from Phase 07 carry forward unchanged. Only divergences and net-new surfaces are
specified here. Executors must read `07-UI-SPEC.md` alongside this document.

Scope — **two frontend surfaces** modified or added in Phase 07.1:

1. **`ResearchDialog` (MODIFIED)** — the single free-text `Período` `TextField` is replaced
   with two `<TextField.Root type="number">` inputs labeled "Início" and "Fim". A
   "Configurar provedores" link is added in the rodapé (next to "Cancelar"). The
   "Última pesquisa" microcopy period rendering is updated to consume
   `period_start / period_end` integers instead of `period_label: str` (D-04b).

2. **`AuthSetupSheet` (NEW)** — a nested Radix `Dialog.Root` opened from the rodapé
   "Configurar provedores" link. Contains a `<Tabs.Root>` shell with one active
   `<Tabs.Trigger>` tab ("Llama.cpp local"). The panel exposes: model dropdown
   (sourced from `useLlamacppHealth().available_models`), server status line, and
   "Levantar servidor" / "Parar servidor" action button.

Out of scope for this contract (deferred / out-of-phase): BC/negative year support;
AuthSetupSheet Claude/Ollama tabs; configurable launch flags via UI; models-directory
UI configuration; persistent PID file; daemon mode; multiple concurrent llama-server
instances. See `07.1-CONTEXT.md §Deferred`.

Exceptions (Phase 07.1 specific):

- **Período inputs side-by-side:** the two numeric `TextField.Root` inputs ("Início" / "Fim")
  are laid out in a `<Flex gap="2">` row under the `Período` label — 8px gap between the
  two inputs. Both inputs are equal width (`flex: 1`). This is narrower than a single
  full-width field; the layout still accommodates 4-digit year values with room to spare.
- **`AuthSetupSheet` max-width clamped to `480px`** (`style={{ maxWidth: 480 }}`) — the
  panel has fewer fields than ResearchDialog (dropdown + status line + one button); 480px
  matches `NewProjectModal` width and avoids an oversized sheet for thin content.
- **Rodapé layout in `ResearchDialog`:** existing CTA row `<Flex gap="2" justify="end">` is
  split into `justify="between"` to accommodate a left-anchored "Configurar provedores" link
  alongside the right-anchored Cancelar/Iniciar buttons. This avoids a new row and keeps the
  dialog height unchanged.

Source: `frontend/src/components/projects/NewProjectModal.tsx` (480px width pattern);
Phase 07 UI-SPEC §Spacing (gap-2 / gap-3 / p-4 / p-5 patterns); `ResearchDialog.tsx:312`
(existing `<Flex gap="2" justify="end" mt="2">` CTA row that gets patched).

#### "Última pesquisa" microcopy period rendering update (D-04b)

The existing Phase 07 dual-timestamp microcopy in `InspectorSidebar` placeholder mode
(`07-UI-SPEC §Copywriting Surface 2`) includes the period component. Phase 07 used
`period_label: str`. Phase 07.1 updates the meta sidecar shape: `period_label` is replaced
by `period_start: int` + `period_end: int`. The rendered string changes as follows:

| Condition | Before (Phase 07, removed) | After (Phase 07.1) |
|-----------|---------------------------|---------------------|
| `period_start !== period_end` | `Iberia 868 AD` (freeform) | `868–1000 AD` |
| `period_start === period_end` | `Iberia 868 AD` (freeform) | `868 AD` |

Full microcopy rows (replacing the corresponding rows in `07-UI-SPEC §Copywriting Surface 2`):

- Fresh-run: `Última pesquisa: {provider} · {model} · {period_rendered} · {generated_at YYYY-MM-DD HH:mm}`
- Cache-hit two-line: `Pesquisa gerada: {provider} · {model} · {period_rendered} · {generated_at YYYY-MM-DD HH:mm}` / `· aplicada: {applied_at YYYY-MM-DD HH:mm}`

Where `period_rendered` is `"{period_start}–{period_end} AD"` when `start !== end`, else
`"{period_start} AD"`.

## Interaction Contract

### `ResearchDialog` — period numeric inputs

| Behavior | Spec |
|----------|------|
| Field type | `<TextField.Root type="number" min="1" max="2100" step="1">` for both Início and Fim. Radix `TextField.Root` renders `<input>` — set `type` via the `type` prop (see Radix Themes docs for pass-through props). |
| Layout | `<Flex gap="2">` with two `<Box flex="1">` wrappers, each containing a label + input. The label is `<Text size="2" weight="medium" as="label">` with `htmlFor` pointing to the input `id`. |
| Seed on open | When `ResearchDialog` opens, read `Project.period_start` and `Project.period_end` from `useProject(projectId)`. If non-null, seed the inputs as controlled values. If null, inputs render empty (no fallback default — D-03). |
| Validation timing | Validate on blur (individual fields) and on submit attempt. Do NOT validate on every keystroke. |
| Submit guard | "Iniciar pesquisa" CTA remains disabled when: (a) either input is empty, (b) either input is outside [1, 2100], (c) period_start > period_end. The backend schema enforces the same rules as a second line of defense. |
| Payload shape | `JSON.stringify({ ..., period_start: Number(startInput), period_end: Number(endInput), ... })` — integers, not strings. The `period_label` field is removed entirely (D-04c). |
| `canSubmit` extension | Add to the existing `canSubmit` useMemo conditions: `periodStart >= 1 && periodStart <= 2100 && periodEnd >= 1 && periodEnd <= 2100 && periodStart <= periodEnd`. |
| Initial focus | Unchanged from Phase 07 — first writable field on open. With the Período field now split into two, focus goes to the "Início" input (it is the first editable field after the read-only País). |

### `AuthSetupSheet` — interaction contract

| Behavior | Spec |
|----------|------|
| Open trigger | Clicking "Configurar provedores" link in `ResearchDialog` rodapé opens `AuthSetupSheet` as a nested Radix `Dialog.Root`. Uses the `open` + `onOpenChange` controlled pattern (no `Dialog.Trigger` inside `AuthSetupSheet` — trigger lives in `ResearchDialog`). |
| Z-order | Radix `Dialog.Root` portals to `document.body` automatically — stacking is correct without manual z-index. The AuthSetupSheet dialog sits above ResearchDialog. |
| Focus management | On open: focus moves to the first interactive element inside `AuthSetupSheet` (the model `Select.Trigger` or the "Fechar" button if dropdown is disabled). On close: Radix auto-returns focus to the "Configurar provedores" link element in `ResearchDialog`. |
| ESC key | ESC closes only `AuthSetupSheet` (the innermost open dialog). ResearchDialog remains open with focus returned to the rodapé link. |
| Health query | `useLlamacppHealth()` — `useQuery` against `GET /api/v3/research/providers` filtered to `provider_id === 'llamacpp'`. **No polling interval** while AuthSetupSheet is open (user refreshes by reopening the sheet). Stale time: 10s. Re-fetches on sheet open (`enabled: isOpen`). |
| Model dropdown source | `useLlamacppHealth().data?.available_models ?? []`. Alphabetical order (already sorted server-side). Empty list → disabled dropdown + empty-models-dir hint. |
| Dropdown disabled state | Disabled (NOT hidden) when `available_models.length === 0`. The empty-models-dir hint renders below the dropdown. This is the "disabled + hint is discoverable" contract (CONTEXT §Claude's Discretion #6). |
| "Levantar servidor" disabled conditions | Any of: (a) no model selected, (b) `available_models.length === 0`, (c) llama-server binary missing (`healthy === false` and message contains "não encontrado"). |
| Launch action | `useLlamacppLaunch` — `useMutation` against `POST /api/v3/llm/llamacpp/launch` with body `{ "model": selectedModel }`. On 2xx: status line updates to running state; "Levantar servidor" swaps to "Parar servidor". On HTTP 409: render inline conflict error. On other errors: render generic launch error. |
| Idempotency (same model already running) | Server returns 200 `{ok: true, base_url, pid, model, started_at}` — UI updates to running state with the existing PID. No error shown. |
| Stop action | "Parar servidor" red button sends `DELETE /api/v3/llm/llamacpp/launch`. On 2xx `{ok: true}`: status returns to "Nenhum servidor ativo."; button reverts to "Levantar servidor". On error: render stop-error inline. |
| Tabs shell | `<Tabs.Root defaultValue="llamacpp">` with `<Tabs.List>` containing three `<Tabs.Trigger>` items: "Llama.cpp local" (value "llamacpp", active), "Claude" (disabled), "Ollama" (disabled). Only `<Tabs.Content value="llamacpp">` renders content. The `disabled` prop on `Tabs.Trigger` is supported by Radix Themes Tabs primitive. |
| No polling after launch | Once the server is running, the UI does NOT poll for liveness. The "Parar servidor" button is the user's explicit stop control. If the server crashes externally, the UI reflects stale "running" state until the user re-opens the sheet and re-fetches. This is acceptable for a local single-user tool. |

### Cross-surface interactions

| Behavior | Spec |
|----------|------|
| Dialog z-order | ResearchDialog (outer) → AuthSetupSheet (inner). Both use Radix `Dialog.Root`; stacking is automatic. At most one inner sheet open at a time. |
| Focus return chain | AuthSetupSheet close → focus returns to "Configurar provedores" link in ResearchDialog → user can continue with research form. |
| ResearchDialog period validation on submit | Validation errors from the two numeric inputs do not block AuthSetupSheet from opening. The two interactions are independent. |
| Backend state shared between sheets | `useLlamacppHealth` is consumed in both the model dropdown (AuthSetupSheet) and potentially in `ProviderSelector` (ResearchDialog). TanStack Query cache deduplicates the request. |
