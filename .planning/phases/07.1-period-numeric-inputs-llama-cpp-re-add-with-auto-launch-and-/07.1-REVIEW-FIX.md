## Fixed Issues

### WR-01: `_is_outer_session` leaks two unclosed `AsyncSession` connections

**Files modified:** `backend/medieval_forge/services/research/runner.py`, `backend/tests/integration/test_research_sse.py`
**Commit:** cdc269d
**Applied fix:** Rewrote `_is_outer_session` to use `getattr(session_factory, "_is_outer", False)` instead of calling the factory twice to compare object identity. The old approach allocated two real `AsyncSession` objects from the SQLAlchemy pool (and leaked them) on every research run completion. Added a `_outer_factory(session)` helper in the integration test file that creates a properly-flagged lambda (`factory._is_outer = True`), and replaced all 8 bare `lambda: db_session` usages with `_outer_factory(db_session)` so the test seam still works correctly.

### WR-02: `hs = None` dead assignment + `available_models` silently dropped

**Files modified:** `backend/medieval_forge/api/v3/research.py`
**Commit:** 2a425b2
**Applied fix:** In the `else` branch of `get_providers` (providers that implement `health_check` but not `health`): removed the `hs = None` dead assignment from the `except` block, moved `available_models = None` into the `except` block so the variable is always defined on the exception path, and added `available_models = list(hs.available_models) if hs.available_models is not None else None` into the `else` clause so that any provider returning `available_models` via `health_check()` now surfaces it in the providers response, matching the behavior of the `health()` branch.
