## Período numérico — semântica

### Q1: Aceita anos negativos pra BC (Antes de Cristo)?

| Option | Description | Selected |
|--------|-------------|----------|
| Só AD positivo (Recomendado) | min=1, max=2100. Escopo Medieval Forge é medieval (~500–1500 AD). BC fora do domínio; rejeita no schema com mensagem clara. | ✓ |
| Aceita negativo pra BC | Permite -3000..2100. Frontend mostra 'a.C.'/'AD' como sufixo. Mais flexível mas adiciona caso de borda em todos prompts/labels. | |

**User's choice:** Só AD positivo (Recomendado)

### Q2: Validação do par start/end?

| Option | Description | Selected |
|--------|-------------|----------|
| start < end estrito (Recomendado) | Período precisa ser intervalo não-vazio. start==end rejeitado. Bate com semântica do prompt ('start...end reference'). | |
| start <= end | Permite ano único (start==end). Prompt já trata period_end opcional; faz sentido pra 'snapshot de 868 AD'. | ✓ |

**User's choice:** start <= end (não-recomendado)
**Notes:** Permite snapshot ano único (start==end) — alinha com semântica do prompt onde period_end é "focus reference".

### Q3: De onde vem o valor inicial do form quando dialog abre?

| Option | Description | Selected |
|--------|-------------|----------|
| Project.period_start/end do DB (Recomendado) | Lê colunas existentes no Project. Vazio se nullable. Frontend faz GET no project antes de abrir. | ✓ |
| Region YAML defaults | Cada region.yaml ganha campos display_period_start/end (e.g. iberia_868.yaml → 868/1000). Dialog lê via /api/v3/regions. | |
| Sem default, usuário digita | Campos vazios na abertura. Simples mas chato pro usuário repetir anos toda hora. | |

**User's choice:** Project.period_start/end do DB (Recomendado)

### Q4: Limites de validação no schema?

| Option | Description | Selected |
|--------|-------------|----------|
| 1–2100 AD (Recomendado) | Schema pydantic conint(ge=1, le=2100). Cobre toda história documentável sem permitir lixo. | ✓ |
| 500–1500 AD (escopo medieval) | Restringe ao escopo do projeto. Mais defensivo mas bloqueia experimentação. | |
| Sem bounds rigorosos | Só valida tipo int e start<end. Deixa usuário escolher livremente. | |

**User's choice:** 1–2100 AD (Recomendado)

## Llama.cpp infra — dir, binário, porta, lifecycle, health()

### Q1: Onde llama.cpp procura .gguf files?

| Option | Description | Selected |
|--------|-------------|----------|
| Env var + fallback ~/.medieval-forge/models/ (Recomendado) | MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR override; default home subdir. Top-level only. Filtra .gguf. | ✓ |
| Hardcode ~/.medieval-forge/models/ | Zero config. Symlink se quer outra pasta. | |
| Configurável via UI | AuthSetupSheet expõe campo persistido em DB. Overkill agora. | |

**User's choice:** Env var + fallback ~/.medieval-forge/models/ (Recomendado)

### Q2: Como resolver caminho do executável llama-server?

| Option | Description | Selected |
|--------|-------------|----------|
| PATH + env LLAMA_SERVER_BIN override (Recomendado) | shutil.which primário; env sobrescreve. Se nenhum: health falsy. | ✓ |
| Só PATH | Sem override. Bloqueia instalações custom. | |
| Caminho fixo bundled | Implica downloader. Fora de escopo. | |

**User's choice:** PATH + env LLAMA_SERVER_BIN override (Recomendado)

### Q3: Endpoint POST /llamacpp/launch — porta + idempotência + flags?

| Option | Description | Selected |
|--------|-------------|----------|
| Porta auto-pick + idempot por modelo (Recomendado) | socket.bind(('',0)). Idempot por model_path. Flags fixas --ctx-size 8192. | ✓ |
| Porta fixa 8080 + idempot por porta | Default clássico. Falha se 8080 ocupada. | |
| Usuário configura port | AuthSetupSheet campo 'porta'. Mais código. | |

**User's choice:** Porta auto-pick + idempot por modelo (Recomendado)

### Q4: Cleanup do processo llama-server na saída do app + health() shape?

| Option | Description | Selected |
|--------|-------------|----------|
| Lifespan shutdown + DELETE endpoint + HealthStatus.available_models (Recomendado) | FastAPI lifespan + atexit fallback. DELETE endpoint. HealthStatus ganha campo opcional. 'ok' alias de 'healthy'. | ✓ |
| Só atexit + sem campo no HealthStatus | Mais simples. Método separado list_models() fora do Protocol. | |
| Daemon mode | Warm start mas processo órfão consumindo RAM. | |

**User's choice:** Lifespan shutdown + DELETE endpoint + HealthStatus.available_models (Recomendado)
