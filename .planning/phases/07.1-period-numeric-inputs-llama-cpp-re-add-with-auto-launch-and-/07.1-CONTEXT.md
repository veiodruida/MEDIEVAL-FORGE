## Phase Boundary

Two coupled deliverables that round out Phase 07's research surface:

1. **Numeric period inputs end-to-end.** Replace the single free-text
   `period_label: str` payload (ResearchDialog → `POST /api/v3/research/start`
   → runner → `cache_key` → `research_overlay.meta.json`) with a typed pair
   `period_start: int, period_end: int` (years AD). The prompt builders in
   `backend/medieval_forge/services/llm/prompt.py` already take
   `(period_start: int, period_end: int)` — Phase 07 only emitted a
   placeholder string into the runner-side prompt bridge. Phase 07.1 closes
   that loop and tightens schema-level validation.

2. **Llama.cpp provider re-add (deleted in `87f8aab`).** Register a new
   `LlamaCppProvider` under `services/llm/registry.py`, with three additions
   beyond the v1 implementation (commit `150561a`, archived for reference):
   - **Filesystem model listing.** `health()` returns
     `{healthy, message, available_models: list[str] | None}` where
     `available_models` is the alphabetically-sorted list of `.gguf` files
     in a configurable directory (env `MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR`,
     fallback `~/.medieval-forge/models/`, top-level only, non-recursive).
   - **Auto-launch endpoint.**
     `POST /api/v3/llm/llamacpp/launch` spawns `llama-server -m <selected>.gguf
     --ctx-size 8192 --port <auto>` via `subprocess.Popen`; idempotent by
     model path; returns `{ok, base_url, pid, model}`.
     `DELETE /api/v3/llm/llamacpp/launch` stops it.
   - **AuthSetupSheet llama.cpp panel.** New
     `frontend/src/components/research/AuthSetupSheet.tsx` (Radix Dialog,
     opened from the rodapé of `ResearchDialog`) exposes the model dropdown
     sourced from `health().available_models` plus a "Levantar servidor"
     button that invokes the launch endpoint.

## Implementation Decisions

### Period numeric inputs

- **D-01 (AD positive only, range `[1, 2100]`):** Pydantic
  `conint(ge=1, le=2100)` on both `period_start` and `period_end`. Medieval
  Forge's domain is ~500–1500 AD, but 1–2100 covers any documented
  historical experiment without permitting garbage (e.g. 99999). BC
  (negative years) is rejected at the schema layer — domain boundary
  decision, not a technical constraint.

- **D-02 (`start <= end`):** Allows snapshot-style requests where
  `period_start == period_end` (e.g. "Iberia exactly at 868 AD"). The
  prompt builders already treat `period_end` as a focus reference, not
  a hard range, so equality is semantically clean. Enforced via Pydantic
  model-level `@model_validator(mode='after')` so DTO is consistent.

- **D-03 (Seed defaults from `Project.period_start / period_end`):** The
  Project model already exposes those columns (nullable since migration
  0005). Frontend `useProject(projectId)` hook fetches them; ResearchDialog
  seeds the two number fields on open. If either column is `null`, the
  input renders empty (no fallback to a region default — D-V3-05 says
  RegionConfig is the only mutable input from the pipeline side; the
  user expressly chose the project's period when creating it).

### Cache + meta sidecar migration

- **D-04 (Truncate `research_cache` on migration; do not re-key):**
  Alembic 0007 forward-only migration runs `DELETE FROM research_cache`.
  Single-user local app; the cost of a one-time re-run per project is
  trivial against the maintenance cost of a regex-based re-key heuristic
  that would silently drop ambiguous rows. Downgrade path is a no-op
  (no guarantee old cache contents are preserved).

- **D-04b (Meta sidecar swaps `period: str` for `period_start: int` +
  `period_end: int`):** Breaking change to
  `research_overlay.meta.json`. Existing meta files become unreadable
  by the new microcopy renderer; the meta sidecar is a per-project
  artifact, so users that need the historical names re-run research
  (which the cache truncate forces anyway). Frontend
  `"Última pesquisa: {provider} · {model} · {timestamp}"` microcopy
  (Phase 07 BLOCKER 2) updates to consume the new shape; period gets
  rendered as `"{start}–{end} AD"` (or `"{start} AD"` when start == end).

- **D-04c (API body breaking change atomic):** `StartResearchBody` drops
  `period_label`, gains `period_start` + `period_end`. No transitional
  dual-acceptance shim. Local single-user app — coordinated swap of
  backend + frontend in one merge is cheaper than carrying both fields.

### Llama.cpp UI placement

- **D-05 (New `AuthSetupSheet.tsx` Radix Dialog, nested from
  `ResearchDialog`):** Matches SC-#5 literal wording. Component lives at
  `frontend/src/components/research/AuthSetupSheet.tsx`. Trigger is a
  "Configurar provedores" link in the rodapé of `ResearchDialog` (next
  to the existing Cancelar button). Opens as a nested Radix Dialog;
  closes return focus to `ResearchDialog`. Single Llama.cpp panel inside
  for now — layout reserves a `<Tabs.Root>` shell with one
  `<Tabs.Trigger>` so adding Claude/Ollama tabs later is mechanical.

- **D-06 (Claude paste-API-key stays inline in `ResearchDialog`):** Per
  Phase 07 D-09. Moving the paste-key into AuthSetupSheet would be a
  refactor of an already-shipped surface; phase 07.1 is additive.
  AuthSetupSheet panel for Claude/Ollama is a deferred idea.

### Llama.cpp infrastructure

- **D-07a (Models dir: env override + fallback `~/.medieval-forge/models/`):**
  - Resolution: `os.environ.get("MEDIEVAL_FORGE_LLAMACPP_MODELS_DIR")
    or Path.home() / ".medieval-forge" / "models"`.
  - Scan: `Path.iterdir()` (top-level only, non-recursive), filter to
    `*.gguf` (case-insensitive on the suffix), sort
    alphabetically. Return filename relative to the directory (not full
    path) so the UI dropdown shows clean labels and the server-side path
    is reconstructed at launch time.
  - Missing dir: returns empty `available_models=[]` (NOT an error).
    UI dropdown renders disabled with hint "Coloque arquivos .gguf em
    `<resolved path>`".

- **D-07b (llama-server binary: `shutil.which` + env override):**
  - Resolution: `os.environ.get("LLAMA_SERVER_BIN") or
    shutil.which("llama-server")`. Cross-platform: on Windows
    `shutil.which` already handles `.exe`.
  - Missing binary: `health()` returns
    `healthy=False, message="llama-server não encontrado no PATH (defina
    LLAMA_SERVER_BIN)", available_models=[<still listed if dir exists>]`.
    The UI shows the dropdown (so users see their models) but disables
    "Levantar servidor".

- **D-08 (Launch endpoint: auto-pick port, idempotent by model path):**
  - Body: `{ "model": "<filename>.gguf" }` (filename relative to the
    resolved models dir; backend joins to absolute path).
  - Port: `with socket.socket() as s: s.bind(('', 0)); port = s.getsockname()[1]`
    pattern (release immediately so llama-server can bind). Race window
    is acceptable for single-user local app.
  - Idempotency: keyed on absolute model path. If the launcher's
    in-memory state shows a live PID for the same model path, return
    `{ok: True, ...}` with the existing `{base_url, pid, model}`. If a
    DIFFERENT model is alive: return HTTP 409 with structured detail
    "modelo `<existing>` ativo — pare-o antes via DELETE".
  - Flags: fixed `--ctx-size 8192 --port {auto} -m {absolute_path}`.
    No `--n-gpu-layers` (let llama-server defaults choose). No user-
    configurable flags this phase (deferred).
  - Response: `{ok: bool, base_url: str (e.g. "http://127.0.0.1:38291"),
     pid: int, model: str (filename), started_at: ISO8601}`. The same
    base_url is what the LlamaCppProvider uses for subsequent research()
    calls (credentials dict gets `base_url` injected from this response).

- **D-08b (Lifecycle: FastAPI lifespan shutdown + atexit fallback +
  DELETE endpoint):**
  - `main.py` lifespan registers `await llamacpp_launcher.shutdown()`
    on app exit (sends SIGTERM, waits up to 5s, then SIGKILL).
  - `atexit.register(llamacpp_launcher.shutdown_sync)` as belt-and-
    braces for non-lifespan exit paths (e.g. uncaught exception during
    bootstrap).
  - `DELETE /api/v3/llm/llamacpp/launch` (no path param — Phase 07.1
    runs one llama-server at a time) calls
    `llamacpp_launcher.shutdown()` and returns `{ok: True}`.
  - No PID file persisted across runs (only in-memory). If a llama-server
    is still running from a previous crashed app instance, the user has
    to kill it manually; the next launch attempt detects the port
    collision and surfaces a clear error. (Persistent PID file deferred
    to backlog if it becomes painful.)

- **D-09 (HealthStatus shape: add optional `available_models`):**
  `HealthStatus` gains `available_models: list[str] | None = None`.
  - `None` (default) for Claude (it doesn't list models that way).
  - `[]` or populated list for Ollama (already partially surfaced via
    `/providers` endpoint — Plan 07-07b T-07-07b-01 comment) and
    Llama.cpp.
  - The existing `healthy: bool` stays the canonical "is this provider
    usable right now?" signal. SC-#3's `{ok, message, available_models}`
    phrasing is satisfied by the existing `healthy` field plus the new
    field — no rename to `ok` (would force a touch of Claude+Ollama for
    no behavioral benefit).
  - The `/api/v3/research/providers` builder surfaces
    `available_models` in its per-provider entry when present.

## Specific Ideas

- **"Period inputs already integer in prompt builders"** — D-01..D-03.
  The hard work (prompt.py) was done in Phase 07. Phase 07.1 is mostly
  thread-the-needle: dialog → API → runner → cache → meta. One coherent

  "Levantar servidor" with the same model is a no-op + success indicator.
- **"HealthStatus extends, not renames"** — D-09. SC-#3's `{ok, ...}`

  touch Claude/Ollama implementations to rename a key.
