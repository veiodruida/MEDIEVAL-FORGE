## Decisions Made

- **`_RUN_STOP_EVENTS` symmetry in generate**: even though `_generate_producer` never writes to `_RUN_STOP_EVENTS`, we pop it in the finally (with `default=None`) anyway to keep both producers' finally blocks grep-equivalent. Plan §`<action>` Task 2 explicitly endorsed this ("harmless and keeps both producers symmetric"). The cost is one no-op `dict.pop` per generate run; the value is uniform finally shape across both routers.
- **Ordering reaffirmed**: `await queue.put(None)` runs first (terminal sentinel for already-attached consumers); the four `.pop` calls follow synchronously. Per the threat register T-04.1-01-04 disposition, this prevents any consumer-vs-pop race because the consumer's `while ... if msg is None: break` exits cleanly via the sentinel regardless of pop ordering.

### Auto-fixed Issues

**1. [Rule 1 - Bug] Reshape two pre-existing test_render_cancel.py tests to post-WR-02 subscribe-before-release contract**

- **Found during:** Task 1 (regression check after applying render-side fix)
- **Issue:** Two pre-existing tests (`test_cancel_on_first_render_falls_back_to_generate_baseline` at line 213, `test_cancel_does_not_update_cache` at line 249) implicitly depended on the WR-02 bug — their stubs completed synchronously (raised `StageCancelled` immediately or after fast on_stage calls), so by the time the test code reached `client.stream("GET", .../render/stream")` the producer's `finally` had already enqueued `None` AND the WR-02 bug kept the key in `_RUN_QUEUES`, letting the late subscriber return 200 and read the sentinel. After the fix, `_RUN_QUEUES.pop` removes the key, so the same flow now returns 404 and the tests fail at `assert resp.status_code == 200`.
- **Fix:** Restructured both tests to gate the stub on a `threading.Event proceed`: the stub calls `proceed.wait(timeout=5.0)` before raising; the test opens the stream first, then calls `proceed.set()` from the asyncio loop. This codifies the real production usage pattern (frontend subscribes immediately after `POST /render` returns 202).
- **Files modified:** `backend/tests/integration/test_render_cancel.py` (added `import threading`; gate pattern in both tests)
- **Verification:** `python -m pytest tests/integration/test_render_endpoint.py tests/integration/test_render_cancel.py -v` → 15/15 green; `python -m pytest tests/unit/test_v3_generate.py tests/integration/test_render_endpoint.py tests/integration/test_render_cancel.py -v` → 26/26 green
- **Committed in:** `cf51524` (part of Task 1 GREEN commit)
- **Why in scope:** plan acceptance criterion explicitly required "Existing tests in `backend/tests/integration/test_render_endpoint.py` and `backend/tests/integration/test_render_cancel.py` continue to pass (no regression)". These two tests were the regression; they were caused by the WR-02 fix directly. Fixing them is the only way to satisfy the acceptance criterion.
