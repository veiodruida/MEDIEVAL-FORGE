## Decisions Made

- **Bounded retry semantics**: counts 1/2/3 re-queue, count 4 surfaces error. The check `if (nextCount <= RENDER_BUSY_MAX_RETRIES)` (≤, not strictly <) is what makes "four times → error on 4th" match the test contract. Documented inline.
- **Counter reset on success vs window expiry, not on either separately**: a single Map entry tracks both `count` and `windowStart`. On any 409, the code checks `fresh = entry === undefined || now - windowStart >= WINDOW_MS` — if fresh, count restarts at 1 and windowStart = now; else count increments, windowStart preserved. A success path calls `retryState.current.delete(projectId)` to clear the slot, so the next 409 reads `entry === undefined` and starts fresh.
- **Module-level hook mock for D-06 test (vs spying on `postRender`)**: the plan's test contract specifies `expect(useParameterStudioDispatch).toHaveBeenCalledWith('proj-1', expect.any(Function))` directly. Mocking the hook at the module level is the cleanest assertion that ParameterSidebar consumes the canonical dispatch path; spying on `postRender` would couple the consolidation test to the hook's internal sequence. The pre-existing tests don't exercise the dispatch path (they only assert DOM rendering), so the module-level mock is non-disruptive.
- **`renderStream.close()` removal is intentional and safe**: useRenderStream.subscribe() already calls `close()` at line 34 before opening a new EventSource; Plan 04.1-01's producer eviction guarantees the prior /render producer's `None` sentinel + dict-pop landed before the new subscribe attaches. Both conditions together close the SSE-leak vector that justified the explicit close() in the inlined copy.
