patterns-established:
  - "Memoization key as effect gate: when an effect must distinguish 'new object ref, same value' from 'real value change', memoize a primitive key (string of scalars) and compare it via useRef in the effect. The dep array on the memo MUST list the primitive scalars (NOT the object), and the effect dep MUST be the memoized key (NOT the object). This is the canonical anti-pattern fix for over-fired effects in React."
  - "Decoupled effects for decoupled concerns: when an effect fires for two independent reasons (bounds change, viewport change), split into two effects with independent gating refs. The viewport effect's first-measurement skip prevents double-fit on mount. Future canvas affordances (e.g., per-stage stage-view fit-restore) can plug in as separate effects without modifying these two."

## Issues Encountered

- **Task 1 Test 2 initial RED revealed a deeper bug than the plan predicted**: the plan diagnosed UAT gap #1 as "fitToView fires on every projection ref change". Empirically (Task 1 Test 2 failing as `expected 1 to be greater than 1`), the actual code did NOT call setProjection on subsequent renders due to the `!projection` guard at line 167 (pre-fix) — meaning fitToView was actually NOT firing on slider re-renders in the test environment. The real production bug is likely a combination of (a) cacheVersion bump triggers TanStack refetch → component re-enters loading branch → ResizeObserver disconnect+reconnect via setContainerRef → new getBoundingClientRect → setViewportW/H → existing viewport-aware fit-to-view effect fires. The fix (bounds-key gate on auto-fit + separate viewport-key effect) covers BOTH mechanisms regardless of which one triggers in production. Advisor confirmed: don't re-diagnose, just ship the structural fix that closes both vectors.
- **Test 7 (D-13 regression) initial RED failed because Zustand `setState` is not wrapped in act()**: the test calls `useRunStore.setState({ priorTokens: { render: 'tok-prev' } })` to simulate the revertStage action, but React 19 + jsdom doesn't flush the resulting re-render before the spy is queried. Wrapped the setState in `act(() => { ... })` to force flush. Common React Testing Library idiom; resolved cleanly.
