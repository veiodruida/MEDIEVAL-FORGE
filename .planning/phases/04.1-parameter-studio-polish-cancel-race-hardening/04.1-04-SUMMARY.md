## Decisions Made

- **`pixel_count` deliberately omitted from BaronyFeature/BaronyRender (Karpathy surgical change):** the backend emits it on baronies.geojson properties (line 234 of canvas_sidecars.py), but no Phase 04.1 consumer reads it from the Feature/Render path — the InspectorSidebar Area row reads pixel_count from `metadata.baronies` (territory_metadata.json), not from BaronyRender. Adding it "for completeness" would inflate the diff for zero immediate consumer benefit. Acceptance criterion explicitly tested: `grep -c pixel_count useCanvasArtifacts.ts` did NOT increase from baseline (stayed at 2 = the two pre-existing references on `TerritoryMetadataCondado.pixel_count` and `metadata.baronies[].pixel_count`).
- **Centroid plumbed via `baronies` prop (option a), not via metadata.baronies extension (option b):** territory_metadata.json is already-on-disk for every project; option (b) would either require a migration script or a "read with-or-without" branch. baroniesQ.data already exists in CanvasViewer and is BaronyRender[] (not | undefined) at the render path via the existing early-return guard at lines 345-358 — TS narrows correctly without `!` or cast. Confirmed by typecheck (tsc --noEmit exit 0).
- **Display convention `lat, lon` (lat first, 3-decimal precision):** mirrors the existing condado branch (InspectorSidebar lines 225-226: `${condado.lat.toFixed(3)}, ${condado.lon.toFixed(3)}`). BaronyRender.centroid is stored as `[lon, lat]` per the backend emission; therefore `centroid[1]` is lat, `centroid[0]` is lon. Precedent-driven, not a fresh decision.
- **Test describe ordering matters (advisor flag #2 mitigated):** the new D-03 describe block lives LAST so its `selectedBaronyId: 'B_BETANZOS'` setState in beforeEach cannot leak into prior describe blocks. Belt-and-suspenders: every pre-existing beforeEach now resets `selectedBaronyId: null` defensively.
- **Native `<details>`/`<summary>` for the explainer:** zero JS handlers, no Radix `<Collapsible>` dependency, no library coupling. Content always in the DOM (browser collapses via CSS user-agent default), which means testing-library asserts the PT-BR text without needing fireEvent.click to expand — caught by advisor flag #3.
