## Implementation Decisions

### D-01 — Stable projection key for zoom/pan persistence (UAT #1, severity major)

`CanvasViewer.tsx:206-208` currently re-runs `fitToView()` whenever the `projection` reference changes. The fix is a stable bounds key that only triggers `fitToView()` when bounds actually change, NOT when a slider re-render produces a new projection object with identical bounds.

- Stable key format: `${mapW}x${mapH}:${lon_min},${lat_min},${lon_max},${lat_max}` (or equivalent — projection-derived, not reference-derived)
- Track previous key with `useRef`; compare on each effect run; call `fitToView()` only on key mismatch
- Slider re-render produces NEW projection reference but IDENTICAL bounds → effect must NOT fire
- Genuine bounds change (project switch, region load, viewport resize) → effect MUST fire
- Vitest coverage: simulate /render hydration cycle, assert `fitToView` mock called exactly once across N slider-driven projection reference changes
- Playwright coverage: drag σ slider, manually zoom in, drag σ again, assert zoom level preserved (Konva Stage `scaleX`/`scaleY` unchanged)

### D-02 — Before/after preview affordance (UAT #2, severity minor)

Surface the existing `priorToken` from `useRunStore` as a held-gesture canvas swap. The raster for the prior state already exists in the cache — only the UI affordance is missing.

- Gesture: hold spacebar (PT-BR keyboard friendly) — pressed = show prior raster, released = show current
- Visual indicator while held: small badge overlay on canvas reading "Anterior" (PT-BR for "Previous") in top-left corner; disappears on release
- Disabled state: when `priorToken` is null (first render of project) the gesture is a no-op
- Alternative considered (split-view side-by-side) is REJECTED: heavier implementation, doubles canvas memory, conflicts with current single-Stage Konva architecture
- Alternative considered (diff highlight overlay) is REJECTED: requires pixel-diff computation, not aligned with the "compare at a glance" UX requested
- Vitest coverage: hold gesture dispatches `useRunStore` action that toggles a `previewPrior` boolean; release reverts
- Playwright coverage: drag σ 3.0→4.5, wait render complete, press-and-hold space, assert Stage raster source URL contains `priorToken`; release, assert URL contains current `cacheVersion`

### D-04 — Cancel→POST 409 race: re-queue, not error (WR-01)

`useParameterStudioDispatch.ts:32-41` and `ParameterSidebar.tsx:37-47` currently transition `useRunStore` to `'error'` when `postRender` returns 409 right after a `postRenderCancel`. The fix is to treat `RENDER_BUSY` as a non-fatal condition and re-queue the debounced dispatch.

- Detection: `catch (e)` block inspects `(e as Error).message === 'RENDER_BUSY'`
- Recovery: call the dispatch ref again (DebouncedState) — re-queues at 250ms (this is the verbatim WR-01 fix from `04-REVIEW.md`)
- Extension beyond WR-01 (defensive bound to prevent infinite re-queue if the backend is permanently busy, not part of the original review patch): re-queue up to 3 times within a 1.5s window; on the 3rd consecutive 409 surface `useRunStore.finish('error', 'RENDER_BUSY')` (real backend failure, not a race). Reject this extension during planning if the team prefers strict review-fidelity — the unbounded re-queue is acceptable too
- Counter resets on a successful `postRender` (`run_id` returned)
- This fix MUST land in BOTH dispatch sites before D-06 consolidation, OR D-06 (consolidation) MUST land first and the fix is applied once — planner picks the order
- Vitest coverage: mock `postRender` to return 409 twice then 200; assert dispatch eventually starts a render and `useRunStore` never enters `'error'`
- Vitest coverage: mock `postRender` to return 409 four times; assert `useRunStore.finish('error', 'RENDER_BUSY')` is called on the 4th attempt

### D-05 — Producer task eviction in `finally` (WR-02)

`backend/medieval_forge/api/v3/render.py:177-180` `_render_producer` `finally` block pops `_RUN_STOP_EVENTS` and `_RUN_KIND` but leaves `_RUN_QUEUES[project_id]` and `_RUN_TASKS[project_id]` populated. Same in `generate.py` `_generate_producer`. A late `GET /render/stream` (or `/generate/stream`) call passes the 404 guard, finds the drained queue, and awaits `queue.get()` forever.

- Extend `finally` in `_render_producer` to also pop `_RUN_QUEUES.pop(project_id, None)` and `_RUN_TASKS.pop(project_id, None)`
- Apply identical fix in `_generate_producer`
- Update the Pitfall 9 comment in `generate.py:205` to match the fixed behavior: the current comment claims "post-run stream returns 404" but pre-fix the stream actually HANGS (per WR-02). After this fix the 404 claim becomes correct again — adjust any wording that references pre-fix hang behavior
- Unit test (pytest): drive `_render_producer` to completion, assert `_RUN_QUEUES` and `_RUN_TASKS` no longer contain the project_id key
- Unit test (pytest): same for `_generate_producer`
- Integration test: complete a render, then call `GET /render/stream` and assert it returns 404 within 100ms (not hang)

### D-06 — Single canonical dispatch path (WR-03)

Consolidate so a single source-of-truth exists.

- Direction: `ParameterSidebar.tsx` imports and uses `useParameterStudioDispatch`; the inlined copy is removed
- The hook is the canonical path; tests already cover it
- The hook signature MUST accept `onRenderStarted?: (runId: string) => void` so `ParameterSidebar.tsx` can wire `renderStream.subscribe(projectId)` (existing behavior)
- Existing imports in `ParameterSidebar.tsx` for `postRenderCancel`, `postRender`, etc., are removed unless still needed elsewhere in the file
- D-04 fix (RENDER_BUSY re-queue) lands in `useParameterStudioDispatch` only — the consolidation eliminates the divergence risk
- Vitest coverage: existing `usePipelineParams.test.ts` (or equivalent) keeps passing; add a new test asserting `ParameterSidebar` invokes the hook

<specifics>
## Specific Ideas

### Stable projection key candidates (D-01)
- Simplest: `useMemo(() => \`${mapW}x${mapH}:${lon_min},${lat_min},${lon_max},${lat_max}\`, [mapW, mapH, lon_min, lat_min, lon_max, lon_max])` — string compare in effect
- Alternative: track each scalar individually in effect deps (no string), works if the projection object exposes them as primitives

### Preview gesture event handling (D-02)
- Recommended attach point: `window.addEventListener('keydown'/'keyup', ...)` inside a `useEffect` in `CanvasViewer.tsx`
- Guard against repeated keydown events (key repeat) — use `e.repeat === false` for the activation, or a local boolean ref
- Restore current raster on `keyup` even if focus leaves the window (handle `blur` event too)

### Re-queue counter scope (D-04)
- Counter MUST be per-(project_id) so two simultaneously-open projects don't share state
- Recommended location: closure inside `useParameterStudioDispatch` factory, OR a `useRef<Record<string, number>>` map

### `finally` block ordering (D-05)
- Terminal sentinel `await queue.put(None)` MUST happen BEFORE the eviction pops, otherwise a consumer that already grabbed the queue reference can race the pop
- Reuse existing async-safe patterns from `generate.py` if symmetric

</specifics>
