# Phase 08.1 Plan 06: G3 Gap Closure — Insert Anchor by Double-Click

One-liner: Identity-safe insert-anchor by double-click (dedicated hit-Path, component-local NO-OP) with splitPolyRange+findNearestSegmentAndVertex unit tests, closing-segment bug fix, and Playwright G3 re-verification end-to-end.

## What Was Done

### Task 1 — splitPolyRange + findNearestSegmentAndVertex tests + closing-segment bug fix

**New tests added to bezierFit.test.ts (24 tests total):**

- `splitPolyRange`: 6 tests covering shared-endpoint contract (`left.rangeEnd === right.rangeStart`), full coverage preservation, exact numeric fixture `{4,9}→[{4,6},{6,9}]`, clamp at rangeStart, clamp at rangeEnd, clamp below rangeStart.
- `findNearestSegmentAndVertex`: 4 tests with an explicit 3-anchor triangle fixture (16 pxPts, known segment layout). Tests: click near segment 0 midpoint returns segmentIdx=0; splitVertexIndex strictly inside range; null when far from all segments; **closing segment (segmentIdx=N-1) is reachable** — this was the discriminating RED test.

**[Rule 1 - Bug] findNearestSegmentAndVertex closing-segment bug fixed:**
- The committed code (commit `4fe634a`) had `for (let s = 0; s < N - 1; s++)` with `b = anchors[s + 1]` — excluding the closing segment N-1 entirely.
- This contradicts G1+G2 (Plan 05: "WR-01 REVERSED — closing segment now editable") and the plan requirement "all N segments editable" with `anchor (s+1)%N`.
- Fix: changed to `for (let s = 0; s < N; s++)` with `b = anchors[(s + 1) % N]`.
- The discriminating test (click near closing segment midpoint returns `segmentIdx === 2`) was RED against the old code and GREEN after the fix.

### Task 2 — Wire double-click insert into BezierEditLayer (identity-safe NO-OP)

**handleInsertAtPx (extracted named handler):**
- `useCallback` that takes `clickPx: [number, number]` (stage-local px).
- Calls `findNearestSegmentAndVertex(clickPx, anchorsRef.current, originalRef.current.pxPts)`.
- Snaps new anchor to `pxPts[splitVertexIndex]` (integer index → valid range boundary).
- Derives `cp1Px/cp2Px` from the cubic tangent at t=0.5 (cubicBezierAt at t±0.05, handleOffset=15px) — display-only, committed verbatim on next drag.
- Calls `splitPolyRange` to split the segment's range into two contiguous disjoint sub-ranges.
- Inserts new anchor at `segmentIdx+1`, renumbers all `idx` fields, `setAnchors(next)`, `setActiveAnchorIdx(segmentIdx+1)`.
- **Zero calls to `setVerticesAndLog`** — store stays byte-identical (BEZ-IDENTITY-01 extended).

**bezier-hit-path (dedicated interactive Path):**
- Rendered immediately after the visible `bezier-curve-outline`.
- Same `data={pathData}`, `stroke="transparent"`, `strokeWidth={12}`, `listening={true}`, `data-testid="bezier-hit-path"`.
- `onDblClick` reads `stage.getPointerPosition()` (stage-local px) and delegates to `handleInsertAtPx`.
- Visible outline (`bezier-curve-outline`) unchanged: `listening={false}`, no `onDblClick`. BEZ-RENDER contract pinned.

**__forgeBezierTriggerInsert DEV hook (index-based):**
- Added to the existing DEV-gated `useEffect` alongside the other forge hooks.
- Signature: `(segmentIdx?: number) => boolean` (default segmentIdx=0).
- Reads `anchorsRef.current[segmentIdx]` and `anchorsRef.current[(segmentIdx+1)%N]`, builds stage-local `midPx = cubicBezierAt(a.anchorPx, a.cp2Px, b.cp1Px, b.anchorPx, 0.5)`.
- Delegates to `handleInsertAtPx(midPx)` — same path as real dblclick. Never calls setAnchors/setVerticesAndLog directly.
- Torn down in unmount cleanup.
- Added `handleInsertAtPx` to useEffect dependency array.

**jsdom getStage() guards:**
- Added `try/catch` wrappers around `layerRef.current.getStage()` in `__forgeBezierState`, `__forgeBezierTriggerDrag`, and `__forgeBezierTriggerHandleDrag`.
- In jsdom the Konva mock has no `getStage` method — the guards let all DEV hooks degrade gracefully (firstAnchor=null, stage=null) without throwing, so unit tests pass.

**BezierEditLayer.addpoint.test.tsx (8 tests):**
- `__forgeBezierTriggerInsert` registered on window after mount.
- Insert-without-drag: `store.vertices` byte-identical + `editLog.length` unchanged (uses `act()` to flush React state).
- BEZ-IDENTITY-01 extended: mount+insert+no-drag leaves vertices byte-identical AND editLog unchanged.
- `bezier-hit-path` rendered as a DISTINCT element from `bezier-curve-outline`.
- After insert: `anchorCount === anchorCount0 + 1` (reads window hook after `act()` re-render flush).
- Drag-after-insert: `editLog.length` grows via real `op:move` path; `lastEntry.op === 'move'` and `vertexIds.length > 0`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] findNearestSegmentAndVertex excluded the closing segment**
- **Found during:** Task 1 (discriminating test RED)
- **Issue:** The committed helper (commit `4fe634a`) used `s < N - 1` (with `b = anchors[s+1]`), silently dropping any double-click on the closing arc (segment N-1). This contradicts the G1+G2 mandate from Plan 05 that all N segments are editable.
- **Fix:** Changed loop to `s < N` with `b = anchors[(s+1)%N]`, matching `handleDragEnd`'s segment model.
- **Files modified:** `frontend/src/lib/bezierFit.ts`
- **Commit:** `4c7ea9e`

**2. [Rule 2 - Missing] jsdom getStage() guard in DEV hooks**
- **Found during:** Task 2 test run (TypeError in unit harness)
- **Issue:** `__forgeBezierState`, `__forgeBezierTriggerDrag`, `__forgeBezierTriggerHandleDrag` called `layerRef.current.getStage()` — which throws in jsdom because the Konva mock has no `getStage`. This made unit tests that read state or trigger drags fail with TypeError rather than testing the actual behavior.
- **Fix:** Added `try/catch` guards in all three hooks so they degrade gracefully (return null for stage/firstAnchor) instead of throwing.
- **Files modified:** `frontend/src/components/canvas/BezierEditLayer.tsx`
- **Commit:** `2b9d36b`

**3. [Refactor - Polish] Remove midPt dead code + harden insert tests (post-advisor)**
- **Found during:** Advisor review after plan completion
- **Issue:** `handleInsertAtPx` computed `const midPt = cubicBezierAt(..., 0.5)` but immediately discarded it with `void midPt` (the tangent direction is derived from `midNext-midPrev`, not midPt). Also, two insert-related tests used `if (inserted) { ... }` guards that could silently pass vacuously.
- **Fix:** Removed the three dead `midPt` lines; added unconditional `expect(inserted).toBe(true)` in anchorCount+1 and drag-after-insert tests (IBERIA_BARONY_RING segment 0 is always non-degenerate — confirmed by Playwright).
- **Files modified:** `BezierEditLayer.tsx`, `BezierEditLayer.addpoint.test.tsx`
- **Commit:** `fb0366b`
