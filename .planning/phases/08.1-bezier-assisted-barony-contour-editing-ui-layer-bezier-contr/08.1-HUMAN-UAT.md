## Gaps

### G1. Bézier curve not closed (open ring outline)
status: resolved
severity: high
expected: The Bézier outline forms a closed loop around the barony; every segment of the ring is editable.
actual: Some baronies show an open/unclosed Bézier. `buildPathData` (BezierEditLayer.tsx:96) iterates `i = 0 .. anchors.length-2`, drawing only anchor[0]→anchor[N-1]; it never emits the closing cubic anchor[N-1]→anchor[0]. The closing segment N-1 is also force-excluded from editing (`addSeg` guard `s < N-1`, line 387). Net: the closing arc is neither drawn nor editable, so the contour reads as open.
fix_hint: Emit the closing cubic in buildPathData (wrap N-1 → 0) and make segment N-1 editable (remove/relax the `s < N-1` guard), threading the closing range through buildPolyIndexMap.

### G2. Edited curve not saved (silent drop on commit)
status: resolved
severity: high
expected: Dragging any anchor or control handle and releasing persists the edit (store + render).
actual: WR-01 (08.1-REVIEW.md). For handles whose only affected segment is the non-editable closing segment — cp1 of anchor 0 (`addSeg(-1)` rejected) and cp2 of the last anchor (`addSeg(N-1)` rejected) — `dirty` ends empty, `changedIds.length === 0`, and handleDragEnd early-returns (line 426) AFTER the live preview already repainted (line 341). The user sees the curve follow the drag, releases, and the change vanishes. Tied to G1 — fixing the closing segment removes most of this dead zone.
fix_hint: After G1 makes segment N-1 editable, the empty-dirty case largely disappears. Also reconcile activeAnchorIdx after refit (WR-02) and harden zero-length flatten (WR-03).

### G3. Cannot add new control points
status: resolved
severity: medium
expected: User can add a new anchor/control point on the curve to increase contour detail.
actual: No add-point affordance exists. V1 fit is fixed at the cubic count fit-curve returns; the only edits are dragging existing anchors/handles.
fix_hint: New feature — double-click on the curve outline inserts an anchor at the nearest curve parameter, splitting the underlying segment's poly range. Out of original V1 scope; confirm priority before planning.

### G4. No color differentiation between lines, points, contour, controls
status: resolved
severity: low
expected: Distinct colors for curve outline vs. anchor points vs. control handles vs. tethers, so the edit surface is readable.
actual: Curve outline (CURVE_STROKE #4a9eff) is the SAME blue as inactive anchors (ANCHOR_INACTIVE_FILL #4a9eff). Handles + tethers share #94a3b8. Hard to distinguish elements at a glance.
fix_hint: Pick a distinct palette — e.g. contour one hue, anchors another, active anchor a third, handles/tethers a muted fourth. Update the UI-SPEC color table + the hex literals at BezierEditLayer.tsx:49-54.
