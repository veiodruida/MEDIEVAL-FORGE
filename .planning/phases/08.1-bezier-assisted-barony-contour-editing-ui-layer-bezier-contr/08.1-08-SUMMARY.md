## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing functionality] editedRingPtsRef for stale-closure safety**
- **Found during:** Task 2 implementation
- **Issue:** `editedRingPts` is computed by `useMemo` after the `useEffect` that registers `__forgeBezierState`. The useEffect closure captures a stale `editedRingPts = []` at effect registration time; subsequent `vertices` changes update the memo but not the closure. Reading the stale closure would always return `length=0` and an empty snapshot — making the Playwright geometry-change assertion useless.
- **Fix:** Added `editedRingPtsRef` (same pattern as `anchorsRef`) synced every render with `editedRingPtsRef.current = editedRingPts`. The DEV hook reads `editedRingPtsRef.current` (always current) instead of the captured `editedRingPts`.
- **Files modified:** `BezierEditLayer.tsx`
- **Commit:** `53dc9ab`

**2. [Rule 2 - Missing functionality] Playwright geometry-change assertion via snapshot (not count)**
- **Found during:** Task 3 design (advisor call before writing)
- **Issue:** The plan's original assertion `editedContourPointCount > 0` is a mount check, not a change check. `editedRingPts.length` is invariant under `op:'move'` (same vertex count, different coords). This would pass even if the overlay were frozen — the exact false-green pattern the plan forbids.
- **Fix:** Added `editedRingSnapshot = JSON.stringify(editedRingPtsRef.current)` to `__forgeBezierState`; Playwright asserts `snapshotAfter !== snapshotBefore` (geometry changed) in addition to `count > 0` (overlay mounted). The load-bearing assertion is the snapshot diff.
- **Files modified:** `BezierEditLayer.tsx`, `08.1-bezier-render-feedback.spec.ts`
- **Commit:** `53dc9ab` (implementation), `ee22de9` (spec)
