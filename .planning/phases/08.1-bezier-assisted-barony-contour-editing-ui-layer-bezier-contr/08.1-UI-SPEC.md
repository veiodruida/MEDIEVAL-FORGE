#### Shape rationale (CONTEXT.md "visually DISTINCT")

Anchors are **squares (Rect 10×10)** — structurally distinct from the raw vertex handles (circles radius 5) used in Phase 08 for landmask mode. Control handles are **smaller circles (radius 4)** — same family as raw handles but clearly subordinate by size. The combination of square+blue (anchor inactive), square+gold (anchor active), and small-circle+slate (handle) creates three unambiguous visual roles with zero risk of confusion.

## Interaction Contract — Bézier Overlay

This section extends Phase 08 §Vertex Edit Mode. It does not replace it. Landmask mode (editableLayer='landmask') continues to use VertexEditLayer with raw handles.

### Scope

`BezierEditLayer` is active **only when**:
- `useEditorStore.editableLayer === 'baronies'` — AND
- `useEditorStore.activeTerritoryId !== null` — AND
- `activeTool === 'V'` (the Select tool; Bézier is V-tool behavior, not a new tool)

### Edit-mode entry (barony selected)

1. `SelectionBridge` fires as today — loads `useEditorStore.vertices` via `temporal.pause/setState/resume`. **No change to this path.**
2. `BezierEditLayer` mounts (or receives new `activeTerritoryId` prop) and reads `useEditorStore.vertices` synchronously.
3. Builds `BezierDisplayState` in component-local `useState`/`useRef`:
   - Convert polygon coords to canvas-px (projection from `useProjection()`).
   - Call `fitPolygonToBezier(coords, error=30)` → array of cubic segments.
   - Call `buildPolyIndexMap(inputPts, cubics)` → `{ rangeStart, rangeEnd }[]` per segment.
   - Derive `BezierAnchor[]` array from segment endpoints.
4. **`useEditorStore.vertices` is NOT written. `editLog` is NOT written.** This is the identity-invariant enforcement point.

### Anchor interaction

**Click anchor** (no drag):
- Sets `activeAnchorIdx` in component `useState` to this anchor's index.
- Shows cp1/cp2 handles + tether lines for this anchor only.
- Previous active anchor reverts to inactive (no handles).

**Click canvas background**:
- Clears `activeAnchorIdx` (null) — all handles hidden, all anchors become inactive blue squares.

**Drag anchor** (V-tool active):
1. `onDragMove`: update anchor position in local state only (`previewRef.current` pattern); repaint curve outline via `Konva.Path data` update + live-preview `Konva.Shape sceneFunc` for the dragged segment only. No store write.
2. Snap applies via `snapToNeighbour()` from `lib/snap.ts` — same as Phase 08 anchor-drag path.
3. `onDragEnd` (commit):
   - Mark `dirtySegments`: add both `anchorIdx - 1` and `anchorIdx` (the two adjacent segments), with boundary guards (`i=0` wraps to `length-1`; closing segment is non-editable so boundary `i=N-1` only marks `N-2`).
   - For each dirty segment: call `flattenSegment(cubic, targetCount, projection)` to produce `[lon, lat][]`.
   - Build `nextVertices` replacing only the index ranges covered by dirty segments. Non-dirty ranges: copy verbatim from `useEditorStore.getState().vertices` — no float recomputation.
   - Call `useEditorStore.getState().setVerticesAndLog(nextVertices, { op: 'move', ts: Date.now() })`.
   - Clear `dirtySegments`.
4. After commit: recompute `BezierDisplayState` from the updated store vertices to keep display consistent.

**Shared-vertex coupling (TOPO-04)**:
- Before writing `nextVertices`, call `getCoupledVertices(changedVertexIds, sharedIndexRef)`.
- If coupled vertices found in neighbour baronies: include them in `nextVertices` and pass all to `setVerticesAndLog`. Identical behavior to Phase 08 `handleDragEnd` in `VertexEditLayer.tsx`.

### Control-handle interaction

**Drag cp1 or cp2** (only shown for active anchor):
1. Update handle position in local state only — no snap (handles are aesthetic).
2. Repaint live-preview segment.
3. `onDragEnd`: mark the adjacent segment(s) dirty and commit via the same flatten path as anchor drag.
4. Smooth-anchor constraint (mirror cp1/cp2) is **NOT** implemented in V1. Handles are independent (cusp behavior). Deferred to follow-on.

### Edit-mode exit

1. If `dirtySegments` is empty → `useEditorStore.vertices` was never written → byte-identical to pre-entry. Identity invariant satisfied.
2. Clear `BezierDisplayState` (anchors, handles, curve path).
3. Mid-edit barony switch (user clicks a different barony): `BezierEditLayer` receives new `activeTerritoryId` → `useEffect` cleanup clears all local state. The store already holds the last committed flatten (or pre-entry vertices if no drag occurred).

### A and D tools in Bézier mode

When `BezierEditLayer` is mounted (barony selected, V-tool active):
- The **A tool** (Add Vertex) is rendered as `disabled` in `EditToolPalette` via a prop/context signal.
- The **D tool** (Delete Vertex) is rendered as `disabled` in `EditToolPalette` via the same signal.
- Clicking either disabled button produces no state change.
- Tooltip copy: see Copywriting section above.
- **This is not handled inside EditToolPalette itself** — EditToolPalette remains unaware of Bézier mode. The signal is passed as a prop (`disabledTools?: EditTool[]`) by the parent that mounts BezierEditLayer. Planner determines the exact prop-threading path.

### Closing segment (V1 known limitation)

The ring closure segment (between anchor `N-1` and anchor `0`) has no fit-curve cubic. It is rendered as a straight line segment in the curve outline path (implicitly — the `M … C …` path string ends at anchor `N-1`; the visual gap at the closure is acceptable). No interaction is possible on this segment in V1. No user-facing message is shown; the visual gap is the signal.

### Keyboard shortcuts (no changes from Phase 08)

All shortcuts from Phase 08 §Keyboard Shortcuts Summary apply unchanged. Ctrl+Z undoes the last `setVerticesAndLog` call (i.e., the last committed flatten), not individual handle movements. This is correct — intermediate handle positions are not undo-able.

## Konva Layer Stack (Phase 08.1 update)

```
z=0 BackgroundLayer    — terrain PNG / stage raster
z=1 TerritoryLayer     — condado polygons (read-only selection)
z=2 BaronyLayer        — barony polygons
z=3 DecorationsLayer   — capitals + labels
z=4 InteractionLayer   — gold selection outlines (listening=false)
z=5 VertexEditLayer    — raw vertex handles (landmask mode + non-barony tiers) [Phase 08]
z=5 BezierEditLayer    — Bézier anchors/handles/curve overlay [Phase 08.1, conditional]
```

**Mount rule at z=5:** `VertexEditLayer` and `BezierEditLayer` are mutually exclusive at z=5:
- `editableLayer === 'landmask'` → `VertexEditLayer` mounted, `BezierEditLayer` unmounted.
- `editableLayer === 'baronies'` + `activeTerritoryId !== null` → `BezierEditLayer` mounted, `VertexEditLayer` unmounted for the barony-handle section (landmask handles section of VertexEditLayer still inactive — it requires editableLayer='landmask').

The planner determines the exact conditional render in `CanvasViewer.tsx`. The executor must not mount both simultaneously.

## Notes for Executor

1. **Bézier state lives ONLY in `BezierEditLayer` component-local state (useRef/useState).** Do NOT add any field to `useEditorStore`. Do NOT add `'bezier_drag'` to `EditOp.op` union. The store receives only `op: 'move'` entries from flatten commits.

2. **Identity invariant is the single non-negotiable.** `setVerticesAndLog` must never be called on edit-mode entry or exit without a drag commit. Test BEZ-IDENTITY-01 must pass before drag-commit code is written. This is the frontend port of the Phase 08 `test_empty_edit_log_preserves_lookup_barony_png` parity test.

3. **`fit-curve` fits in canvas-pixel space, not geo-coordinate space.** Convert polygon coords to canvas-px via `geoToCanvas(lon, lat, projection)` before calling `fitCurve`. Convert back to `[lon, lat]` via `canvasToGeo(x, y, projection)` only at flatten commit time. This is non-negotiable — error tolerance is in px units.

4. **`buildPolyIndexMap` is a Wave 0 deliverable, not optional.** Without it, dirty-segment flatten cannot know which original polygon vertex indices to replace. Build it as a standalone pure function with its own unit test before writing any flatten code.

5. **Mark BOTH adjacent segments dirty on anchor drag.** Dragging anchor `i` affects segment `i-1` (ends at anchor `i`) AND segment `i` (starts at anchor `i`). Single-segment marking leaves a visible discontinuity. The closing-segment non-editability (V1 limitation) means `i=N-1` only marks `N-2` (not `N-1`).

6. **Do NOT add a new tool to EditToolPalette.** Bézier editing is the V-tool behavior when a barony is selected. CONTEXT.md locked this. Any PR adding a new tool entry must be rejected.

7. **A and D tools must be visibly disabled (not silently no-op) in Bézier mode.** Use Radix `disabled` prop on the `IconButton`. Pass disabled state via `disabledTools` prop from the parent that knows Bézier mode is active. Do not add Bézier-mode awareness inside `EditToolPalette.tsx` itself.

8. **Smooth-anchor (mirrored handles) is explicitly OUT OF SCOPE for V1.** Control handles cp1 and cp2 are independent (cusp behavior). Do not implement handle mirroring. RESEARCH Open Q3 deferred this.

9. **Konva Path vs Shape for live drag preview.** Start with `Konva.Shape sceneFunc ctx.bezierCurveTo` for the single dragged segment (avoids SVG string re-parse on each `onDragMove` at 60fps). The non-dragged segments use a single static `Konva.Path data` string recomputed only on commit.

10. **Phase 08 parity tests must stay green.** Backend, export, parity harness are unchanged. Run `pytest tests/parity/` before any push. This phase produces zero backend commits.
