# Phase 08.1: Bézier-assisted barony contour editing — Context

**Gathered:** 2026-05-28
**Status:** Ready for planning (research required)
**Source:** Live UAT of Phase 08 editor — user found raw per-vertex handles unusable (hundreds of dots per smoothed Voronoi barony). User chose Bézier control-point editing over RDP simplification.

<domain>
## Phase Boundary

Replace the raw "every polygon vertex = a draggable handle" editing model (Phase 08, `VertexEditLayer.tsx:404-415` renders all viewport vertices with zero decimation) with a Bézier-assisted control-point model that shows a small number of organized anchors + curve handles instead of hundreds of raw dots.

**In scope:** UI/editor layer only — the visual representation, the curve-fit on edit-mode entry, the drag interaction on anchors/control handles, and the flatten-back-to-polygon of edited segments.

**Out of scope:** Backend, DAG, `/editor/apply`, the `manual_edit` stage, export schema, parity tests. NONE of them ever see Bézier. The 12-file raster export contract (lookup PNGs, NEAREST upscale, SSIM/byte parity) is unchanged.
</domain>

<decisions>
## Implementation Decisions (LOCKED)

### Parity-safe architecture (NON-NEGOTIABLE — derived from D-17 + CLAUDE.md)
- **Bézier exists ONLY in the editor UI layer.** The Zustand store (`useEditorStore.vertices`) keeps polygon vertices exactly as today. Backend/DAG/`manual_edit`/`/editor/apply` never receive Bézier data.
- **Anchors + control handles are DERIVED** (curve-fit) from the polygon for display — never the source of truth.
- **On drag, only the AFFECTED segments flatten back to polygon points;** unedited segments keep their original vertices verbatim.
- **Empty edit_log → polygon untouched → byte-equal output.** Entering and exiting edit mode with zero drags MUST leave `useEditorStore.vertices` byte-identical to pre-entry. This is the frontend port of the 08-07c empty-log identity parity test and is the single must_have that proves the design didn't silently rewrite geometry.

### Curve model
- Fit cubic Béziers to the existing polygon ring (curve-fitting), producing few anchors (~10-20 for a typical barony) + 2 control handles per anchor.
- Flatten resolution must match the polygon density produced by σ=3.0 smoothing so re-flattened segments don't visibly coarsen the contour or perturb the raster.

### Interaction
- Reuse the existing EditToolPalette (Phase 08, 08-13) — Bézier editing is the new behavior of the Select/move tool, not a separate tool unless research shows otherwise.
- Keep barony-tier-only guard (D-03) and the SelectionBridge wiring (08-12).

### Claude's Discretion
- Exact curve-fitting library (research: `fit-curve` is the obvious candidate — ~300 lines, no deps) vs hand-rolled Schneider fit.
- Visual style of anchors vs control handles (distinct shapes/colors).
- Whether control handles are always shown or only for the selected anchor (advisor noted ~N anchors + 2N handles can still be many — consider showing control handles only for the active anchor).
</decisions>
