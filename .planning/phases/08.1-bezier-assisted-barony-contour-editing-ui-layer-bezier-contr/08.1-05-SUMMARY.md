# Phase 08.1 Plan 05: G1/G2/G4 Gap Closure Summary

One-liner: Closed Bezier ring (G1), editable closing-segment handle commits (G2), and visually distinct 5-color palette (G4) — with WR-02 clamp, WR-03 flatten hardening, and Playwright re-verification of G1+G2 end-to-end.

## What Was Done

### Task 1 — Close the ring (G1)

**Problem:** `buildPathData` looped `i=0..N-2`, emitting only N-1 cubic commands. The closing segment (anchor[N-1] → anchor[0]) was never rendered, leaving the outline open.

**Fix:**
- `buildPathData`: Added a closing segment cubic after the loop — now emits N cubic `C` commands (not N-1), returning to anchor[0]. The outline forms a fully closed ring.
- `deriveAnchors`: Anchor[0]'s `cp1Px` now comes from `cubics[N-1][2]` (c2 of the last cubic), connecting the incoming handle of anchor 0 to the closing segment.
- `addSeg` guard: Relaxed from `s < N-1` to `s < N` — all N segments are now editable including the closing segment N-1. The stale comment "non-editable closing segment" was removed.
- Flatten loop: Changed `working[s+1]` to `working[(s+1) % N]` so the closing segment uses anchor[0] as its endpoint.
- `bezierFit.ts`: Updated the forced-last-index comment (line 85-87) to explain that `k = M-1` covers the closing-duplicate vertex, preventing a forward-scan regression where vertex M-1 would be left without a range owner.

**Ring model decision:** Kept `anchor count == cubic count`. The closing segment runs from anchor[N-1] back to anchor[0] using the last cubic as its geometry. No orphan anchor for the duplicate point.

### Task 2 — Commit closing-segment drags (G2) + WR-02 + WR-03 + Playwright

**G2 (closing-segment commit):**
- `handleDragEnd`: Changed dirty routing to use `incomingSeg = (idx-1+N)%N`. For anchor 0: `incomingSeg = N-1` (the closing segment), not -1. This routes cp1-on-anchor-0 drags into the dirty set instead of falling to the empty-dirty early-return.
- Anchor drag: Now marks BOTH `incomingSeg` (incoming segment) AND `idx` (outgoing segment), so dragging anchor 0 affects both segments 0 and N-1.
- The early-return at line 426 (changedIds.length === 0) is now only reachable in genuinely degenerate cases; the closing-segment dead zone is eliminated.

**WR-02 (activeAnchorIdx clamp):**
- After `setAnchors(refit)`, added `setActiveAnchorIdx((cur) => (cur === null ? null : Math.min(cur, refit.length - 1)))` to prevent a stale index from pointing past the new array after a commit-refit that yields fewer cubics.

**WR-03 (flattenSegment hardening):**
- Added degenerate guard in `flattenSegment`: when `targetCount < 2`, returns `[canvasToGeo(p0), canvasToGeo(p3)]` (2 points) instead of a single t=0 sample or empty array. The even-spacing loop for targetCount >= 2 is unchanged.

**New DEV hook `__forgeBezierTriggerHandleDrag`:**
- Added alongside `__forgeBezierTriggerDrag` inside the same DEV-gated `useEffect`.
- Signature: `(kind: 'cp1'|'cp2', idx: number, dx?: number, dy?: number) => boolean`
- Critical: control handles are center-anchored Circles — NO `-5` offset (unlike anchor Rects). Uses `cp1Px[0] + dx` directly.
- Calls the real `handleDragMove(kind, idx, evt)` then `handleDragEnd(kind, idx, evt)`. Never writes the store directly.
- Torn down in the existing unmount cleanup.

**Playwright G1+G2 re-verification:**
- New test in `08.1-bezier-edit.spec.ts`: selects a real barony, reads editLogLength baseline, triggers `__forgeBezierTriggerHandleDrag('cp1', 0, 25, 25)`, polls until editLogLength grows. This re-verifies G1+G2 in the running app (RESEARCH Pitfall 5 / CLAUDE.md UI-UAT mandate).

**Existing drag tests updated:**
- `boundary i=0` test: updated to reflect G2 behavior (anchor 0 now marks both segment 0 and closing segment N-1 dirty). Old assertion that "closing segment stays verbatim" removed.
- `boundary i=N-1` test: updated to reflect that last anchor also marks closing segment N-1 dirty.

### Task 3 — Distinct color palette (G4)

**Problem:** `CURVE_STROKE = '#4a9eff'` was identical to `ANCHOR_INACTIVE_FILL = '#4a9eff'` — the outline was visually indistinguishable from inactive anchors. `HANDLE_FILL = '#94a3b8'` was identical to `TETHER_STROKE = '#94a3b8'` — handles were indistinguishable from tethers.

**Fix:**
- `CURVE_STROKE`: `#4a9eff` → `#22c55e` (green) — distinct from blue inactive anchors
- `HANDLE_FILL`: `#94a3b8` → `#e879f9` (magenta) — distinct from slate-gray tethers
- All other constants unchanged: `ANCHOR_INACTIVE_FILL=#4a9eff` (blue), `ANCHOR_ACTIVE_FILL=#f0c040` (amber), `ANCHOR_HOVER_FILL=#ffffff` (white), `TETHER_STROKE=#94a3b8` (slate-gray)
- 5 visually distinct hexes, no collision between any pair.
- `08.1-UI-SPEC.md` color table updated.
- Header comment in `BezierEditLayer.tsx` updated.
