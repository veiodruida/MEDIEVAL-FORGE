## Decisions Made

### Coordinate Conversion (Critical — Advisor-Identified)

The plan (§RESEARCH §785-824) instructed using `geo_to_pixel` directly in `replay_vertex_ring`. The advisor identified this as a critical error before implementation:

- `geo_to_pixel` (contracts.py:185) uses `int()` truncation → ~34px drift per barony ring.
- `from_bounds(0,0,W,H,W,H)` uses rasterio world y (0=bottom, y grows UP), not pixel row index.
- The A1 contract (Wave 0) explicitly proved: `round() + H-flip → 0 diff pixels`, `int() + H-flip → 34 diff pixels`.

**Fix applied (Rule 1 — Bug):** `_lonlat_to_rasterio_xy` internal helper implemented in `manual_edit.py`, matching the `_lonlat_to_rasterio_xy` test helper from Wave 0 exactly. `geo_to_pixel` is parity-frozen and was NOT modified.

### buffer(0) for Non-Convex Rings (Rule 1 — Bug)

The plan specified `if poly.is_valid and not poly.is_empty` as the guard before replacing `polygons_by_id`. This rejected valid-after-heal polygons:

- `test_add_op_grows_barony_ring` uses a 5-point ring where B#4 creates a concave shape. Shapely reports `is_valid=False` (self-intersection), `area=0.0` for the raw Polygon.
- `buffer(0)` is the canonical Shapely fix for self-intersecting rings. After healing: `is_valid=True`, `area > 0`, and the polygon is correctly accepted.

**Fix applied (Rule 1 — Bug):** `buffer(0)` called when `not poly.is_valid`; guard changed to `not poly.is_empty and poly.area > 0`.

### _geometry_modified Short-Circuit (Rule 2 — Missing Critical Functionality)

The plan's Pitfall 4 guard (`vertex_ops_present`) prevents ring re-rasterisation for landmask-only branches. However, without a short-circuit, the rasterise-back step (step 3) still executes for landmask-only branches (where the loop ran with zero mutations). For rectangular test baronies this is byte-identical, but for complex real shapes the round-trip may introduce sub-pixel drift.

**Fix applied (Rule 2):** `_geometry_modified` flag tracks whether any op (split/merge/translate/vertex) mutated `polygons_by_id`. If `False` after the loop + ring block, returns `input_array` directly. This makes `test_landmask_only_branch_with_nonempty_hash_returns_byte_identical` robustly pass regardless of raster complexity.

### Mock-DB Harness Design

The three `test_render_producer_loader_injection.py` tests needed a real mock-DB harness exercising the production `_render_producer` fetch block. Strategy chosen: `_run_phase_082_fetch_block` async helper imports `AsyncSessionLocal`, `Branch`, `Snapshot`, `_snapshot_deserialize` from `render.py`'s real namespace; `unittest.mock.patch` replaces `AsyncSessionLocal` with a mock context manager. This exercises the production code path without spinning up FastAPI + real DB.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] replay_vertex_ring must NOT use geo_to_pixel**
- **Found during:** Task 1, pre-implementation advisor review
- **Issue:** Plan §RESEARCH §785-824 showed `pixel_coords = [geo_to_pixel(vertices_dict[k]['lon'], vertices_dict[k]['lat'], cfg) for k in ring_keys]`. geo_to_pixel uses int() truncation → ~34px drift; also returns (px_col, py_row) in pixel-row space, not rasterio world y. Polygon built from these coords would be vertically incorrect.
- **Fix:** `_lonlat_to_rasterio_xy(lon, lat, cfg, W, H)` helper added to `manual_edit.py` using `round()` + `rasterio_y = H - py_row`. Identical to `_lonlat_to_rasterio_xy` in the Wave 0 test file, which the A1 gate already proved byte-exact.
- **Files modified:** `backend/medieval_forge/services/pipeline/manual_edit.py`
- **Commit:** 1214846

**2. [Rule 1 - Bug] poly.is_valid guard rejects healable rings from add/delete ops**
- **Found during:** Task 1, test run (test_add_op_grows_barony_ring FAILED)
- **Issue:** A 5-point ring with a concave vertex produces `poly.is_valid=False` and `poly.area=0.0` in Shapely. The plan's `if poly.is_valid and not poly.is_empty` guard silently skipped the polygon, leaving `polygons_by_id[5]` with the original geometry → byte-identical output → assert failed.
- **Fix:** `buffer(0)` applied when `not poly.is_valid` before the guard; guard changed to `not poly.is_empty and poly.area > 0`. buffer(0) is the canonical Shapely self-intersection fixer.
- **Files modified:** `backend/medieval_forge/services/pipeline/manual_edit.py`
- **Commit:** 1214846

**3. [Rule 2 - Enhancement] _geometry_modified short-circuit for BEZ-CONV-04**
- **Found during:** Task 1, analysis of Pitfall 4 robustness
- **Issue:** Plan's vertex_ops_present guard only prevents ring re-rasterisation. The rasterise-back step (step 3) still fires for landmask-only branches, relying on rasterio round-trip fidelity for arbitrary raster shapes. For the test (rectangular baronias), this passes. For production Iberia staircase shapes without the round() helper path, sub-pixel drift is possible.
- **Fix:** `_geometry_modified = False` flag; set to True in each op branch and after ring re-rasterisation block; `if not _geometry_modified: return input_array` short-circuit before step 3.
- **Files modified:** `backend/medieval_forge/services/pipeline/manual_edit.py`
- **Commit:** 1214846
