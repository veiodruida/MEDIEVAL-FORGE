<domain>
## Phase Boundary

Close G8: make barony contour edits (`move`/`add`/`delete`) **converge** from the branch
edit-log all the way to the colored `BaronyLayer` on the canvas AND the 12-file Unity export.

**Root cause (two missing wires):**
1. `backend/medieval_forge/services/pipeline/manual_edit.py:128` — the `compute()` replay loop
   handles `split`/`merge`/`translate` only; `move`/`add`/`delete` were deferred in Phase 08
   and silently fall through (no-op).
2. The render pipeline only feeds `landmask_replace` edits into a render cascade (roadmap cites
   `render.py:148-167`); barony vertex-ops have no convergence trigger, so even a manual re-render
   does not surface them.

**In scope:**
- Barony `move`/`add`/`delete` replay in `manual_edit.compute()` (BEZ-CONV-01, BEZ-CONV-02).
- A render-cascade trigger after a Bézier commit + frontend `baroniesQ` refetch so the colored
  map updates (BEZ-CONV-03).
- Iberia 10/10 byte/SSIM parity stays green on the zero-edit path (BEZ-CONV-04).
- UAT: real-mouse Bézier edit → colored boundary changes + survives reload + appears in export
  (BEZ-CONV-05).

**Out of scope (deferred / unchanged):**
- The 08.1 Bézier editor UI itself (curve-fit, anchors, drag) — already shipped, unchanged.
- New editor capabilities, new tiers, condado-direct editing.
- Selective per-barony incremental render (Phase 08 D-21 keeps full re-render).
- 3-way branch merge, touch support, the rest of Phase 08's deferred list.

</domain>

<decisions>
## Implementation Decisions

### Convergence trigger + cost (the one area discussed)

- **D-01 (Two-mode trigger — mirror Phase 08 D-05):** Convergence is triggered two ways,
  user picks per session, exactly like the landmask two-mode pattern:
  - **Manual mode (DEFAULT):** edits buffer; an explicit **"Apply edits"** button flushes a
    single render cascade. Batches many drags → one ~3-5s cascade. Recommended for big edits.
  - **Auto-immediate mode (toggle):** every committed edit triggers the full cascade
    automatically. Honest live convergence, slow (~3-5s/edit). For final fine-tuning.
  - The toggle lives in the editor header, consistent with D-05's "Apply landmask" toggle.
- **D-02 (Reuse Phase 04.1 render UX):** Convergence runs through the SAME cancellable `/render`
  path the parameter studio uses — progress state, **Cancelar** button, `RENDER_BUSY` bounded-retry
  guard, and **`baroniesQ` auto-refetch on success** (this is the frontend half of BEZ-CONV-03).
  No bespoke render plumbing. The spacebar before/after preview (04.1) carries over for free.
- **D-03 (Cascade scope = Phase 08 D-17/D-21):** The cascade re-runs
  `manual_edit → hierarchy → render → lookup → metadata` over the edited geometry. Full
  re-render (~3-5s), NO selective-barony render. Upstream stages
  (`landmask → border → voronoi → cleanup → smooth → merge`) stay cached unless the landmask was
  also edited — so the zero-edit path is byte-untouched (BEZ-CONV-04).

### Backend replay semantics

- **D-04 (Close the line-128 gap):** `manual_edit.compute()` gains `move`/`add`/`delete` replay
  so the edited contour reaches the rasterised `BaronyLayer` and the 12-file export — not just
  the 08.1 live overlay (BEZ-CONV-01, BEZ-CONV-02). Add/delete replay must work regardless of
  which editor produced the op (Phase 08 raw `VertexEditLayer` emits add/delete; the 08.1 Bézier
  insert-anchor is a NO-OP that commits via `op:'move'` on drag).
- **D-05 (Parity-safe by construction):** Vertex-op replay fires ONLY when the active branch has
  barony edit-events. The empty-log identity path (`manual_edit_log_hash == ""`) stays the exact
  byte-equal pass-through from Phase 08 D-17 / Plan 08-07c. This is the single must-have that
  proves convergence did not silently rewrite the zero-edit pipeline (BEZ-CONV-04).

### Claude's Discretion (defaults recorded so the planner does NOT silently drop them)

- **Live overlay lifecycle:** The 08.1 amber-dashed live overlay should **clear once the colored
  barony re-renders to match** (avoid a doubled / ghost contour). Default = clear-on-converge;
  UI-phase / planner may refine the exact transition.
- **Undo after converge:** `Ctrl+Z` reverts `useEditorStore` geometry only (zundo is editor-scoped,
  Phase 08 D-25). The colored map stays as last-rendered until the next Apply / cascade — there is
  **no automatic re-cascade-back on undo**. To revert the colored map, the user re-Applies. (zundo
  has no post-render precedent; this keeps the editor history and the render cache decoupled.)
- **"Apply edits" button styling/placement + auto-immediate toggle label copy** — UI-phase /
  planner discretion, consistent with the Phase 03 Mapbox-style shell and the D-05 toggle.

</decisions>

<research_targets>
## Research Targets (for `/gsd-plan-phase 08.2 --research`)

1. **Replay geometry source (THE CRUX — highest priority).** `op:'move'` carries
   `{ vertexIds, lat, lon }` in **geographic** coords, but `compute()` re-vectorises the int16
   raster into **pixel-space** polygons via `from_bounds(0,0,W,H,W,H)` — with NO stable vertexIds
   matching the store. Determine the replay source of truth: almost certainly **rasterise the edited
   GeoJSON ring per barony** (the store / sidecar ring already holds the moved + coupled vertices)
   rather than re-vectorise pixels and remap IDs. Resolve the lat/lon → raster coordinate transform
   and which baronies must be re-rasterised.
2. **Render-feed wiring.** Pin the exact `landmask_replace → render` cascade (`render.py:148-167`)
   and decide whether barony convergence mirrors it, or whether `render` already reads `manual_edit`
   output so only the *trigger* (Apply / auto-immediate) is missing.
3. **Shared-boundary / gap consequence.** Phase 08 D-30 couples shared vertices. If replay
   rasterises the coupled store rings, shared edges stay together and no ocean-sentinel gap opens by
   construction — verify empirically on a real Iberia barony move; reconcile with editor D-26 block.
4. **add/delete emission scope.** Confirm which editor emits `add`/`delete` ops and their payload
   shape, so replay handles them regardless of producer (BEZ-CONV-02).
5. **Frontend trigger wiring.** How "Apply edits" + the auto-immediate toggle hook into
   `useParameterStudioDispatch` / `WorkspaceToolbar`, and where `baroniesQ.refetch()` fires on
   cascade success.

</research_targets>

## Specific Ideas

- The two-mode trigger (D-01) was the user's explicit choice to **mirror the Phase 08 D-05 landmask
  pattern** rather than invent a new convergence UX — consistency over novelty.
- Convergence reuses the Phase 04.1 cancellable render path (D-02) rather than a bespoke pipeline —
  the hard cancel/race/RENDER_BUSY work is already paid for.

<deferred>
## Deferred Ideas

- **Automatic re-cascade-back on undo** — `Ctrl+Z` reverts the store only (D-03 Claude's Discretion);
  re-rendering the colored map on every undo is out of scope and would couple zundo history to the
  render cache. Re-Apply is the explicit path.
- **Selective per-barony incremental render** — Phase 08 D-21 keeps full re-render; optimise later
  only if measured-slow.
- **Live overlay during the auto-immediate cascade** — the overlay clears on converge (D-03); a
  fancier in-flight transition is a later UI polish item, not a convergence requirement.

</deferred>
