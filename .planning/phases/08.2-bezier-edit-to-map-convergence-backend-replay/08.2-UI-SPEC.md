### New badge color (cost warning)

| Element | Radix Token | Copy | Trigger |
|---------|-------------|------|---------|
| Auto-immediate cost badge | `color="orange" variant="soft"` | "Modo auto: ~3-5s por edição" | Shown only when auto-immediate switch is ON |

> The cost string is ~3-5s (not ~10s from the landmask badge) — barony cascade
> re-runs manual_edit → hierarchy → render → lookup → metadata, which is faster
> than the full landmask cascade (D-03). Do not copy the landmask badge string verbatim.

### Overlay-clear-on-converge (Konva — no color change required)

The 08.1 amber-dashed live overlay (`#f0c040` stroke, dash `[6,4]`, fill `rgba(240,192,64,0.12)`)
does NOT need a new color or visual state for the "converged" condition.

After a successful Apply cascade, the colored BaronyLayer raster updates to match the edited
contour. The overlay renders the same geometry as the new raster, so they visually coincide.
The overlay then fades to zero perceptual contrast against the updated colored barony — it
does not need an explicit hide or animation. It clears naturally when the user deselects the
barony (`activeTerritoryId` → null) or exits Bézier mode.

**Mechanism (executor detail):** After render success, call:
```
temporal.pause()
useEditorStore.setState({ editLog: [] })
temporal.resume()
```
This clears `editLog` (which gates the Apply button's `disabled` state), NOT the overlay.
The overlay's visibility is gated on `isActive && anchors.length > 0` — it stays rendered
until the user deselects. This is intentional: the overlay confirming the edit shape while
the colored raster catches up is a positive affordance, not a ghost.

## Toolbar Layout (Phase 08.2 addition to Phase 08)

The existing 48px `WorkspaceToolbar` gains one new control group between `EditToolPalette`
and Undo/Redo. Full right-zone layout after this phase:

```
[BranchPicker ▼] [EditToolPalette] | [AUTO SWITCH] [Aplicar edições ▼] | [↩] [↪] [Regenerar] [Exportar ZIP]
                                       ↑ new in 08.2 ↑
```

### Apply Edits Control Group

**Placement:** In the right-zone `Flex align="center" gap="2"`, inserted between `EditToolPalette`
and the Undo/Redo buttons.

**Conditional visibility:** The entire control group is rendered only when:
- `editableLayer === 'baronies'` AND
- `activeTerritoryId !== null` AND
- `activeTool === 'V'`

(Same predicate as Bézier mode, derived from the same store values already read by WorkspaceToolbar.)
The mode switch is visible even when `editLog.length === 0` — user must be able to pre-select
auto mode before making edits. The Apply button is enabled only when `editLog.length > 0`.

### Mode Toggle

The mode control is a Radix `Switch` with a `Text` label — NOT a RadioGroup (CONTEXT D-01 mirrors
D-05 semantics, but the toolbar is a horizontal 48px bar; a vertical RadioGroup does not fit).

**Rationale:** The D-05 landmask control uses `RadioGroup` in a sidebar card with vertical space.
Toolbar constraints require a more compact widget. A `Switch` labeled "Auto-aplicar" conveys the
same two-mode semantics (OFF = manual, ON = auto-immediate) with one element instead of two stacked
radio items. The semantic equivalence is preserved; the widget form adapts to the layout constraint.

```
<Flex align="center" gap="2">
  <Switch
    data-testid="bezier-apply-auto-switch"
    checked={bezierApplyMode === 'auto-immediate'}
    onCheckedChange={(v) => setBezierApplyMode(v ? 'auto-immediate' : 'manual')}
    size="1"
  />
  <Text size="1" color="gray">Auto-aplicar</Text>
</Flex>
```

- Default: OFF (manual mode), switch unchecked — CONTEXT D-01 locks manual as default.
- When ON: orange Badge "Modo auto: ~3-5s por edição" rendered inline, immediately after
  the switch, before the Apply button placeholder zone.

### Apply Button

Rendered only in manual mode (switch OFF). Enabled only when `editLog.length > 0`.

```jsx
{bezierApplyMode === 'manual' && (
  <Button
    variant="outline"
    color="blue"
    disabled={editLog.length === 0 || isRunning}
    onClick={handleApplyEdits}
    data-testid="bezier-apply-edits-btn"
  >
    Aplicar edições
  </Button>
)}
```

- `variant="outline"` — secondary action, parallels "Aplicar landmask" (D-05 discretion call
  from Phase 08 UI-SPEC §Landmask Editor Layer Header).
- `color="blue"` — consistent with the landmask Apply button.
- `disabled` when no pending edits (`editLog.length === 0`) or render already in progress
  (`isRunning = runState === 'generating' || runState === 'rendering' || runState === 'ingesting'`).

### In-Flight State (during Apply cascade)

The Apply cascade reuses the Phase 04.1 render UX exactly (D-02). No new progress UI is needed:

- The existing `GenerateStatusBadge` (center toolbar) shows rendering progress as today.
- The existing `showCancel = runState === 'rendering'` gate replaces the badge with the red
  "Cancelar" button as today.
- `isRunning` disables the Apply button and the Gerar Mapa button simultaneously — no collision.

**There is no new spinner, no new progress bar, no new cancel UI for Apply edits.** The entire
in-flight state is inherited from the existing rendering-state machine (RunState).

### Undo-after-converge behavior (executor note, not user-facing copy)

Ctrl+Z reverts `useEditorStore` geometry only (zundo is editor-scoped, Phase 08 D-25).

is sufficient. Executor must not add a "map not reverted" toast.

## Interaction Contract

### Manual mode (default)

1. User drags anchors or control handles in BezierEditLayer — commits via `op: 'move'`.
2. `editLog` grows; Apply button becomes enabled.
3. User clicks "Aplicar edições":
   a. Frontend posts snapshot with `{ ..., vertices, edit_log, barony_name_to_idx }` payload.
   b. Frontend calls `postRender(projectId, {}, stageView)` directly (bypasses diffOverrides check).
   c. `useRunStore.startRender(run_id)` — existing rendering-state machine kicks in.
   d. GenerateStatusBadge shows rendering progress; Cancelar shows if user wants to abort.
4. On render success (project `updated_at` bumped by backend):
   a. Parent component refetches `project` → new `cacheVersion` propagates to `useCanvasArtifacts`.
   b. All 5 canvas queries (including `baroniesQ`) refetch — BaronyLayer updates with new raster.
   c. `temporal.pause(); useEditorStore.setState({ editLog: [] }); temporal.resume()` — Apply button
      returns to disabled state.
5. The amber-dashed overlay remains visible (user still has barony selected, Bézier mode still active).
   The overlay now shows the same geometry as the freshly-rendered colored raster — they coincide.
   No explicit overlay dismiss is triggered.

### Auto-immediate mode

1. User toggles the Auto-aplicar switch ON — orange cost badge appears.
2. User drags anchor and commits via `op: 'move'`.
3. After `setVerticesAndLog`:
   a. Frontend posts a fresh inline snapshot (with current `vertices`) immediately — does NOT rely
      on the 25-edit auto-snapshot cadence.
   b. Frontend calls `postRender(projectId, {}, stageView)` directly.
   c. Existing rendering-state machine handles progress + cancel.
4. Subsequent edits are queued or cancelled per the existing RENDER_BUSY bounded-retry logic
   (3 retries / 1.5s window, Phase 04.1).
5. After each render success: same as step 4 of manual mode above.

### Visibility and enable state matrix

| Condition | Mode Switch | Apply Button | Badge |
|-----------|-------------|--------------|-------|
| Bézier mode inactive (no barony selected, or not V-tool) | Hidden | Hidden | Hidden |
| Bézier mode active, manual, editLog empty | Visible, OFF | Visible, disabled | Hidden |
| Bézier mode active, manual, editLog non-empty | Visible, OFF | Visible, enabled | Hidden |
| Bézier mode active, auto-immediate, any editLog | Visible, ON | Hidden | Visible |
| Any mode, rendering in progress | Visible | Disabled | Visible if auto mode |

## Notes for Executor

1. **D-01: Mirror D-05 semantics, not widget.** The Apply button + mode control mirrors the
   Phase 08 D-05 landmask pattern semantically (manual default, auto-immediate toggle, outline Apply,
   orange cost badge) but uses a `Switch` instead of a `RadioGroup` because the toolbar has no vertical
   space for stacked radio items. The spec source for this decision is §Toolbar Layout above.

2. **Do NOT call `dispatch.flush()` or `dispatch()` from `useParameterStudioDispatch` for Apply edits.**
   The hook's `diffOverrides` check will short-circuit silently when no slider values changed.
   Call `postRender(projectId, {}, stageView)` directly. RENDER_BUSY retry: implement a simple
   per-projectId counter in the Apply handler (same 3-retry / 1.5s pattern as Phase 04.1).

3. **Snapshot payload extension.** The Apply snapshot must include:
   - `vertices`: the current `useEditorStore.getState().vertices` dict
   - `edit_log`: the current `useEditorStore.getState().editLog` (snake_case — NOT camelCase `editLog`)
   - `barony_name_to_idx`: built from the `effectiveBaronies` array in CanvasViewer context
   This is the non-standard extension identified in RESEARCH Target #5 (Pitfall 0 + Pitfall 5).

4. **Auto-immediate snapshot.** Each auto-immediate cascade must post a fresh snapshot before
   calling `postRender` — do NOT rely on the 25-edit auto-snapshot cadence. The 25-edit cadence
   uses `{ vertices, editLog }` (camelCase); the Apply snapshot must use `{ vertices, edit_log }`
   (snake_case) or `compute()` must normalize both (RESEARCH Pitfall 0, Option B).

5. **`bezierApplyMode` is NOT in zundo history.** Add it to the `partialize` exclusion list in
   `useEditorStore`. Undo must never change the mode toggle state.

6. **baroniesQ refetch is automatic.** No explicit `baroniesQ.refetch()` call is needed.
   After render success, `_render_producer` bumps `project.updated_at`. The parent's
   project query returns a new `cacheVersion`, which propagates via the `cacheVersion` prop
   to `useCanvasArtifacts`, triggering all 5 canvas queries including `baroniesQ`.
   (RESEARCH Target #5: "No additional baroniesQ.refetch() call needed.")

7. **Overlay clear is NOT a hide.** Do not add `setActiveTerritoryId(null)` or
   `setBezierMode(false)` on Apply success. The overlay staying visible while the user is
   still editing is the correct UX — it confirms the last committed shape while the raster
   converges. Clearing the barony selection would break the editing flow.

8. **`editLog` reset wraps zundo pause/resume.** The post-converge reset must use:
   ```
   const temporal = useEditorStore.temporal.getState()
   temporal.pause()
   useEditorStore.setState({ editLog: [] })
   temporal.resume()
   ```
   This prevents the `editLog = []` write from appearing in the undo history as a separate op.

9. **data-testid anchors for UAT.** The Playwright BEZ-CONV-05 spec needs:
   - `data-testid="bezier-apply-edits-btn"` (the Apply button — specified above)
   - `data-testid="bezier-apply-auto-switch"` (the mode switch — specified above)
   - `data-testid="bezier-edited-contour"` (the overlay — already exists in BezierEditLayer)
   - `data-testid="barony-layer"` or equivalent to assert the colored raster changed (existing or add)
