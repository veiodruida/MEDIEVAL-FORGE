## Decisions Made

### BezierApplyControls Extraction

WorkspaceToolbar was 228 LOC before this plan. Adding the Apply Edits control group inline would exceed the ~250 LOC planner-stated budget (UI-SPEC §New Files note explicitly permits extraction). The controls were extracted into `BezierApplyControls.tsx` with the data-testids referenced by the acceptance criteria (`bezier-apply-edits-btn`, `bezier-apply-auto-switch`) — the criteria allow the subcomponent to host the anchors.

### pendingApplyRef Guard

The useRunStore subscription in `useBezierApply` uses a `pendingApplyRef` flag that is set to `true` only after a successful snapshot POST and `postRender` call. This prevents an unrelated parameter-studio render (which also transitions `rendering → generated`) from clearing a user's in-progress Bézier edits. The ref is reset on both success and error paths.

### vi.clearAllMocks() + Mock Return Value

`vi.clearAllMocks()` in `beforeEach` clears mock implementations, including the `postRender` factory return. Fix: re-register `vi.mocked(postRender).mockResolvedValue(...)` in `beforeEach` after `clearAllMocks`. This is standard vitest pattern with module-level `vi.mock`.

- **Issue:** Adding `editLog.length > 0` guard to the overlay (line 877) caused `TypeError: Cannot read properties of undefined (reading 'length')` in 14 existing tests. Both test files mock `useEditorStore` with a `MockState` that did not include `editLog`, so the selector returned `undefined`.
