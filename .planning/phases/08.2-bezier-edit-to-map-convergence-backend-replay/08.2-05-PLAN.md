<objective>
Close the single blocking gap from 08.2-VERIFICATION.md: **BEZ-CONV-05 PARTIAL — second Apply degrades barony metadata.**

`replay_vertex_ring` (manual_edit.py:381-387) calls `buffer(0)` to heal a non-convex (self-intersecting) Shapely ring, but does NOT check whether the result is a `MultiPolygon`. When it is, the MultiPolygon is stored directly in `polygons_by_id` and rasterised. On a SECOND Apply to the same barony, this causes the edited barony (Gijón) to disappear from `baronies.geojson` and `territory_metadata.json` — violating CLAUDE.md rule #4 (`original_idx` in every territory — Unity's `byOriginalIdx` shader throws on missing entries) and the "12-file Unity export" clause of the phase goal.

Purpose: A repeat-edit workflow (editing the same barony twice) is normal, not an edge case. The export must stay rule-#4-valid across multiple Applies.

Output:
- A bounded fix in `replay_vertex_ring`: after `buffer(0)`, reduce any `MultiPolygon` to its largest-area `Polygon` component before storing.
- A NON-SKIPPED regression test that reproduces the defect (RED on current code, GREEN after fix) and asserts the edited barony's `original_idx` survives in `territory_metadata.json` + `baronies.geojson` after a SECOND Apply / second render.
- A fast unit guard asserting `polygons_by_id` never holds a `MultiPolygon` after `replay_vertex_ring` on a self-intersecting ring.
- Iberia 10/10 parity re-confirmed green.
</objective>

The defective function (manual_edit.py:327-387):
```python
def replay_vertex_ring(
    barony_name: str,
    barony_name_to_idx: dict[str, int],
    vertices_dict: dict[str, dict],
    polygons_by_id: dict[int, list[Polygon]],
    cfg: RegionConfig,
    W: int,
    H: int,
) -> None:
    raster_idx = barony_name_to_idx.get(barony_name)
    if raster_idx is None:
        return
    ring_keys = sorted([k for k in vertices_dict if k.startswith(barony_name + "#")],
                       key=lambda x: int(x.split("#")[1]) if "#" in x else 0)
    if len(ring_keys) < 3:
        return
    pixel_coords = [_lonlat_to_rasterio_xy(vertices_dict[k]["lon"], vertices_dict[k]["lat"], cfg, W, H)
                    for k in ring_keys]
    try:
        poly = Polygon(pixel_coords)
        if not poly.is_valid:
            poly = poly.buffer(0)        # <-- can return MultiPolygon; NOT guarded
    except Exception:
        return
    if not poly.is_empty and poly.area > 0:
        polygons_by_id[raster_idx] = [poly]   # <-- stores MultiPolygon directly (DEFECT)
```

Current imports at top of manual_edit.py (line 31):
```python
from shapely.geometry import LineString, Polygon
```
(MultiPolygon is NOT yet imported.)

The downstream rasterise step (compute(), lines 207-220) iterates `polygons_by_id` and rasterises every entry. A MultiPolygon stored here produces a raster whose re-extraction via `rasterio.features.shapes` drops the barony on the next render — that is the failure mechanism.

The sidecar writer (`baronies.geojson` / `territory_metadata.json`) reads the rasterised output downstream; a barony absent from the raster is absent from both sidecars.
