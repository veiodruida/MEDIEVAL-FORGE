## Deviations from Plan

### UAT-found defects (Task 5 checkpoint, fixed inline)

**1. Pen snap unit mismatch — interior clicks snapped to parent border; territory could not be closed**
- **Found during:** Task 5 human-verify (real-mouse carve).
- **Issue:** `snapToNeighbour`/`snapToEdge` tolerance is `radiusPx / stageScale` in MAP-PIXEL units; `PenDrawLayer` fed them lat/lon DEGREES, so the 12-screen-px radius behaved like ~12 degrees (≈ the whole Iberian peninsula). Every interior click snapped to the nearest parent-barony edge, and the close-on-first-anchor click snapped to the border instead of the anchor. Create-in-ocean had no nearby candidates so it stayed green — carve (drawn inside a barony) was the first gesture to expose it.
- **Fix:** new pure `resolvePenSnap()` converts cursor + candidates to map-pixels via the projection, snaps with the screen-px radius, converts back. snap.ts primitives unchanged. Close-gesture + closeable-pulse proximity harmonized to `PEN_SNAP_PX / safeScale`. Regression test `snap.penResolve.test.ts` (a cursor 50 screen-px away must NOT snap — the exact case the degree bug wrongly snapped).
- **Verification:** 14 snap vitest + 23 PenDraw/penFlatten vitest green; confirmed live via Playwright-MCP that interior placement no longer snaps.

**2. Double-click-to-close (user request) — and its timing**
- **Found during:** Task 5 (closing by clicking the small first anchor is fiddly at fit-scale; user asked for double-click close).
- **Issue:** a Konva `onDblClick` handler fired but the double-click's own two clicks added spurious anchors that self-intersected the ring → `validate()` rejected → no close (confirmed live: anchors 4→6, editLog 0). Then `DBLCLICK_MS=350` rejected human-speed double-clicks (300–500ms).
- **Fix:** manual double-click detection in `handleMouseDown` (2nd click within `DBLCLICK_MS` + `DBLCLICK_NEAR_PX` of the previous, ≥3 anchors → close on points already placed, 2nd click never added). Window widened to 600ms.
- **Verification:** faithful Playwright-MCP repro with explicit inter-click delays — closes at 150/450/550ms, does not at 900ms (two deliberate clicks). carve POST `/editor/apply` returns 200 + allocated idx.
