<objective>
Add an **enclave CARVE** operation: a closed loop drawn fully inside an existing barony X becomes a NEW
barony N carved out of X, leaving X as a polygon-with-a-hole. This is the parity-critical foundation
that the freehand-draw UX, on-canvas buttons, post-close edit handoff, and condado picker (deferred to
plans 08.3-08 / 08.3-09 — see PHASE SPLIT in the planner return) build ON TOP of. It MUST land first
because the hole round-trip (D-25) is a CORRECTNESS BLOCKER: if the parent's interior ring does not
survive store → reload → re-Apply, the carve silently reverts and breaks `original_idx` stability
(CLAUDE.md #7).

Purpose: Prove — with a backend pytest that is RED before the carve op exists and GREEN after, plus a
real-mouse Playwright UAT — that `N = drawn ∩ parent`, `parent' = parent − N`, and the hole survives BOTH
(a) pure carve → reload → re-Apply AND (b) carve → edit-parent-Bézier → re-Apply (the load-bearing hop,
because plan 08.3-08's auto-select makes editing-after-carve the immediate next gesture).

- `manual_edit.py` — new `op_type == "carve"` branch in `compute()` (NOT the create clip at lines 215-227).
