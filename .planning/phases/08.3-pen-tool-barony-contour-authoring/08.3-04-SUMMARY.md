# Phase 08.3 Plan 04: API Surface for CREATE + /editor/country

**One-liner:** Wired `op_type='create'` into `POST /editor/apply` with backend-authoritative `barony_floor` seeding (load_region + setup_baronies), fixed the latent split aliasing bug by threading the same floor into the split branch, added DoS ring cap (10k), and added `GET /editor/country` for D-08 PT/ES inference via cfg.border_polygon.

## What Was Built

**`POST /editor/apply` — create branch:**
- `op_type` regex widened: `r"^(split|merge|translate|landmask_replace|create)$"`.
- `create` and `split` share a unified `elif` branch that derives `barony_floor`:
  1. `await db.get(Project, project_id)` → `load_region(project.region_key)`
  2. `bars, *_ = setup_baronies(cfg)` → `barony_floor = len(bars)` (= 257 for iberia_868)
  3. `allocate_next_original_idx(db, body.branch_id, min_floor=barony_floor)` — seeds `original_idx_high_water` to at least 257 before incrementing, so the first allocated idx is `>= 257` and never aliases `0..256`.
- Create-specific validation (T-08.3-04-01, T-08.3-04-03):
  - `ring` must be a list with `3 <= len <= 10000` (< 3 → 400, > 10000 → 422).
  - `barony_meta.name` and `barony_meta.condado_idx` must be present (missing → 400).
- The persist block (unchanged) embeds `allocated_original_idx` into `persisted_payload` alongside the ring + barony_meta.

**Split aliasing bug fix (T-08.3-04-02):**
The split branch previously called `allocate_next_original_idx(db, branch_id)` with no `min_floor`, so on a fresh branch (`high_water=0`) it returned `1`, aliasing barony idx 1. Now split shares the same `elif` with create and uses `min_floor=barony_floor` — closing the bug authoritatively. Plan 01 RESEARCH flagged this bug; Plan 04 closes it.

**`GET /editor/country` (D-08):**
New endpoint at `/{project_id}/editor/country?lat=&lon=` (float query params). Loads `cfg` via `load_region(project.region_key)` and calls `point_in_polygon(lon, lat, cfg.border_polygon)` — exactly mirroring `border.build_border_mask`. Returns `{"country": "PT"}` if inside, `{"country": "ES"}` if outside. READ-ONLY; no writes. FastAPI float coercion handles T-08.3-04-04 (non-numeric → 422 automatically).

**Integration tests (`test_editor_create_handler.py` — 8 tests):**
- `test_create_allocates_above_floor`: nb=0 sent → idx >= 257 (floor from backend, not frontend).
- `test_create_allocates_above_floor_even_when_nb_omitted`: nb absent → still >= floor.
- `test_create_persists_ring_and_meta`: edit_events row contains ring + barony_meta + allocated_original_idx.
- `test_create_ring_too_short_400`: 2-point ring → 400.
- `test_create_ring_oversized_422`: 10001-point ring → 422.
- `test_split_seeded_above_floor`: split on fresh branch → idx >= 257 (regression for aliasing bug).
- `test_country_pt_lisbon`: lat=38.72, lon=-9.14 → `{"country": "PT"}` (empirically verified).
- `test_country_es_madrid`: lat=40.42, lon=-3.70 → `{"country": "ES"}` (empirically verified).
