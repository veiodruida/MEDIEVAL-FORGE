### Gaps Summary

**1 gap blocking full goal achievement:**

**PEN-EXTEND-01 — frontend EXTEND graft is a stub** (most-severe gap)

The phase goal states two headline capabilities: CREATE and EXTEND. CREATE is fully implemented and proven end-to-end. EXTEND has all the supporting scaffolding (extendMode detection, first-anchor snap routing, backend replay_vertex_ring handles move/add ops in isolation via test_extend_via_vertex_ring) but the frontend `commitExtend()` body does not graft the drawn arc. It discards the arc geometry and emits a no-op op:'add' with synthetic IDs.

**Contradiction note:** Plan 01-SUMMARY lists PEN-EXTEND-01 in `provides:` and states "EXTEND regression confirmed". The backend test `test_extend_via_vertex_ring` is real and GREEN — but it tests the backend's ability to replay a hand-crafted move op, not the frontend path. Plan 05-SUMMARY correctly marks it `partial:` / "Known Stubs". The code sides with Plan 05.

**To close this gap:** `commitExtend()` must:
1. Find the two snap-contact vertices on the target barony ring (stored in `firstAnchorSnap` / `extendBaronyIdRef`)
2. Determine the shorter arc between the contact points (Assumption A3)
3. Splice the drawn intermediate points into the ring between those two contact-point vertex IDs
4. Emit real op:'add' or op:'move' ops with the existing barony's vertex ID scheme (`${baronyName}#${index}`)

The backend replay path (08.2) is already capable of handling the result.
