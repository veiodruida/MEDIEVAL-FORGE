#### Color assignment rationale

Straight vs curve anchor differentiation: `Rect` (straight) vs `Circle` (curve) matches the
Photoshop pen-tool convention and reuses the `#4a9eff` blue already established for BezierEditLayer
inactive anchors — no new hue needed. First-anchor pulse uses amber (`#f0c040`) — the active-anchor
color from 08.1 — to signal "this is the special/closeable point" without adding a 7th hue.
Rubber-band and segment preview use the same amber dash style as the 08.1 live overlay (D-15 explicit).
Handle / tether colors are identical to 08.1 (magenta + slate-gray) — Pen mode and Bézier mode
are never active simultaneously, so no collision exists.

The full draw-layer palette uses ONLY the 6 hexes already established in Phase 08.1:
`#4a9eff`, `#f0c040`, `#e879f9`, `#94a3b8`, `#22c55e`, `#ef4444` — plus `#eab308` for snap
indicators (inherited from Phase 08 TOPO-03 snap contract). No new colors introduced.

## Draw-Mode Status Hint

**Decision (Claude's discretion, D-18):** A non-blocking cursor-following status hint is shown
while the pen tool is active. It clarifies the intent model without extra chrome.

Copy (PT-BR, inline): "Clique: âncora reta — Arraste: curva Bézier"

Implementation: Konva.Text rendered 12px below + 8px right of the current cursor position,
`fontSize: 11`, `fill: '#f0c040'`, `opacity: 0.75`, `listening: false`. Updated on every
`mousemove`. Disappears when path closes (pen mode exits).

Alternative if Konva.Text proves hard to align: a DOM overlay `<Text size="1" color="amber">`
absolutely positioned with `pointerEvents: none` via `stage.getPointerPosition()` → CSS `transform`.

The hint does NOT differentiate CREATE vs EXTEND — intent is inferred by the engine (D-18).
The cursor proximity to a neighbor contour is the only "mode" indicator (the edge-snap marker
shows when EXTEND mode is triggered by the first anchor snapping to a contour).

One new Konva Layer is added at z=6, above BezierEditLayer.

```
z=0 BackgroundLayer    — terrain PNG / stage raster
z=1 TerritoryLayer     — condado polygons (read-only selection)
z=2 BaronyLayer        — barony polygons (updates on render success)
```

path closes (D-04), the activeTool switches to 'V' and BezierEditLayer takes over.

**`PenDrawLayer` is a NEW component** — it does not modify BezierEditLayer.

## Store Extension

### `EditTool` union

Add `'P'` to the `EditTool` union in `useEditorStore.ts`:

```typescript
export type EditTool = 'V' | 'A' | 'D' | 'S' | 'M' | 'P' | null;
```

### Pen draw state (component-local — NOT in useEditorStore)

The in-progress draw state is component-local to `PenDrawLayer` (same pattern as BezierEditLayer's
anchor display state — RESEARCH anti-pattern: never put transient draw state in the store).

```typescript
// Component-local (useState / useRef in PenDrawLayer)
interface PenAnchor {
  lat: number
  lon: number
  type: 'straight' | 'curve'
  cp1?: { lat: number; lon: number }  // control point 1 (outgoing handle)
  cp2?: { lat: number; lon: number }  // control point 2 (incoming handle)
}

interface PenDrawState {
  isDrawing: boolean
  anchors: PenAnchor[]
  cursorPos: { x: number; y: number } | null   // canvas px, for rubber-band
  altDragging: boolean                          // true while alt-drag adjusts last anchor's handle
}
```

### New `'create'` EditOp (store-level — logged post-close)

After path closure, a single `create` EditOp is committed to `useEditorStore.editLog` via
`setVerticesAndLog` (the WARNING-6 chokepoint). The op payload carries the closed ring:

```typescript
// Added to EditOp op union:
// op: 'create'
// payload shape:
{
  op: 'create',
  ts: number,
  ring: Array<{ lat: number; lon: number }>,  // flattened polygon ring (closed — first = last)
  allocated_original_idx: number | null,        // null until server allocates (post-Apply)
}
```

The `create` op collapses into ONE undo entry in zundo history (D-13). Mid-draw per-anchor
Ctrl+Z (D-12) is handled by removing the last entry from the component-local `PenDrawState.anchors`
array — NOT via zundo. zundo only sees the final committed `create` op.

### `penDrawState.isDrawing` — one field exposed to WorkspaceToolbar

WorkspaceToolbar needs to know whether a pen path is in progress to drive the `disabledTools`
prop. Use a single boolean derived from the component-local state via a ref + callback prop:

```typescript
// PenDrawLayer prop:
onDrawingStateChange?: (isDrawing: boolean) => void
```

WorkspaceToolbar passes this callback; PenDrawLayer calls it whenever `isDrawing` changes.
WorkspaceToolbar holds the derived `penDrawing` boolean in local state.

| Condition | Copy (PT-BR) |

| Self-intersection in ring | "O contorno se cruza — ajuste os pontos e tente fechar novamente." |
| Area below merge threshold (< ~200px equivalent) | "Área muito pequena — o baronato seria removido na limpeza. Amplie o contorno." |

|---------|------|-----------|

| First-anchor closeable hint | (Visual only — amber pulse ring on the first anchor; no text) | Konva animation (D-15) |

### Path cancellation (Esc — D-02)

No confirmation dialog. Esc during draw discards the entire in-progress path silently and
returns `activeTool` to 'V' (or null). No toast. This matches pen-tool conventions — the
cost is only the unfinished path, not a committed op.

### Post-close handoff (D-04)

No new copy. After path closure, `activeTool` switches to 'V' and the new barony is loaded
into `useEditorStore` (same SelectionBridge path used for existing baronies), making the new
barony the active selection. BezierEditLayer activates automatically. The user sees the amber
curve-fit overlay on their newly-created barony and can refine it immediately.

### Apply edits (inherited from Phase 08.2)

No new copy. The "Aplicar edições" button + mode switch + cost badge (Phase 08.2 §Copywriting)
apply unchanged. The `create` op appears in `editLog` like any other op — the user clicks
"Aplicar edições" to converge the new barony to the colored map.

### Destructive actions

No destructive actions in this phase. Esc discards only the in-progress (uncommitted) path —
not a destructive op. The single-entry `create` undo (D-13) is handled by the standard Ctrl+Z
path with no confirmation.

## Interaction Contract

### Pen draw state machine

```
IDLE (activeTool ≠ 'P')
  → press P / click Pen button → DRAWING_FIRST_ANCHOR

DRAWING_FIRST_ANCHOR (isDrawing=false, anchors=[])
  → click empty space → place first straight anchor → DRAWING (isDrawing=true)
  → click-drag empty space → place first curve anchor + adjust cp1 → DRAWING
  → click barony contour (edge/vertex snap) → place first anchor snapped → DRAWING (EXTEND mode inferred)

DRAWING (isDrawing=true, anchors.length ≥ 1)
  → click → place straight anchor → DRAWING (anchors.length += 1)
  → click-drag → place curve anchor, show cp1/cp2 handles → DRAWING
  → alt-drag last anchor → adjust outgoing handle only (D-03) → DRAWING (same state)
  → hover first anchor within snap radius (closeable) → first anchor pulses; cursor hits closeable zone
  → click first anchor (within snap) → CLOSING_RING
  → Ctrl+Z → remove last anchor; if anchors.length becomes 0 → DRAWING_FIRST_ANCHOR
  → Esc → CANCELLED → IDLE (activeTool reset to 'V' or null)

CLOSING_RING (ring closed, validation run immediately)
  → validation PASS (≥3 anchors, no self-intersection, area ≥ threshold) → CLOSED
  → validation FAIL → ring highlighted red, message shown → DRAWING (user must adjust or Esc)

CLOSED (ring valid)
  → flatten ring to lat/lon polygon (same flattenSegment from bezierFlatten.ts reused)
  → clip against existing baronies (D-07 — Shapely call via POST to new endpoint or inline in Apply)
  → commit single 'create' EditOp to useEditorStore via setVerticesAndLog
  → activeTool ← 'V'
  → new barony loaded via SelectionBridge pattern → BezierEditLayer activates (D-04)
  → IDLE (PenDrawLayer unmounts)
```

### Snap behavior (D-05, D-06, D-16)

- Snap radius: **12 screen-px** (fixed, zoom-aware: `snapRadius = 12 / currentScale` in world coords)
- What snaps: anchor drop point (not rubber-band tracking)
- Snaps to: neighbor barony vertices AND edges within snap radius
- Visual: vertex snap → amber circle ring (radius 8 screen-px); edge snap → amber edge highlight
- Alt key disables snap for the current anchor placement (hover the key, release restores)
- First anchor on a barony edge/vertex → EXTEND mode is inferred; closing anchor on the same
  contour → EXTEND path grafts between two contact points (D-06)

### Undo granularity (D-12, D-13)

- Ctrl+Z during draw (isDrawing=true): removes last placed anchor from `PenDrawState.anchors`
  (component-local removal — no store write, no zundo entry)
- Ctrl+Z after close (isDrawing=false, create op committed): removes the entire new barony from
  `useEditorStore.editLog` (single zundo pop; the `create` op is one undo entry — D-13)
- Ctrl+Z after Apply (colored map rendered): reverts `useEditorStore` geometry only; colored map
  stays as last-rendered until next Apply (D-14, carried forward from 08.2 D-03)

### Post-close Apply flow

Identical to Phase 08.2 §Interaction Contract (Manual mode or Auto-immediate). No new flow.
The `create` op in `editLog` causes:
- "Aplicar edições" button to become enabled
- Overlay (amber preview of drawn ring) to appear
- Normal Apply → backend `manual_edit.compute()` → render cascade → `baroniesQ` refetch → new
  barony appears colored on the `BaronyLayer`

## Notes for Executor

1. **PenDrawLayer is component-local state only.** No `useEditorStore` fields for in-progress draw
   anchors, cursor position, or altDragging. Mirror the BezierEditLayer pattern exactly.

2. **The single `create` EditOp is the only store write during the entire pen interaction.**
   It is written via `setVerticesAndLog` (the WARNING-6 chokepoint) exactly once, on path close.
   Mid-draw Ctrl+Z removes from the component-local `anchors` array, never from the store.

3. **Pen mode and Bézier mode are mutually exclusive.** `PenDrawLayer` (z=6) is mounted only when
   `activeTool === 'P'`. After path close, `activeTool` becomes 'V' → `PenDrawLayer` unmounts →
   `BezierEditLayer` activates for the newly-created barony. They are never mounted simultaneously.

4. **Snap radius = 12 screen-px, zoom-aware.** `snapRadius = 12 / currentScale`. Applies to
   anchor placement only (not rubber-band). Reuse the existing `snapToNeighbour` utility from
   `frontend/src/lib/snap.ts` with `candidates` built from `neighborCandidates` prop.

5. **`Pencil1Icon` availability must be verified.** If not available, use `Pencil2Icon` or a
   custom inline SVG. Do NOT add `lucide-react` or any new icon package as a dependency.

6. **EXTEND mode is inferred, not selected.** First anchor snapped to a barony contour → EXTEND.
   First anchor in empty space → CREATE. WorkspaceToolbar shows NO mode label. Only the snap
   marker visually confirms EXTEND mode is triggered.

7. **Validation must run before ring is committed.** Run the four D-17 checks client-side
   (anchor count, self-intersection via `turf/boolean-intersects` or inline cross-product,
   area vs threshold, EXTEND end-snap). If any fails, do NOT call `setVerticesAndLog`. Show the
   red ring overlay and the validation callout. User must Esc or fix and re-close.

8. **`allocated_original_idx` is null in the `create` EditOp at commit time.** The server
   allocates the id during the Apply cascade (D-10). The EditOp carries `allocated_original_idx: null`
   when first committed; the Apply response fills it. Planner must decide the allocation response
   shape and how the frontend patches the EditOp after Apply (analogous to split's
   `allocated_original_idx` flow in `useEditorStore.ts` lines ~277-285).

9. **Do not reopen the 08.2-05 MultiPolygon defect.** D-07 clip against neighbors uses Shapely
   boolean ops. After clipping, always extract the largest-area component (same guard as 08.2-05)
   before rasterising the ring. Planner must verify this in the backend `create` branch.

10. **data-testid `'pen-draw-layer'` on the root Konva Group.** Playwright needs a stable anchor.
    Use `<Group data-testid="pen-draw-layer">` at the layer root. Note: Konva Groups do not
    render a DOM element — use the `name` prop (`name="pen-draw-layer"`) as the Playwright-queryable
    identifier if needed; confirm with the existing BezierEditLayer __forgeBezierState DEV hatch pattern.
