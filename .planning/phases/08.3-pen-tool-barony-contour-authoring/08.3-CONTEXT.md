# Phase 08.3: Pen tool — Photoshop-style barony contour authoring — Context

**Gathered:** 2026-05-30
**Status:** Ready for planning (research required)
**Source:** Phase 08.2 UAT feedback (2026-05-30). User found the 08.1 Bézier handle editor too
hard to fill the empty space left by editing a neighboring barony, and could not draw clean
S-curves on demand. Needs a Photoshop pen-tool model: click = straight anchor, click-drag =
Bézier curve handle.

<domain>
## Phase Boundary

Add a pen/path-authoring tool to the canvas so a Game Designer authors barony contours
point-by-point. Two capabilities:
1. **CREATE** a brand-new barony in empty space (e.g. the gap left after editing a neighbor).
2. **EXTEND** an existing barony's contour.

New/extended geometry converges through the **same 08.2 backend path** (vertex-op replay →
render cascade → colored `BaronyLayer` → 12-file export), integrates with territory assignment
(per-country Voronoi/KD-tree), hierarchy (barony→condado→…), and `original_idx`
uniqueness/stability (CLAUDE.md #4). Iberia 10/10 parity stays green on the zero-edit path.

**Key asymmetry (anchor this — it shapes the whole plan):** CREATE and EXTEND are NOT symmetric.
EXTEND ≈ the already-decided 08.1/08.2 add-vertex + replay machinery with a new entry gesture.
ALL the hard, parity-touching decisions (id allocation, country/hierarchy assignment, convergence
of a footprint that has no prior int16 raster + is not a Voronoi cell) cluster on **CREATE**.

**In scope:**
- Pen tool UI: click=straight anchor, click-drag=Bézier handle (PEN-CURVE-01), live preview,
  snapping, path close/cancel, undo.
- CREATE new barony (PEN-CREATE-01) + EXTEND existing contour (PEN-EXTEND-01).
- Assignment of new/extended geometry via per-country Voronoi/KD-tree + hierarchy + `original_idx`
  stability (PEN-ASSIGN-01).
- Convergence to colored map + 12-file export via 08.2 replay/cascade (PEN-CONV-01).
- Iberia 10/10 parity unchanged on the zero-edit path (PEN-PARITY-01).
- Real-mouse UAT: draw a new barony to fill a gap → appears colored + in export + survives reload
  (PEN-UAT-01).

**Out of scope (deferred / unchanged):**
- The 08.1 Bézier editor itself (curve-fit, anchor drag) — reused as-is for post-close refinement.
- The 08.2 convergence trigger/cascade machinery — reused verbatim, not reinvented.
- Touch support, 3-way branch merge, condado-direct authoring, multi-barony batch draw.

</domain>

<decisions>
## Implementation Decisions

### Pen interaction + curve model
- **D-01 (Close = click first anchor):** A closed barony loop is finalized by clicking the first
  anchor (Photoshop-style). The first anchor highlights/pulses when the cursor is within snap
  range so the user sees it's closeable.
- **D-02 (Cancel = Esc discards whole path):** Esc during draw discards the entire in-progress
  path, returning to a clean state. (Incremental anchor removal is via Ctrl+Z — D-09.)
- **D-03 (Mid-draw anchor edit = last anchor only, alt-drag):** While drawing, only the current
  (just-placed) anchor's handle is adjustable (alt-drag, Photoshop convention). Earlier anchors are
  refined only AFTER closing, via the existing 08.1 Bézier editor. Keeps the pen tool simple.
- **D-04 (Post-close → reuse 08.1 Bézier editor):** Once closed/finalized, the new barony enters
  the SAME 08.1 Bézier editing model (derivable anchors + handles). No second editor; consistency.

### Snapping & gap/overlap rules
- **D-05 (CREATE snap = vertex AND edge):** Anchors snap to both vertices and edges of neighboring
  baronies within a snap radius. This closes gaps **by construction** (no ocean-sentinel `-1` gap
  opens between adjacent baronies — mirrors Phase 08 D-30 shared-vertex coupling), which is exactly
  the "fill the gap left by an edited neighbor" use case.
- **D-06 (EXTEND = snap both ends to the contour):** An EXTEND path begins and ends snapped to the
  target barony's contour; the drawn segment replaces the contour arc between the two contact
  points. Clean graft, no ambiguity about which arc to keep.
- **D-07 (Overlap = clip against neighbors):** New geometry is clipped against existing baronies;
  overlapping pixels belong to whichever barony was already there. No double-assignment, no
  overwrite of existing territory (protects parity / `original_idx`). Overwrite was explicitly
  rejected as dangerous.

### New-barony assignment policy (the parity-critical cluster)
- **D-08 (Country = auto by geometry):** A gap-filling barony's country is decided by its
  centroid vs the PT/ES border polygon (38 pts) — the same routing logic that sends municipalities
  to the correct per-country KD-tree (CLAUDE.md #3). Zero extra click.
- **D-09 (Hierarchy = inherit from snap neighbor):** The new barony joins the condado (and thus
  duchy/kingdom) of the neighboring barony it snapped/contacted — coherent with the "fill the
  edited neighbor's gap" use case. Does NOT re-cluster existing hierarchy (stability).
- **D-10 (`original_idx` = server allocates new, never reuse):** Backend allocates the next free
  `original_idx` (>= max+1), never reusing a freed one. Same uniqueness/stability guarantee as the
  split path. **⚠ Research must verify** the split allocator does not assume an existing parent —
  a free-floating barony has none (see Research Targets).
- **D-11 (Hand-drawn barony = fixed anchor in the KD-tree, NOT a Voronoi seed):** The drawn
  geometry is fixed truth: it enters as its own cell and the municipalities inside it re-route to
  it in the country's KD-tree. It is NOT re-assimilated/redrawn by Voronoi (which would distort the
  hand-authored contour and defeat the manual control).

### Undo granularity
- **D-12 (Mid-draw Ctrl+Z = per anchor):** During drawing, each Ctrl+Z removes the last placed
  anchor (incremental). Matches pen-tool expectations.
- **D-13 (Post-close = one `create` history entry):** A finalized path collapses into a single
  undoable `create` op in the zundo editor history — Ctrl+Z removes the whole barony. Consistent
  with Phase 08 D-25 (zundo is editor-scoped).
- **D-14 (Undo after Apply = store-only, re-Apply to revert map):** Ctrl+Z reverts only
  `useEditorStore` geometry; the colored map stays as last-rendered until the next Apply. Identical
  to the 08.2 D-03 contract — NO automatic re-cascade-back (08.2 explicitly rejected coupling zundo
  to the render cache).

### Visual feedback + entry
- **D-15 (Full draw feedback):** Live rubber-band dashed line from the last anchor to the cursor;
  straight anchors and curve-handle anchors are visually distinct (e.g. square vs circle+handle
  lines); the first anchor pulses/highlights when closeable; an active-snap marker shows when an
  anchor is grabbing a neighbor. Reuse the amber-dashed style of the 08.1 live overlay for
  consistency.
- **D-16 (Snap radius = screen-px, zoom-aware):** Snap radius is a fixed screen-pixel distance
  (e.g. ~12px) converted to world coords via the current zoom — constant feel at any zoom. A visual
  cue (circle/line) shows when snapping is active.
- **D-17 (Pre-Apply validation = all guards):** Closing/Applying is blocked with a PT-BR warning
  unless: ≥3 anchors, no self-intersection in the ring, area ≥ the merge-stage threshold (>200px
  blob removal), and (EXTEND) both ends are snapped to the contour. Protects the 08.2 replay/parity
  path from degenerate geometry.
- **D-18 (Single Pen tool, mode inferred):** One Pen tool (key `P`) in the EditToolPalette.
  Clicking empty space starts CREATE; clicking/snapping onto an existing contour starts EXTEND.
  Fewer buttons, fluid intent.

### Carried forward (NOT re-asked — locked in prior phases)
- **08.2 D-01/D-02/D-03:** Two-mode convergence trigger (Manual "Apply edits" default +
  auto-immediate toggle); reuse the Phase 04.1 cancellable `/render` path (progress, Cancelar,
  `RENDER_BUSY` retry, `baroniesQ` refetch on success); undo reverts store only, no re-cascade-back.
- **08.1:** Bézier exists ONLY in the editor UI layer; the empty-log identity parity contract is
  sacred (entering/exiting with zero ops = byte-equal output).

### Claude's Discretion
- Exact anchor/handle glyph shapes and colors (within the D-15 amber-dashed family).
- Exact snap-radius px value and the snap-cue visual.
- "Apply edits" button copy/placement (already 08.2 discretion).
- Whether CREATE's clip (D-07) reuses the existing Shapely boolean-op path from split/merge.

</decisions>

<research_targets>
## Research Targets (for `/gsd-plan-phase 08.3 --research`)

1. **CREATE convergence — THE CRUX.** 08.2 convergence works by re-rasterising EXISTING baronies'
   edited GeoJSON rings. A brand-new barony has NO prior int16 footprint and is NOT a Voronoi cell.
   "Converges via 08.2 replay" (PEN-CONV-01) is a real extension, not free inheritance. Determine
   how a new closed ring enters `manual_edit.compute()` → render: a new `create` op carrying the
   ring (lat/lon), rasterised into the int16 grid alongside the replayed existing baronies, with the
   server-allocated `original_idx` painted as its label. Resolve the lat/lon→raster transform reuse.
2. **`original_idx` allocator parentage (gates D-10).** Verify whether the split allocator in
   `editor.py` `/editor/apply` assumes an existing parent (split derives a child that inherits
   country/condado for free). A free-floating CREATE barony has no parent — confirm the allocation
   path transfers or needs a parentless variant.
3. **Fixed hand-drawn cell vs Voronoi (gates D-11).** Confirm how to insert the drawn ring as a
   fixed KD-tree anchor so municipalities re-route to it WITHOUT the Voronoi/cleanup stages redrawing
   or merging it away (watch the >200px merge threshold and σ smoothing). Empirically verify on a
   real Iberia gap.
4. **Clip mechanism for overlap (D-07).** Whether CREATE's clip-against-neighbors reuses the
   existing Shapely boolean-op path used by split/merge, and that it cannot produce a MultiPolygon
   that reopens the 08.2-05 `original_idx` defect.
5. **EXTEND graft mechanics (D-06).** How a 2-end-snapped open path maps to add/move ops on the
   existing contour (reusing 08.2 add/move replay) vs needing a new op — i.e. how much of EXTEND is
   literally the 08.1/08.2 machinery with a new entry gesture.
6. **Frontend pen-state + op shape.** Pen draw-state machine (anchors, handles, snap), the new
   `create` EditOp payload shape (ring of {lat,lon} + straight/curve flags), and how mid-draw
   per-anchor undo (D-12) sits over zundo before the single post-close `create` entry (D-13).

</research_targets>

<specifics>
## Specific Ideas

- The pen model is explicitly **Photoshop pen tool**: click = straight anchor, click-drag = pull
  Bézier handle; close by clicking the first anchor; alt-drag adjusts the current anchor's handle.
- The driving use case is **filling the gap left by editing a neighbor** — which is why CREATE snaps
  to vertices AND edges (D-05, gap-free by construction) and inherits the neighbor's country/hierarchy
  (D-08/D-09).

## Addendum — Plan 08.3-07 (added 2026-05-31 from live UAT conversation)

**Source:** Post-06 UAT. After the pen-tool live-curve fix (commit `ed5b80f`), the user
requested THREE follow-on capabilities. Captured here as locked decisions D-19..D-27 so plan
08.3-07 and the plan-checker share scope. This addendum SUPERSEDES the `deferred` line
"condado-direct authoring … out of scope" — condado assignment is now in scope (D-26).

**Scope of 08.3-07 (4 parts):**
1. Post-close edit handoff (item 1).
2. Freehand/lasso draw mode, Photoshop-grade, with on-canvas BUTTONS + hints (item 2 UX).
3. Enclave CARVE — drawn loop becomes a NEW barony carved fully INSIDE a parent (item 2 geometry).
4. Condado picker for the new enclave, default = parent's condado (item 3).

### Post-close edit handoff
- **D-19 (Auto-switch to V + auto-SELECT the new barony):** After any pen/freehand contour
  closes and commits, the tool switches to V (pointer) AND the newly-created barony becomes
  `activeTerritoryId` so its Bézier curves are immediately editable. Today `commitCreate`/
  `commitExtend` only call `selectTool('V')` — nothing sets `activeTerritoryId`, so there is
  nothing to edit. The hard part is mapping the **async server-allocated `original_idx` → barony
  id → `setActiveTerritoryId`** AFTER the render cascade + `baroniesQ` refetch settle (the new
  barony does not exist in `effectiveBaronies` until the cascade returns). Selection must wait on
  the refetch, not fire optimistically. Must VERIFY the non-snap create path's `selectTool('V')`
  actually fires today (prior real-mouse test only exercised the `extendMode`/`commitExtend`
  branch — `06` testing went through extend, not pure create).

### Freehand / lasso draw mode + UX
- **D-20 (Freehand drag-to-draw, Photoshop-grade):** A free-draw mode where the user drags a
  continuous contour (lasso style) inside an existing barony, with curve smoothing/sampling so the
  committed ring is clean (not jagged). Distinct entry from the click/click-drag pen, but reuses
  the same close/validate/commit + snap infrastructure. Sampling cadence + Douglas-Peucker-style
  simplification are Claude's discretion within "clean, not jagged."
- **D-21 (On-canvas action BUTTONS, not just keyboard):** Provide visible buttons for the draw
  actions (e.g. Fechar contorno / Transformar em baronia / Cancelar / Desfazer último ponto) in
  addition to the existing keyboard shortcuts. The user explicitly asked for buttons + hints, not
  shortcut-only. Buttons live in a small canvas-anchored action bar that appears while drawing.
- **D-22 (On-screen hints/tips):** Show contextual hint text for the current draw state (what a
  click does, what drag does, how to close, that right-click deletes the last point). Reuse the
  existing PT-BR status-hint style already in `PenDrawLayer`.

### Enclave CARVE geometry (the parity-critical cluster for this plan)
- **D-23 (Carve = interior enclave; parent becomes polygon-with-hole):** The drawn closed loop
  inside barony X becomes a NEW barony N fully INSIDE X. X is reshaped to a polygon WITH AN
  INTERIOR RING (a hole) where N now sits. User chose "totalmente dentro (enclave/buraco)" over
  border-touch split.
- **D-24 (Carve geometry formula — clip to parent, do NOT keep "new whole"):**
  `parent = barony under the drawn centroid`; `N = drawn_loop ∩ parent`; `parent' = parent − N`.
  This guarantees `N ⊆ parent`, zero overlap with any other barony, and resolves "which parent"
  when the loop is sloppy or pokes slightly outside. Reuse `allocate_next_original_idx` exactly as
  the existing create path does. **Carve must NOT reuse the existing `op_type:'create'` clip** at
  `backend/medieval_forge/services/pipeline/manual_edit.py:215-227`, which does
  `poly = poly.difference(neighbours_union)` — for an interior loop that subtracts the parent and
  clips N to EMPTY, silently dropping the create. A NEW op variant (`op_type:'carve'`) is required.
- **D-25 (Hole round-trip survival — CORRECTNESS BLOCKER, design around it):** The parent's
  interior ring (hole) MUST survive the full round-trip store → reload → re-Apply, or the carve
  silently reverts on the next Apply (parent rasterises filled, overpaints N) and breaks
  `original_idx` stability (CLAUDE.md #7). Today `normalizeCandidate` in `PenDrawLayer.tsx`
  (and likely GeoJSON sidecar storage / vertex extraction / the Bézier editor) read only
  `geometry.coordinates[0]` (exterior ring) — holes get silently dropped. The plan MUST either
  make holes survive end-to-end across EVERY hop (rasterise w/ hole, GeoJSON store w/ interior
  ring, snap-candidate build, vertex/Bézier editor) OR explicitly verify+document each hop. A
  Playwright real-mouse UAT must prove: carve → Apply → reload → carve still present (hole intact).

### Condado assignment
- **D-26 (Condado picker, default = parent's condado):** A UI dropdown lists the project/branch
  condados (sourced from `territories.geojson` — id + name + idx, served at
  `/api/v3/projects/{id}/artifacts/territories.geojson`). The user picks the new enclave's condado;
  if left unset, DEFAULT to the parent barony's `condado_idx`. Duchy/kingdom inherit transitively
  from the chosen condado (same inherit path as D-09). Supersedes the prior "condado-direct
  authoring out of scope" deferral for the enclave case only.
- **D-27 (Non-negotiables hold):** CLAUDE.md rules unchanged — NEAREST upscale only, `original_idx`
  unique/stable + server-allocated never-reused (D-10 precedent), `-1`/`9999` sentinels skipped in
  median pass and never created by the carve difference, 2x masks independent renders. Iberia
  10/10 parity stays green on the zero-edit path (carve adds an op only when the user draws).
