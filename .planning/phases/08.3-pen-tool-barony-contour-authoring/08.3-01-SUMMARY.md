# Phase 08.3 Plan 01: Backend CREATE Convergence Summary

**One-liner:** Seeded `allocate_next_original_idx` with `min_floor=nb`, tuple-returned `compute()` with CREATE raster overpaint + D-07 clip, and index-aware `bars[]` extension in both orchestrator sites so new baronies reach hierarchy/lookup/metadata.

## What Was Built

This plan fixes the two root-cause bugs that blocked CREATE convergence (PEN-CONV-01):

**BUG 1 (index collision):** `Branch.original_idx_high_water` defaults to 0, so the first `allocate_next_original_idx` call returned 1, aliasing existing barony 1. Fixed by adding `min_floor: int = 0` to the allocator — callers pass `min_floor=nb` so the first allocated idx is `>= nb` (safely outside `0..nb-1`). The models.py column default is intentionally unchanged (test for it stays green).

**BUG 2 (hierarchy coverage gap):** After seeding, allocated idx = nb, but `build_hierarchy_maps` loops `range(nb)`, `generate_lookup_map` iterates `range(n_items=nb)`, and `export_metadata` loops `enumerate(bars)` — all three skip idx=nb. Fixed by having `compute()` return `(out_array, new_barony_entries)` and extending `bars/bc/bd/bk/nb` in both orchestrator call sites before `build_hierarchy_maps` runs.

**CREATE branch in `compute()`:** Rasterises hand-drawn rings at `allocated_original_idx` via `_lonlat_to_rasterio_xy` (round() + rasterio y-flip, A1 contract). Applies D-07 clip (`difference(neighbours_union)`) with the 08.2-05 largest-component guard after `difference()` (T-08.3-01-03). Appends barony metadata to `new_barony_meta` list sorted by `original_idx`.

**Split BUG 2 closure:** The split branch also appends child metadata to `new_barony_meta` with safe defaults for pre-existing ops missing `barony_meta`. Same orchestrator path as CREATE.

**EXTEND regression confirmed:** No new backend op needed — `replay_vertex_ring` handles grafted arcs via standard move/add vertex ops with zero changes. `test_extend_via_vertex_ring` confirms this.

## D-11 Raster-Overpaint Deviation

The plan objective explicitly surfaces this: D-11 states "insert the drawn ring as a fixed KD-tree anchor so municipalities re-route." The actual mechanism is **raster overpaint in `manual_edit.compute()`** — `manual_edit` runs after Voronoi/cleanup/merge (all cached), so there is no KD-tree to mutate. The CREATE ring is painted at `allocated_original_idx` in `polygons_by_id` and survives the rasterise-back step. The end effect (fixed, stable hand-drawn barony) is identical to D-11's intent. No KD-tree code is needed.
