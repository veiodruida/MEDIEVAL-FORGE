`setVerticesAndLog(currentVertices, {op:'add', vertexIds: ring.map((_,i)=>`extend-${i}`)})` —
it passes the EXISTING store vertices UNCHANGED and logs synthetic `extend-N` ids. The drawn
arc's coordinates never enter the vertices dict and the synthetic keys are never read by the

capability of this phase (alongside CREATE); it must actually graft the drawn arc.

arc (Assumption A3), write the resulting full new ring into the store vertices as
`${baronyName}#i` (clearing stale keys), and log a real vertex op. The backend
`replay_vertex_ring` → `compute()` path already rebuilds the barony from that ring on Apply —
verified GREEN this session for the shrink case; this plan strengthens its EXTEND/grow coverage.

FACT 1 — How replay_vertex_ring selects which barony to rebuild (manual_edit.py:349-355):
```python

if vertex_ops_present and barony_name_to_idx and vertices_dict:
```

The backend replays EVERY barony whose name appears as a `${name}#i` key in the vertices dict.
The op's `baronyName` field does NOT select the barony — the vertices-dict keys do.
`vertex_ops_present = any(op in {move,add,delete,multi_delete})` (manual_edit.py:123-124).

CONSEQUENCE for commitExtend (the exact fix shape):
  (1) MUST write the full spliced ring as `${targetName}#0`, `${targetName}#1`, ... contiguous.
  (2) MUST log ANY vertex op (op:'add' or 'move') so `vertex_ops_present` is true.
  (3) The current stub's `extend-${i}` keys are WRONG (never matched by `startswith(name+'#')`)
      and `currentVertices` is passed UNCHANGED (the new ring is never written). Both are the bug.

FACT 2 — replay_vertex_ring reads ALL matching keys, sorted by index (manual_edit.py:622-638):
```python
ring_keys = sorted([k for k in vertices_dict if k.startswith(barony_name + "#")],
                   key=lambda x: int(x.split("#")[1]) if "#" in x else 0)
```
CONSEQUENCE — STALE-KEY TRAP: the spliced ring is a DIFFERENT LENGTH than the original. If the
store held `${name}#0..#19` and you write `${name}#0..#14`, the leftover `#15..#19` get
concatenated into the polygon and CORRUPT it. commitExtend MUST delete every prior
`${targetName}#*` key from the vertices map, THEN write the new contiguous `#0..#n`.

FACT 3 — close routing already reaches commitExtend (PenDrawLayer.tsx:872-873, 1146-1147):
