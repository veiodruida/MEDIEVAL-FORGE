<objective>
Backend CREATE convergence — THE CRUX of Phase 08.3. A brand-new hand-drawn barony has no prior
int16 footprint and is not a Voronoi cell. This plan makes a new `create` op rasterise into the
merged raster (raster OVERPAINT, see deviation note), get a non-aliasing `original_idx`, and reach
hierarchy/lookup/metadata so it converges to the colored map and the 12-file export.

This plan fixes the TWO backend bugs RESEARCH found, which gate PEN-CONV-01:
  BUG 1 (index collision): `original_idx_high_water` defaults to 0 → first allocation returns 1 →
    aliases existing barony idx 1, overwriting its geometry. The split path is broken the same way.
  BUG 2 (hierarchy coverage gap): once seeded, allocated idx = nb, but `build_hierarchy_maps`,
    `generate_lookup_map`, and `export_metadata` all iterate `range(nb)`/`enumerate(bars)` and
    silently SKIP idx = nb. The orchestrator must extend `bars/bc/bd/bk/nb` before those run.

DEVIATION FROM CONTEXT D-11 (surface to user): D-11 says "insert the drawn ring as a fixed KD-tree
anchor so municipalities re-route." That mechanism does NOT match the architecture — `manual_edit`
runs AFTER Voronoi/cleanup/merge (all cached). The real mechanism is RASTER OVERPAINT: compute()
overwrites the merged int16 raster at the allocated idx. No KD-tree code is needed. The end effect
(hand-drawn ring is fixed and stable) is identical. This SIMPLIFIES the work — no KD-tree mutation.

Purpose: without this, "converges via 08.2 replay" (PEN-CONV-01) is a real backend extension, not
free inheritance. EXTEND (Target 5) is ~90% existing machinery — this plan only adds a regression
test proving the existing `replay_vertex_ring` path handles the grafted ring with zero new op.

SPLIT SCOPE (explicit decision): this plan fixes split's ALLOCATION (min_floor so it stops
aliasing idx 1) AND, because the split branch in compute() also produces a child idx >= len(bars),
split children flow through the SAME `new_barony_entries` index-aware placement as CREATE — so
split's latent hierarchy-coverage gap (BUG 2) is closed too. The split branch in compute() must
therefore append its child to `new_barony_entries` (with the parent's inherited condado/duchy/
kingdom), not just rasterise it. A split regression test confirms the child now appears in the
hierarchy map.
Output: a tuple-returning `compute()`, a seeded allocator, extended orchestrator call sites, and a
RED→GREEN test file covering all the failure modes.
</objective>
