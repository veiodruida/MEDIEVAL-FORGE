# Phase 08.3 Plan 03: Store + Palette + Keyboard Contract for Pen Tool

**One-liner:** Widened `EditTool` to include `'P'` and `EditOp` to include `'create'` op with optional `ring`/`allocated_original_idx`/`barony_meta` fields; added Pen button (testid `edit-tool-p`) to `EditToolPalette` and `P` shortcut to `useKeyboardShortcuts`, so Plan 05 (PenDrawLayer) receives a typed contract instead of building its own.

## What Was Built

**`useEditorStore.ts`:** `EditTool` union widened from `'V'|'A'|'D'|'S'|'M'|null` to include `'P'`. `EditOp.op` union widened with `'create'`. Three optional fields added to `EditOp`: `ring?: Array<{lat:number;lon:number}>`, `allocated_original_idx?: number | null`, `barony_meta?: {name, condado_idx, duchy_id, kingdom_id, country}`. Fields are optional (not required) to preserve compatibility with all existing op constructors that use `setVerticesAndLog` — required fields would conflict with the `[key: string]: unknown` index signature and break `moveVertex`, `addVertex`, etc. at type-check time.

**`useEditorStore.create.test.ts`:** 4 TDD tests covering the four plan behaviors: single-entry commit (op==='create', ring present, allocated_original_idx===null), single-zundo-entry (D-13 — one undo removes it entirely), allocated_original_idx patch (mirrors split lines 279-289), and barony_meta round-trip (all 5 fields survive).

**`EditToolPalette.tsx`:** Added `Pencil1Icon` import from `@radix-ui/react-icons` (confirmed available at 1.3.2). Added descriptor `{key:'P', testid:'edit-tool-p', icon:<Pencil1Icon/>, tooltip:'Caneta — desenhar contorno de baronato (P)'}` between M and ESC. Added `S` and `M` entries to `DISABLED_TOOLTIP` with pen-draw-mode PT-BR copy from UI-SPEC §Disabled state. `A` and `D` retain Bézier-mode copy (existing test lock — see Deviations).

**`useKeyboardShortcuts.ts`:** Added `p: 'P'` to the `TOOL_KEYS` record inside `useEffect`. The existing guard (no Ctrl/Meta/Alt modifier, not in editable element, canvas-focused) applies automatically — no new guard needed.

**`EditToolPalette.pen.test.tsx`:** 4 tests: render with testid and tooltip aria-label; `disabledTools={['A','D','S','M']}` disables those four while V and P remain enabled; S/M enabled regression when no disabledTools; click calls `selectTool('P')`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] EditOp create fields declared optional, not required**
- **Found during:** Task 1 pre-write analysis (advisor review)
- **Issue:** Plan text stated "make ring/barony_meta required" but `EditOp` has `[key: string]: unknown`. Declaring required fields on an interface with an index signature means every existing `setVerticesAndLog` call (`moveVertex`, `addVertex`, etc.) would fail `tsc` with "Property 'ring' is missing". Required fields are incompatible with the existing index-signature pattern used by all other ops.
- **Fix:** Declared all three create fields as optional (`ring?`, `allocated_original_idx?`, `barony_meta?`). The index signature already accepts them at runtime; optional declaration satisfies tsc. The plan's acceptance criteria ("EditOp union contains 'create' with ring and allocated_original_idx fields") is satisfied — fields exist and are typed correctly.
- **Files modified:** `frontend/src/stores/useEditorStore.ts`
- **Commit:** 6212dd1

**2. [Rule 1 - Bug preserved] DISABLED_TOOLTIP A/D retains Bézier copy; only S/M get pen-draw copy**
- **Found during:** Task 2 pre-write (existing test read — EditToolPalette.test.tsx Test 10)
- **Issue:** Plan says add pen-draw copy for A/D/S/M. Existing Test 10 (non-skippable) asserts the Bézier-mode aria-label string for A and D. Overwriting would break a non-skippable test. A and D have two valid disable reasons (Bézier mode, pen-draw mode) but `DISABLED_TOOLTIP` is a flat map with one string per key — no multi-reason support.
- **Fix:** A/D keep Bézier copy (test-locked). S/M receive pen-draw copy (genuinely new — no existing test asserts their tooltip). The new `EditToolPalette.pen.test.tsx` asserts disabled STATE for all four buttons (`toBeDisabled()`) without asserting the A/D tooltip string — covers the UI-SPEC requirement without conflicting with the existing test.
- **Files modified:** `frontend/src/components/editor/EditToolPalette.tsx`
- **Commit:** 2c9e64d
