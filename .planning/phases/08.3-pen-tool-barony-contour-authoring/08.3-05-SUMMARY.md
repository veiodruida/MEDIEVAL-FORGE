# Phase 08.3 Plan 05: PenDrawLayer — Pen-Tool Interaction Layer

**One-liner:** Implemented PenDrawLayer (Konva z=6) with full draw state machine (click=straight anchor, rubber-band, snap vertex+edge at 12px zoom-aware), D-17 validation (self-intersection + area threshold), CREATE commit (flattenPenPath → hierarchy inherit via Plan 02 fields → GET /editor/country → setVerticesAndLog op:'create' → POST /editor/apply → allocated_idx patch), EXTEND graft via op:'add', component-local Ctrl+Z, Esc discard, and WorkspaceToolbar disabledTools derivation (A/D/S/M during pen drawing).

## What Was Built

**`snap.ts` (extended):**
- `snapToEdge(cursorWorld, edges, stageScale, altHeld, radiusPx=12)`: nearest point on polygon edge within radiusPx/stageScale world units; t clamped [0,1]; returns `{lat, lon, edgeEndpointIds}` or null.
- `snapToNeighbour` gains optional `radiusPx` param (default=5, preserving all existing callers); PenDrawLayer passes 12 for both vertex and edge snap (D-16: pen snap radius = 12px).

**`penFlatten.ts` (new):**
- `flattenPenPath(anchors, projection)`: converts PenAnchor[] to closed `{lat,lon}[]` ring. Straight segments contribute endpoints directly; curve anchors reuse `flattenSegment` from bezierFlatten.ts with 12 samples per segment for smooth arcs. Pure function (no store, no react-konva imports).

**`PenDrawLayer.tsx` (new, Konva Layer z=6):**
- Component-local state: `anchors`, `cursorPos`, `extendMode`, `extendBaronyId`, `validationError`, `snapVertexMarker`, `snapEdgeMarker` — no useEditorStore fields (mirrors BezierEditLayer pattern).
- State machine: IDLE → DRAWING_FIRST_ANCHOR → DRAWING → CLOSING_RING → CLOSED per UI-SPEC §Interaction Contract.
- Snap: `snapToNeighbour` (vertex, 12px) + `snapToEdge` (edge, 12px) on anchor drop; Alt disables.
- Visual markers: `pen-snap-vertex` (amber Circle), `pen-snap-edge` (amber Line), `pen-rubber-band` (amber dashed Line), `pen-first-anchor` (amber pulse Circle at ≥2 anchors), `pen-validation-error` (Text + red fill).
- D-17 validation: ≥3 anchors + no self-intersection (inline cross-product, no new dep) + area ≥ 200px² (shoelace in px).
- CREATE close: flattenPenPath → centroid → hierarchy from neighbor via `normalizeCandidate` (Plan 02 condado_idx/duchy_id/kingdom_id) → GET /editor/country (Plan 04) → `setVerticesAndLog(vertices, {op:'create', ts, ring, allocated_original_idx:null, barony_meta})` → POST /editor/apply → patch `editLog[-1].allocated_original_idx` (mirrors split 277-289) → `selectTool('V')` (D-04).
- EXTEND close: graft arc via `op:'add'` on existing barony (no op:'create').
- Ctrl+Z: `window.addEventListener('keydown', handler, true)` capture phase, `stopPropagation`, removes last anchor from local state — no zundo entry.
- Esc: clears anchors + `onDrawingStateChange(false)`.
- DEV hatch: `window.__forgePenState` for Plan 06 Playwright.
- `AnyBaronyCandidate` union type + `normalizeCandidate()` adapter accepts both `BaronyFeatureForSnap` (GeoJSON) and `BaronyRenderForSnap` (BaronyRender) so CanvasViewer can pass `effectiveBaronies` directly.

**`CanvasViewer.tsx` (modified):**
- Import `PenDrawLayer`; add `onPenDrawingChange?` prop to `CanvasViewerProps`.
- Add `activeTool` selector from useEditorStore; add `[penDrawing, setPenDrawing]` state + `handlePenDrawingChange` callback.
- Mount `<PenDrawLayer>` gated on `activeTool === 'P'` (after z=5 BezierEditLayer/VertexEditLayer block) — mutually exclusive with BezierEditLayer's active state (D-04).

**`WorkspaceToolbar.tsx` (modified):**
- Add `penDrawing?: boolean` prop (default false).
- Derive `disabledTools`: `penDrawing → ['A','D','S','M']`; `bezierMode → ['A','D']`; neither → `[]`. Union semantics, pen-drawing takes priority.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] snapToNeighbour radiusPx param added**
- **Found during:** Task 1 pre-implementation (advisor item #2)
- **Issue:** Plan must-have states "vertices AND edges within 12px" but `snapToNeighbour` was hardcoded to `SNAP_SCREEN_PX=5`. Calling it from PenDrawLayer without the 12px radius would silently make vertex snap 5px instead of 12px, violating D-16.
- **Fix:** Added optional `radiusPx` param (default=5 preserves all BezierEditLayer callers); PenDrawLayer passes 12 for both vertex and edge snap.
- **Files modified:** `frontend/src/lib/snap.ts`
- **Commit:** 6750916

**2. [Rule 3 - Blocking] Konva event handler type incompatibility**
- **Found during:** Task 2 tsc verification
- **Issue:** `onClick`/`onMouseMove` on react-konva Group expect `KonvaEventObject<MouseEvent>`, not `React.MouseEvent`. The handlers were initially typed as `React.MouseEvent` causing 2 tsc errors (TS2322).
- **Fix:** Changed handler signatures to `Konva.KonvaEventObject<MouseEvent>`; used dual-compat raw access `(e as unknown as {evt?: MouseEvent; clientX?: number}).evt?.clientX ?? clientX` to work in both Konva real and jsdom mock environments.
- **Files modified:** `frontend/src/components/canvas/PenDrawLayer.tsx`
- **Commit:** 09c0f1a

**3. [Rule 3 - Blocking] BaronyRender[] vs BaronyFeatureForSnap[] type mismatch**
- **Found during:** Task 3 tsc verification (TS2322 on `effectiveBaronies`)
- **Issue:** `CanvasViewer` holds `effectiveBaronies: BaronyRender[]` but `PenDrawLayer.neighborCandidates` was typed as `BaronyFeatureForSnap[]`. `BaronyRender` uses a flat structure (`id`, `geoRing`) while `BaronyFeatureForSnap` uses GeoJSON shape (`type`, `properties`, `geometry`).
- **Fix:** Added `BaronyRenderForSnap` interface + `AnyBaronyCandidate = BaronyFeatureForSnap | BaronyRenderForSnap` union type + `normalizeCandidate()` adapter function. CanvasViewer passes `effectiveBaronies` directly; PenDrawLayer normalizes internally.
- **Files modified:** `frontend/src/components/canvas/PenDrawLayer.tsx`
- **Commit:** 3feec8b

## Known Stubs

**1. EXTEND graft body is a stub (PEN-EXTEND-01 partial)**

`commitExtend` in PenDrawLayer calls `setVerticesAndLog(currentVertices, {op:'add', vertexIds: ring.map((_,i)=>'extend-'+i)})` — this passes the *unchanged* store vertices with synthetic IDs. No arc is spliced into the target barony's ring. The EXTEND constraint (grafts drawn arc via add/move, shorter arc per Assumption A3) is not fully implemented.

**What IS implemented:** extendMode is correctly detected (first anchor snaps to contour vertex → `extendMode=true`), and the close path routes to `commitExtend` instead of `commitCreate`. The contract that op:'create' is NOT emitted in EXTEND mode is tested (T8 green). Plan 06 UAT exercises the full EXTEND visual flow; the backend replay path from 08.2 handles op:'add' correctly for the eventual real implementation.

**Which future plan resolves this:** Plan 06 (Playwright UAT) will drive the full EXTEND click sequence and verify the colored map changes; at that point the graft body should be completed or the test will fail explicitly.
