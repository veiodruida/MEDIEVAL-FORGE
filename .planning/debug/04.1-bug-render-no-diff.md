## Resolution

root_cause: **NÃO É BUG DE CÓDIGO.** A faixa válida `smooth_sigma ∈ [3.0, 4.5]` (CLAUDE.md non-negotiable rule #2) produz, no Iberia 868 a fit-to-view, uma diferença visual **sub-pixel / sub-percepção humana**: apenas 1.25% dos pixels do viewport têm diff > 10/255 (limiar de percepção comum), concentrada em fronteiras finas de territórios. O flicker reportado é o reset do `useImage` durante swap de URL — comportamento herdado de Phase 04, não é regressão. Backend, frontend, e ambos specs E2E (SC-3 + SC-2) operam corretamente.

A "regressão" implícita do Phase 04 UAT teste 11 ("SC-3 pixel diff visible" pass) é provavelmente uma diferença de **postura de teste**: em Phase 04 o usuário pode ter inspecionado o canvas com zoom-in numa região fronteiriça (o que torna a diferença visível); em Phase 04.1 testou em fit-to-view default (onde a diferença é sub-pixel). Não há código que faça regressão funcional.

fix: NÃO é uma correção de código. É uma resposta de produto/UX:
  1. Orientar usuário a fazer **zoom-in** numa região com muitas fronteiras (Norte/Galiza/Marca) ANTES de comparar renders. A diferença está nas bordas dos territórios — em zoom-in ela é visível.
  2. Sugerir parâmetros mais impactantes para validar slider→render funciona: `median_passes` (range 1-12, muda densidade de territórios) ou `blob_merge_px` (range 0-500, muda merge de blobs pequenos).
  3. **Não** mexer em `useCanvasArtifacts.ts keepPreviousData` nem em CanvasViewer viewport-key effect — esses fechões Phase 04.1-05 Rule 1 (UAT gap #1 zoom reset).
  4. **Não** alterar bounds do σ (CLAUDE.md non-negotiable rule #2).

Opcional (deferido para Phase 05+): mitigar flicker via preload pattern — manter prev `<img>` enquanto novo `<img>` ainda carregando, swap atômico. Não bloqueia esse issue.
