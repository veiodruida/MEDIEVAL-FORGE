### Pattern 3: DEM tile enumeration (1°×1° grid)

```python
import math

def enumerate_tiles(
    lat_min: float, lon_min: float, lat_max: float, lon_max: float,
) -> list[tuple[int, int]]:
    """Returns (lat, lon) integer pairs naming the SW corner of each 1×1° tile.
    Copernicus tiles are named for their SW corner integer degrees.
    """
    tiles: list[tuple[int, int]] = []
    for lat in range(math.floor(lat_min), math.ceil(lat_max)):
        for lon in range(math.floor(lon_min), math.ceil(lon_max)):
            tiles.append((lat, lon))
    return tiles

def tile_url(lat: int, lon: int) -> str:
    ns = "N" if lat >= 0 else "S"
    ew = "E" if lon >= 0 else "W"
    return (
        f"https://copernicus-dem-90m.s3.eu-central-1.amazonaws.com/"
        f"Copernicus_DSM_COG_30_{ns}{abs(lat):02d}_00_{ew}{abs(lon):03d}_00_DEM/"
        f"Copernicus_DSM_COG_30_{ns}{abs(lat):02d}_00_{ew}{abs(lon):03d}_00_DEM.tif"
    )
```

### Anti-Patterns to Avoid

- **Don't fan out 24 DEM tile downloads with `asyncio.gather` directly.** Use a `Semaphore(4)` wrapping each task — D-08 explicitly chose 4 concurrency.
- **Don't call `rasterio.merge.merge` on the asyncio loop.** Wrap in `asyncio.to_thread(...)` (D-10).
- **Don't reproject DEM at ingest time.** D-11 keeps EPSG:4326 native.
- **Don't auto-evict the DEM tile cache.** D-09 — manual cleanup only.
- **Don't write a JSON envelope for SSE events.** Existing protocol = `data: <plain text>\n\n` (see `ingest_osm._post_query`). New steps follow the same shape (CONTEXT.md `<code_context>` line 188).
- **Don't construct paths manually.** Always go through `services/paths.py::ensure_project_dirs(project_id)["raw"]`.

## Common Pitfalls

### Pitfall 1: Overpass `out geom;` strips tags
**What goes wrong:** `out geom;` returns coords but may drop `tags` on member ways.
**Avoid:** Use `out geom tags;` for relations to keep both. For ways the default `out geom;` is fine.
**Detect early:** Wave 0 fixture replay test must assert `feature.properties.name` is populated for at least one OSM peak with a known name.

### Pitfall 2: Coastline gaps break `line_merge`
**What goes wrong:** OSM coastline ways occasionally have <1m gaps at way boundaries, causing `line_merge` to produce a disconnected MultiLineString instead of one continuous line.
**Why:** OSM editing artifacts, especially near island archipelagos.
**Avoid:** Accept that the post-merge geometry is `MultiLineString` (per D-03). Don't fail if it's not a single LineString. The contract in CONTEXT.md `<contract>` already specifies `MultiLineString`.

### Pitfall 3: HydroSHEDS shapefile encoding
**What goes wrong:** HydroSHEDS .dbf companion uses ISO-8859-1 (some non-ASCII basin names). geopandas/pyogrio default may produce mojibake on Windows.
**Avoid:** Pass `encoding="utf-8"` explicitly OR convert names through `.encode('latin-1').decode('utf-8', errors='replace')`. Verify on Iberia (no non-ASCII basin names — low risk).
**Detect:** Wave 0 test asserts a clipped basin's `name` field decodes without UnicodeDecodeError.

### Pitfall 4: Copernicus tile is missing (404) over open ocean
**What goes wrong:** The Copernicus DSM only publishes tiles where land exists. Pure-ocean 1°×1° tiles return HTTP 404.
**Avoid:** In the fetcher, treat 404 as "tile is ocean — skip silently" and emit `data: Tile {N40_W010} ausente (oceano).\n\n`. Continue with other tiles. `rasterio.merge` handles missing inputs gracefully (the mosaic will have nodata in those cells).
**Iberia worked example:** ~24 tiles covering 36..44 N, -10..4 E; up to 6–8 may 404 (Atlantic / Mediterranean blocks). This is normal.

### Pitfall 5: rasterio.merge memory blow-up on large bboxes
**What goes wrong:** `rasterio.merge.merge(datasets)` loads all input datasets into a single output array in RAM. For ~24 tiles at 1200×1200 int16 ≈ 70 MB; for a US-scale bbox (~250 tiles) ~700 MB.
**Avoid:** For Iberia (D-21 split) we are well under the limit. For >30°×30° bboxes D-21 already mandates splitting at the request layer. Document the memory ceiling in the plan; don't optimise prematurely.
**Detect:** Add a SSE log `data: Mosaicing N tiles ({size_mb:.1f} MB peak estimate)\n\n` before the merge call.

### Pitfall 6: scikit-image `skeletonize` requires bool input
**What goes wrong:** Passing int16 DEM nodata (-32768) into a thresholded mask produces unexpected skeletons.
**Avoid:** Build mask explicitly: `mask = (curvature > thresh) & (z != nodata)` then `skeletonize(mask.astype(bool))`.
**Detect:** Synthetic-DEM test (D-30) — assert ridge polygons fall on the gaussian crests, not at array edges.

### Pitfall 7: Ridge ID determinism breaks if centroid rounding flips
**What goes wrong:** `sha1(round(centroid.x, 3), round(centroid.y, 3), round(elev_max))` — if a polygon's centroid is at exactly e.g. 40.0005, banker's rounding can flip between Python versions / numpy versions, changing the SHA-1.
**Avoid:** Cast to `Decimal` and use `decimal.Decimal.quantize(Decimal('0.001'), rounding=ROUND_HALF_UP)` OR concatenate the inputs as a string with `f"{x:.3f}|{y:.3f}|{int(round(elev_max))}"` before hashing — string formatting is deterministic.
**Detect:** Add a test that creates a polygon with centroid at exactly the bisector and asserts the ID is stable across reruns.

### Pitfall 8: Tailwind v4 + Radix Collapsible specificity
**What goes wrong:** Phase 1 Tailwind v4 + Radix research already documents the transparency bug (CLAUDE.md "Potential Issues" §3, GitHub #17137). Radix `Collapsible.Content` may render with wrong stacking when nested inside Tailwind utility containers.
**Avoid:** Wrap `Collapsible.Root` in a Radix Theme card (`<Card>` from `@radix-ui/themes`); avoid mixing custom Tailwind utility backgrounds inside.
**Detect:** Wave 0 component smoke test verifies `Collapsible.Content` is visible (not transparent) when expanded — same approach as Phase 2's "Tailwind v4 + Radix Pitfall-2 smoke" test.

```python
async def fetch_dem(
    bbox: tuple[float, float, float, float],
    cache_dir: Path,
    queue: asyncio.Queue[str | None],
    *, stop_event: asyncio.Event,
) -> Path:
    tiles = enumerate_tiles(*bbox)
    sem = asyncio.Semaphore(4)  # D-08

    async def fetch_one(lat: int, lon: int) -> Path | None:
        cached = cache_dir / _tile_filename(lat, lon)
        if cached.exists():
            await queue.put(f"data: tile {ns}{lat:02d}{ew}{lon:03d} cache hit\n\n")
            return cached
        async with sem:
            if stop_event.is_set():
                return None
            try:
                async with httpx.AsyncClient(timeout=300) as client:
                    resp = await client.get(_tile_url(lat, lon))
                    if resp.status_code == 404:
                        await queue.put(f"data: tile {ns}{lat}{ew}{lon} ausente (oceano).\n\n")
                        return None
                    resp.raise_for_status()
                    cached.write_bytes(resp.content)
                    return cached
            except httpx.HTTPError as exc:
                await queue.put(f"data: tile {ns}{lat}{ew}{lon} falhou: {exc}\n\n")
                return None

    paths = await asyncio.gather(*[fetch_one(lat, lon) for lat, lon in tiles])
    paths = [p for p in paths if p is not None]
    out_path = ...  # raw/dem.tif via ensure_project_dirs
    await asyncio.to_thread(_merge_to_geotiff, paths, out_path)
    await queue.put("data: mosaic_complete\n\n")
    return out_path

def _merge_to_geotiff(input_paths: list[Path], out_path: Path) -> None:
    import rasterio
    from rasterio.merge import merge
    srcs = [rasterio.open(p) for p in input_paths]
    try:
        mosaic, transform = merge(srcs)  # default nodata uses sources' nodata
        meta = srcs[0].meta.copy()
        meta.update({
            "height": mosaic.shape[1], "width": mosaic.shape[2],
            "transform": transform,
            "compress": "deflate", "tiled": True, "blockxsize": 512, "blockysize": 512,
        })
        tmp = out_path.with_suffix(".tif.tmp")
        with rasterio.open(tmp, "w", **meta) as dst:
            dst.write(mosaic)
        tmp.replace(out_path)
    finally:
        for s in srcs:
            s.close()
```

### §4 — Ridge derivation pipeline (GEO-07)

Concrete pipeline (D-14, D-15, D-19):

```python
import numpy as np
import rasterio
from scipy import ndimage
from skimage import morphology, measure
from shapely.geometry import shape, mapping, GeometryCollection, MultiPolygon, LineString
from shapely.ops import unary_union

# Threshold tuples (Claude's discretion — starting numbers, tunable per D-17)
THRESHOLDS = {
    "low":  {"slope_min_deg": 25, "curvature_min": 0.0010, "min_polygon_area_m2": 1.0e6},
    "med":  {"slope_min_deg": 30, "curvature_min": 0.0020, "min_polygon_area_m2": 5.0e6},
    "high": {"slope_min_deg": 35, "curvature_min": 0.0030, "min_polygon_area_m2": 1.0e7},
}

def derive_ridges(dem_path: Path, sensitivity: str = "med") -> dict:
    cfg = THRESHOLDS[sensitivity]
    with rasterio.open(dem_path) as src:
        z = src.read(1).astype("float32")
        nodata = src.nodata if src.nodata is not None else -32768
        transform = src.transform

    # 1. Mask nodata + light gaussian smooth (denoise, preserve crests)
    valid = z != nodata
    z_smooth = ndimage.gaussian_filter(np.where(valid, z, 0), sigma=1.5)

    # 2. Slope (degrees)
    dy, dx = np.gradient(z_smooth)  # cell-units, but scale-invariant after threshold
    slope = np.degrees(np.arctan(np.hypot(dx, dy)))

    # 3. Negative laplacian (convex up = ridge candidates)
    lap = -ndimage.laplace(z_smooth)

    # 4. Threshold mask
    mask = (slope > cfg["slope_min_deg"]) & (lap > cfg["curvature_min"]) & valid

    # 5. Skeletonize (centerline)
    skeleton = morphology.skeletonize(mask)

    # 6. Polygonize buffered skeleton (for adjacency penalty zone)
    #    Convert mask to polygons via rasterio.features.shapes
    from rasterio.features import shapes
    polys = []
    for geom_dict, value in shapes(mask.astype("uint8"), mask=mask, transform=transform):
        if value == 1:
            poly = shape(geom_dict)
            if poly.area >= cfg["min_polygon_area_m2"] / (111_000**2):  # rough deg² conversion
                polys.append(poly)

    # 7. For each polygon, extract centerline from skeleton via measure.find_contours
    #    OR vectorize the skeleton inside the polygon.

    # 8. Build features with deterministic IDs (D-23) — see Pitfall 7 for ID gen
    features = []
    for poly in polys:
        cx, cy = poly.centroid.x, poly.centroid.y
        # ... compute elev_min/max/mean from z under poly, peak_count, basin_ids
        # ... extract centerline
        feat_id = sha1(f"{cx:.3f}|{cy:.3f}|{int(round(elev_max))}".encode()).hexdigest()[:12]
        features.append({
            "type": "Feature",
            "properties": {"id": feat_id, "name": None, "elev_min": ..., ...},
            "geometry": mapping(GeometryCollection([MultiPolygon([poly]), centerline])),
        })
    return {"type": "FeatureCollection", "features": features}
```

[CITED: rasterio.features.shapes — https://rasterio.readthedocs.io/en/stable/api/rasterio.features.html]
