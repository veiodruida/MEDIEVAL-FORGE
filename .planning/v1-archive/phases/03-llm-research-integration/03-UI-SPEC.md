## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, tight label-to-field gaps |
| sm | 8px | Compact element spacing (Flex gap="2" in Radix = 8px) |
| md | 16px | Default panel padding, card padding (Radix p="4") |
| lg | 24px | Section gaps within dialog (Radix gap="3" = 12px; gap="6" = 24px) |
| xl | 32px | Dialog header to body spacing |
| 2xl | 48px | Not used in Phase 3 dialogs |
| 3xl | 64px | Not used in Phase 3 dialogs |

Exceptions:
- Provider status badge row: 4px gap between icon and label (xs)
- Auth setup sheet inner padding: 16px (md) matching existing Card padding convention
- Dialog max-width: 560px (content constraint, not spacing token)

Source: Existing Radix Themes gap/padding conventions observed in `InspectorSidebar.tsx` and `LayerTogglePanel.tsx`.

## Typography

Radix UI Themes uses a numeric size scale (size="1"–"9"). Mapping to px for executor clarity:

| Role | Radix Size | Approx px | Weight | Line Height |
|------|------------|-----------|--------|-------------|
| Body | size="2" | 14px | regular (400) | 1.5 |
| Label / metadata | size="1" | 12px | regular (400) | 1.5 |
| Section heading | size="3" | 16px | bold (700) | 1.2 |
| Dialog heading | size="4" | 18px | bold (700) | 1.2 |

Rules:
- Use `weight="bold"` only for headings and emphasis labels (e.g., step indicators)
- Use `color="gray"` for secondary labels (source label, auth source string, metadata)
- Use `color="red"` for inline error messages
- Never introduce a 5th size within this phase

Source: `InspectorSidebar.tsx` (size="1"/"2"/"3" pattern), `ProjectDetail.tsx` (size="3" headings).

## Color

Radix UI Themes semantic color tokens — no raw hex. Phase 3 follows the same palette as Phase 2.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--gray-1` / `--gray-2` (Radix surface) | Dialog background, sheet background, form field backgrounds |
| Secondary (30%) | `--gray-3` / `--gray-4` | Card surfaces, provider list item backgrounds, separator lines |
| Accent (10%) | `--blue-9` / `--blue-10` | Primary CTA button ("Iniciar pesquisa"), active provider highlight, streaming progress indicator |
| Destructive | `--red-9` | Error inline messages, "Limpar credenciais" destructive action only |
| Success feedback | `--green-9` | Auth confirmed badge, cached result badge |
| Warning / pending | `--amber-9` | Provider unhealthy / Ollama offline warning tooltip |

Accent reserved for:
- The single primary CTA button "Iniciar pesquisa" (solid fill)
- The currently selected provider highlight border
- The SSE streaming token progress bar/indicator

The success green (`--green-9`) is reserved for:
- Auth status badge when configured: "via CLI auth", "via OAuth", "via env var", "via session key"
- Cached result badge "Resultado em cache"

The warning amber (`--amber-9`) is reserved for:
- Ollama offline/unhealthy disabled state tooltip

Source: `ProjectDetail.tsx` color usage (`var(--green-9)`, `var(--amber-6)`, `var(--blue-6)`); CONTEXT.md D-16 auth status badge spec.

## Interaction States

Each interactive element must handle all four states:

| Element | Default | Loading | Success | Error |
|---------|---------|---------|---------|-------|
| "Iniciar pesquisa" button | enabled, solid blue | `disabled` + "Pesquisando…" label | replaced by result area | `color="red"` inline error below |
| Provider radio option (Ollama) | enabled | — | — | `disabled` + tooltip "Inicia `ollama serve`…" |
| Auth setup "Configurar" link | visible | — | replaced by auth badge | — |
| "Sign in with Google" button | enabled | spinner inside button | replaced by "via OAuth (Google)" badge | inline "Falha no login Google" |
| Manual JSON editor | hidden (failure only) | — | — | shown with last raw LLM response |
| "Revalidar JSON" button | hidden (failure only) | disabled + "Validando…" | dialog proceeds to result | inline Pydantic error |
| Force refresh button | visible when cached | disabled | result reloaded | inline error |

SSE streaming view:
- Mirrors the existing ingest log `<pre>` block in `ProjectDetail.tsx` (padding 8px, background `#f5f5f5`, border-radius 4px, maxHeight 200px, overflow auto, fontSize 11px, white-space pre-wrap)
- Shows token pass-through for Claude and OpenAI; shows "Gemini respondeu (N chars)" for Gemini; shows spinner text "Aguardando Ollama…" for Ollama

## Layout Contract

### ProjectDetail integration

The "Pesquisa histórica" button is added to the Pipeline tab controls row (`Flex gap="2" mb="3" wrap="wrap"` in `ProjectDetail.tsx`), after the existing action buttons and before the log area. It opens `ResearchDialog` as a controlled Dialog via local state (`useState<boolean>`).

The button is only enabled when `project.status === 'generated' || project.status === 'exported'` — research requires generated condados to build the LLM prompt.

### ResearchDialog layout (560px max-width, 3 sections)

```
┌─────────────────────────────────────────┐
│ Pesquisa histórica com LLM       [✕]    │  ← Dialog.Title, size="4"
│─────────────────────────────────────────│
│ Provedor LLM                            │  ← Section heading size="3"
│ [◉ Claude] [○ OpenAI] [○ Gemini]        │  ← RadioGroup (3 cloud)
│ [○ Ollama (local) — disabled if down]   │
│ Auth: ✓ via CLI (claude)  [Configurar→] │  ← Badge + Sheet trigger link
│─────────────────────────────────────────│
│ País (QID Wikidata)  [Q29           ]   │  ← TextField
│ Período  [868  ] d.C. – [900  ] d.C.   │  ← Two TextFields inline
│─────────────────────────────────────────│
│ [progress / result area — see states]   │
│─────────────────────────────────────────│
│              [Cancelar] [Iniciar pesq.] │  ← Dialog.Close + primary CTA
└─────────────────────────────────────────┘
```

Progress area states:
- **Idle:** empty state copy (see Copywriting)
- **Streaming:** `<pre>` log block (SSE tokens), "Pesquisando…" label
- **Cached:** "Resultado em cache" badge + result summary + "Forçar nova pesquisa" button
- **Success:** result summary (kingdom/duchy/condado counts), "Fechar" button
- **Failure (max retries):** error heading + last raw JSON in `TextArea` + "Revalidar JSON" button
