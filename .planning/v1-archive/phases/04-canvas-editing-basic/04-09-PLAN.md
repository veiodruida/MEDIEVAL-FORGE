<objective>
Close the sole verification gap blocking SC1, SC2, and SC3.

Root cause (from 04-VERIFICATION.md):
- `CanvasViewer.tsx` line 555 passes `territoriesQ.data` (TanStack Query cache) to `TerritoryLayer`.
- `CanvasViewer.tsx` line 562 passes `metaQ.data.condados` (TanStack Query cache) to `DecorationsLayer`.
- Edit operations correctly mutate `useProjectStore.territories` and `useProjectStore.capitals`, and the backend correctly persists via `territories.geojson` atomic write.
- But NO edit success path calls `queryClient.invalidateQueries`, so the render layer keeps showing the pre-edit snapshot until page reload.

Fix (Option A from VERIFICATION.md — minimum blast radius):
After each successful edit operation, call `queryClient.invalidateQueries` for the two relevant query keys. TanStack Query re-fetches from `/api/projects/{id}/preview/territories.geojson` (the backend's atomic-write target) and from `/api/projects/{id}/preview/territory_metadata.json`. The existing data flow to `TerritoryLayer` / `DecorationsLayer` / `InteractionLayer` carries the updated data naturally — zero component API changes.

Purpose: Without this, users drag capitals, click Fundir (merge), drag vertices, or finish a split — and get ZERO visual feedback. The canvas is frozen at pre-edit state. All 80 Phase 4 tests pass but the feature is not actually functional from a user's perspective.

Output: Invalidation calls at 4 edit success sites + 1 temporal subscriber for undo/redo. Surgical — no component API changes, no test rewrites.
</objective>

<interfaces>
From `frontend/src/hooks/useCanvasArtifacts.ts` (source of truth for query keys — verified by reading the file):

```typescript
// Query keys that must be invalidated after edit success:
['territories-geojson', projectId, cacheVersion]  // TerritoryLayer + InteractionLayer data
['territory-metadata', projectId, cacheVersion]   // DecorationsLayer condados (capital lon/lat)

// Both use staleTime: Infinity + gcTime: Infinity.
// invalidateQueries triggers an immediate refetch from the backend.
```

Invalidation pattern — pass the key WITHOUT cacheVersion so TanStack matches any cacheVersion:

```typescript
import { useQueryClient } from '@tanstack/react-query'
const queryClient = useQueryClient()

// After successful edit:
await queryClient.invalidateQueries({ queryKey: ['territories-geojson', projectId] })
await queryClient.invalidateQueries({ queryKey: ['territory-metadata', projectId] })
```

TanStack Query v5 matches partial query keys by prefix by default, so this matches
`['territories-geojson', projectId, anyCacheVersion]`.

From `frontend/src/stores/useProjectStore.ts`:
- `useProjectStore.temporal` is a zundo temporal store exposing `.subscribe(listener)`.
- Undo/redo fires via `temporal.getState().undo()` / `.redo()` in `useUndoShortcut.ts`.
- Subscribing to `temporal` lets us invalidate queries AFTER a state traversal so the canvas reverts.

Backend behavior (from 04-07-SUMMARY and 04-08 existing code):
- `moveCapital` endpoint writes to `territories.geojson` when `persist=true`.
- `mergeTerritories` / `splitTerritory` / `reshapeGeometry` — same pattern.
- With `persist=false` (explicit save mode), backend does NOT write the file — the frontend
  holds Zustand state. **In explicit mode, do NOT invalidate** because the backend file is
  still stale; invalidation would overwrite the unsaved in-memory state. In explicit mode,
  invalidation must instead happen after `manualSave` (Ctrl+S flush) succeeds.
