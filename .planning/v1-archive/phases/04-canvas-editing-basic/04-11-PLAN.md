<objective>
Wire `useProjectStore.hydrate()` into CanvasViewer so the edit-side Zustand geometry store is populated with the loaded project's territories and capitals as soon as the canvas data queries resolve. Without this, every downstream Phase-4 edit feature (capital drag rollback + invalidation, vertex handles render gate, merge button visibility, undo history, Ctrl+S snapshot) short-circuits on empty store state — which is exactly what UAT tests T1-T5 observed.

Purpose: Close the diagnosed root cause of all 5 UAT failures. The hydrate() action already exists in useProjectStore.ts:24,47 but has zero production call sites — only tests invoke it. This plan adds the single missing wiring point while protecting the zundo undo stack from hydration pollution.

Output: One useEffect in CanvasViewer that calls hydrate() exactly once per (projectId, cacheVersion) tuple, wrapped in temporal pause/resume + clear so undo history is never polluted, plus one integration test asserting the store is populated after mount and history stays clean.
</objective>

CRITICAL DATA-SHAPE NOTE:
`territoriesQ.data` returned to the CanvasViewer is already run through `select` →
`TerritoryRender[]` with Konva points (projection-transformed). That is NOT
restorable to lon/lat for the store. Adapter approach:

DECISION: Use Option B (direct fetchJson refetch inside the effect).
Rationale (per checker WARNING 3): `queryClient.getQueryData` with the exact key
assumes TanStack v5 caches the pre-`select` result under that key. In v5 the cache
entry SHOULD hold the raw queryFn result, but this is an implementation detail that
has shifted between minor versions and a silent `undefined` return would mean every
UAT test still fails silently. One extra network round-trip (a local file served by
FastAPI on localhost) is negligible for this local tool — robustness wins.

Use the same `fetchJson` helper the query already uses (import from
`useCanvasArtifacts.ts` or copy the minimal fetch call — see action).

HYDRATION POLLUTES UNDO HISTORY (checker BLOCKER 1):
`hydrate()` calls `set({ projectId, territories, capitals, loading: false })` via
the temporal-wrapped setter. The `partialize` function (lines 32-37) includes
territories + capitals, and the `diff` function returns a non-null delta whenever
those references change → every hydrate would push one full undo entry. The first
user Ctrl+Z after a capital drag would undo the drag; the second Ctrl+Z would undo
hydration back to empty → territories vanish from canvas. UNACCEPTABLE.

Mitigation: Wrap the hydrate call in `temporal.pause()` ... `temporal.clear()` ...
`temporal.setState({ isTracking: true })`. See action step 4.

RE-HYDRATE RACE ON AUTO-SAVE INVALIDATION (checker BLOCKER 2):
`invalidateCanvasArtifacts()` (CanvasViewer.tsx:171-175) fires after every capital
drag / vertex commit in auto/per_op mode → `['territories-geojson', projectId]`
query invalidates → TanStack refetches → `territoriesQ.data` reference changes →
naive hydrate effect re-runs → overwrites the user's in-memory edits and destroys
undo history. The effect MUST run exactly once per (projectId, cacheVersion) tuple.
Use a ref-tracked `hydratedKey` guard. See action step 2.

       ```tsx
       // Hydrate the edit-side geometry store once queries resolve.
       // Without this, Phase-4 edit features short-circuit on empty store
       // (SelectionFloatingToolbar guard, VertexHandlesLayer render, undo history,
       // manualSave snapshot). See 04-HUMAN-UAT.md Root Cause (2026-04-25).
       //
       // History safety (checker BLOCKER 1): hydrate() writes through the
       // temporal-wrapped setter; partialize includes territories+capitals, so
       // the naive call would push one undo entry on every hydrate. We pause
       // tracking, hydrate, clear history, then restore tracking. Undo stack
       // stays empty until the user performs their first real edit.
       //
       // Single-run guard (checker BLOCKER 2): auto-save invalidates the
       // territories query after every edit; without the hydratedKeyRef guard
       // the refetch would silently overwrite in-memory edits.
       useEffect(() => {
         if (!metaQ.data) return

         const key = `${projectId}|${cacheVersion ?? ''}`
         if (hydratedKeyRef.current === key) return

         let cancelled = false

         async function run() {
           // Fetch raw FeatureCollection directly — Option B per checker WARNING 3.
           // territoriesQ.data is post-`select` (Konva points, non-reversible).
           const resp = await fetch(
             `/api/projects/${encodeURIComponent(projectId)}/territories.geojson${
               cacheVersion ? `?v=${encodeURIComponent(cacheVersion)}` : ''
             }`,
           )
           if (!resp.ok) return
           const rawFC = (await resp.json()) as {
             type: 'FeatureCollection'
             features: Array<{
               type: 'Feature'
               id?: string
               properties: { id: string }
               geometry:
                 | { type: 'Polygon'; coordinates: [number, number][][] }
                 | { type: 'MultiPolygon'; coordinates: [number, number][][][] }
             }>
           }
           if (cancelled || !metaQ.data) return

           // Build territories record
           const territoriesRecord: Record<
             string,
             { type: 'Polygon'; coordinates: [number, number][][] } |
             { type: 'MultiPolygon'; coordinates: [number, number][][][] }
           > = {}
           for (const f of rawFC.features) {
             territoriesRecord[f.properties.id] = f.geometry
           }

           // Build capitals record
           const capitalsRecord: Record<string, [number, number]> = {}
           for (const c of metaQ.data.condados) {
             capitalsRecord[c.id] = [c.lon, c.lat]
           }

           // HISTORY-SAFE HYDRATE (checker BLOCKER 1 mitigation):
           //   1. pause() — disables tracking
           //   2. hydrate() — updates state; diff is skipped because isTracking=false
           //   3. clear() — wipes pastStates/futureStates (also resets history across
           //      project switches so old project's undo stack doesn't bleed in)
           //   4. setState({ isTracking: true }) — restore tracking directly.
           //      We bypass the project's patched resume() because that helper
           //      flushes a one-entry batch (intended for beginTransaction/endTransaction
           //      user edits). Hydrate is not a user edit → restore tracking manually.
           const temporal = useProjectStore.temporal
           temporal.getState().pause()
           try {
             useProjectStore.getState().hydrate(projectId, territoriesRecord, capitalsRecord)
             temporal.getState().clear()
           } finally {
             temporal.setState({ isTracking: true })
           }

           hydratedKeyRef.current = key
         }

         void run()
         return () => {
           cancelled = true
         }
       }, [projectId, cacheVersion, metaQ.data])
       ```
