<persistence_decision>
**Storage strategy chosen — Option B from 05-RESEARCH §Open Questions §1:**

Per-territory terrain assignment is persisted as a `terrain_type` string property on each
GeoJSON feature in `territories.geojson` (one key per feature). This aligns with the
existing Phase 4 D-07 save strategy — `save_territories` already round-trips feature
properties — and avoids a new SQLite migration. The `paint_terrain` endpoint mutates
the in-memory dict and persists via `save_territories(project_id, territories)`.

`load_territories` adds `terrain_type: Optional[str]` (None when absent) to the
returned dict so the frontend can hydrate `useProjectStore.terrain_types` on project open.
</persistence_decision>
